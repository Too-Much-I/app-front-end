## Clarifications

### Session 2026-07-30

- Q: 실제 파트 점수 그래프의 만점 기준과 답변 회차 규칙은 무엇인가? → A: TOEIC Speaking 고정 파트 만점 `6/6/9/9/5`를 사용한다. 최초 답변은 `retryCount=0`이고 사용자가 다시 답변할 때마다 새 회차를 `1, 2, 3…`으로 증가시키며 네트워크 재전송은 같은 값을 유지한다.
- Q: 실제 `examId` 없이 피드백 탭을 직접 열면 어떻게 표시하는가? → A: API를 호출하지 않고 `완료된 시험이 없어요` 안내와 `모의고사 시작하기` 버튼이 있는 빈 상태 UI를 표시한다.
- Q: 홈의 `최근 피드백` 목카드도 이번 실제 API 연동에서 제거하는가? → A: 아직 제거하지 않고 현재 상태로 유지하며, `examId` 없는 피드백 탭만 빈 상태로 바꾼다.

## Scope *(mandatory)*

### In Scope

- 피드백 탭을 하나의 긴 세로 스크롤 결과 UI로 교체한다.
- 결과 콘텐츠를 `예상 총점 → 한눈에 보기 → 종합 피드백 → 파트별 피드백 → 파트별 점수` 순서로 제공한다.
- 예상 총점 칠판에는 총점, 만점, 레벨과 결과 요약을 표시하고 강점과 보완점은 별도의 한눈에 보기 섹션에 표시한다.
- 파트별 피드백에는 파트 상태, 핵심 피드백, Q 번호와 `문항별 피드백 보기` 버튼을 제공한다.
- 파트의 문제 버튼은 해당 파트의 첫 문제 상세 UI를 열고, 같은 파트의 다른 Q 번호를 선택할 수 있게 한다.
- 문제 상세에서 돌아오면 단일 결과 화면의 이전 스크롤 위치를 유지한다.
- 파트별 점수는 교실 칠판 형태의 상호작용 카드로 제공한다.
- 칠판 앞면은 점수를 확인할 수 있다는 안내와 명확한 누르기 동작을 제공한다.
- 사용자가 칠판을 누를 때마다 앞면과 다섯 파트 오각형 그래프 뒷면이 번갈아 나타난다.
- 움직임 감소를 사용하는 사용자는 회전 없이 즉시 그래프를 확인할 수 있게 한다.
- 채점 완료 화면에서 전달받은 실제 `examId`로 요약 API를 호출하고 매핑된 `ExamGradingResult`를 렌더링한다.
- 문항 선택 시 실제 문제 상세 API를 `retryCount=0`으로 호출하고 매핑된 `ExamQuestionDetail`을 렌더링한다.
- Part 1~5 그래프의 만점은 시험 형식의 고정 메타데이터 `6/6/9/9/5`를 사용한다.
- 요약 및 문제 상세의 로딩, 실패와 재시도 UI를 제공한다.
- 마이페이지에서 UI 검토용 목 피드백 카드와 진입 버튼을 제거한다.
- 피드백 화면의 정적 fixture와 fixture 전용 이미지 매핑을 제거하되 실제 UI에서 사용하는 기존 마스코트 자산은 별도 asset 모듈로 유지한다.
- `examId` 없이 피드백 탭을 직접 연 경우 완료된 시험이 없다는 빈 상태와 모의고사 진입 동작을 제공한다.
- `public/mascots`의 기존 캐릭터 자산을 점수, 종합 피드백, 파트 카드와 칠판 안내에 사용한다.
- 휴대폰과 태블릿, 안전 영역, 큰 글자 설정과 보조 기술을 고려한다.

### Out of Scope

- `1/4` 같은 단계 숫자, 페이지 점, 페이지 전환과 이전/다음 단계 버튼
- 화면 옆 고정 인덱스 또는 목차형 빠른 이동
- 다음 학습 추천 섹션 및 추천 실행
- 최근 피드백/시험 이력 API가 없는 상태에서 과거 결과 목록을 새로 제공하는 작업
- 이번 API 연동 작업에서 다시 답변 녹음 및 제출 UI까지 구현하는 작업
- API 응답 캐시와 오프라인 저장
- 홈의 `최근 피드백` 목데이터 카드 제거 또는 실제 이력 API 연동
- 점수 산정, 피드백 생성 또는 실제 파트 상태 판정 정책
- 문제 재녹음과 재답변 비교
- 신규 마스코트 생성 또는 기존 원본 수정

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 한 화면에서 전체 결과 확인 (Priority: P1)

학습자는 페이지를 전환하거나 현재 단계를 해석할 필요 없이 피드백 탭을 아래로 스크롤하며 전체 결과를 순서대로 확인한다.

**Why this priority**: 모바일에서 가장 단순하고 예측 가능한 결과 탐색 방식이며 승인된 최신 방향의 기반이기 때문이다.

**Independent Test**: 피드백 탭을 열어 시작부터 끝까지 한 번 스크롤하고 다섯 주요 콘텐츠가 지정된 순서로 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 피드백 탭을 열 때, **When** 결과 화면이 표시되면, **Then** 단계 숫자나 페이지 점 없이 종합 결과 제목과 예상 총점 카드가 먼저 보인다.
2. **Given** 화면을 아래로 스크롤할 때, **When** 점수 카드 아래에 도달하면, **Then** 한눈에 보기와 종합 피드백이 순서대로 보인다.
3. **Given** 계속 아래로 스크롤할 때, **When** 종합 피드백 아래에 도달하면, **Then** 파트별 피드백과 파트별 점수 칠판이 순서대로 보인다.
4. **Given** 화면의 끝에 도달했을 때, **When** 마지막 콘텐츠를 확인하면, **Then** 다음 학습 추천은 표시되지 않는다.

### User Story 2 - 파트에서 문제 상세로 이동 (Priority: P1)

학습자는 파트별 피드백에서 Q 범위를 확인하고 해당 문제의 실제 상세 피드백으로 이동한다.

**Why this priority**: 파트 수준 조언을 실제 문제 수준의 피드백과 연결하는 핵심 학습 동작이기 때문이다.

**Independent Test**: 파트 카드의 문제 버튼을 눌러 올바른 Q 상세를 열고 다른 Q를 선택한 뒤 돌아왔을 때 기존 결과 위치가 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 파트별 피드백이 표시될 때, **When** 파트 카드를 확인하면, **Then** 파트 번호, 상태, 핵심 피드백, Q 번호와 `문항별 피드백 보기`가 함께 보인다.
2. **Given** 파트 문제 버튼을 누를 때, **When** 문제 상세 API가 완료되면, **Then** 해당 파트의 첫 Q에 대응하는 `retryCount=0` 상세 데이터가 표시된다.
3. **Given** 같은 파트에 여러 문제가 있을 때, **When** 다른 Q 번호를 선택하면, **Then** 선택한 문제의 평가, 내 답변, 교정과 추천 답변이 표시된다.
4. **Given** 문제 상세에서 뒤로 돌아갈 때, **When** 결과 화면이 다시 보이면, **Then** 직전에 보던 파트별 피드백의 세로 위치가 유지된다.

### User Story 3 - 칠판을 돌려 파트 점수 비교 (Priority: P1)

학습자는 결과 마지막의 칠판을 눌러 다섯 파트 점수의 균형을 오각형 그래프로 재미있게 확인한다.

**Why this priority**: 사용자가 명시적으로 요청한 대표 상호작용이며 긴 결과 화면의 마지막에 시각적 보상을 제공하기 때문이다.

**Independent Test**: 앞면 칠판을 눌러 오각형 그래프를 열고 다시 눌러 앞면으로 돌아오는지, 점수와 파트가 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 아직 점수 그래프를 열지 않았을 때, **When** 파트별 점수 섹션에 도달하면, **Then** 칠판 앞면에 `칠판을 눌러 파트별 점수 확인`과 같은 명확한 안내가 보인다.
2. **Given** 칠판 앞면이 보일 때, **When** 학습자가 칠판을 누르면, **Then** 칠판이 회전하고 뒷면에 Part 1~5 오각형 그래프와 수치가 나타난다.
3. **Given** 오각형 그래프가 보일 때, **When** 학습자가 칠판을 다시 누르면, **Then** 칠판이 회전하고 기본 앞면으로 돌아온다.
4. **Given** 움직임 감소 설정이 켜져 있을 때, **When** 칠판을 누르면, **Then** 회전 애니메이션 없이 그래프가 즉시 나타난다.
5. **Given** 그래프를 보조 기술로 탐색할 때, **When** 각 파트의 정보를 읽으면, **Then** 그래프 모양과 별개로 Part 1~5의 점수와 기준값을 텍스트로 확인할 수 있다.

### Edge Cases

- 긴 한국어/영어 실제 피드백과 큰 글자 설정에서도 카드 높이가 내용에 맞게 늘어난다.
- 마스코트가 본문, 점수, 그래프와 버튼을 가리지 않는다.
- 태블릿에서는 카드가 과도하게 늘어나지 않고 읽기 좋은 최대 너비를 유지한다.
- 존재하지 않는 Q 번호에는 문제 이동 버튼이 만들어지지 않는다.
- 한 파트의 마지막 Q에서는 다음 Q로 이동할 수 없다.
- 일부 파트 점수가 없으면 오각형 그래프가 해당 값을 0점으로 오인시키지 않고 `점수 없음`으로 함께 알린다.
- 칠판을 빠르게 여러 번 눌러도 회전이 중첩되거나 앞뒤 면이 동시에 보이지 않는다.
- 화면을 빠르게 전환해도 취소되거나 늦게 완료된 다른 Q의 API 응답이 현재 문제에 섞이지 않는다.
- 요약 또는 문제 상세 요청이 실패하면 사용자가 같은 요청을 다시 시도할 수 있다.
- `examId`가 없을 때는 요약 API를 호출하지 않고 빈 상태가 표시된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 피드백 탭은 예상 총점, 한눈에 보기, 종합 피드백, 파트별 피드백과 파트별 점수를 이 순서로 제공하는 하나의 세로 스크롤 화면이어야 한다.
- **FR-002**: 결과 화면은 단계 숫자, 페이지 점, 옆 인덱스와 다음 학습 추천을 표시하지 않아야 한다.
- **FR-003**: 예상 총점 칠판은 총점, 만점, 레벨과 결과 요약을 실제 API에서 매핑한 `ExamGradingResult`에서 표시해야 한다.
- **FR-004**: 종합 피드백 카드는 실제 `overallFeedback`과 기존 마스코트를 함께 표시하되 텍스트를 가리지 않아야 한다.
- **FR-005**: 파트별 피드백 카드는 파트 번호, 학습 주제, 상태, 실제 `partFeedback`, Q 번호와 문제 이동 버튼을 제공해야 한다.
- **FR-006**: 파트 문제 버튼은 해당 파트 첫 문항의 실제 `ExamQuestionDetail`을 `retryCount=0`으로 조회해 열어야 한다.
- **FR-007**: 문제 상세는 같은 파트의 실제 문제 사이를 Q 번호로 이동할 수 있어야 한다.
- **FR-008**: 문제 상세에서 돌아오면 결과 화면의 기존 세로 스크롤 위치를 유지해야 한다.
- **FR-009**: 파트별 점수 섹션은 누를 수 있는 칠판 앞면과 오각형 점수 그래프 뒷면을 제공해야 한다.
- **FR-010**: 칠판 앞면은 그래프가 숨겨져 있다는 사실과 누르면 확인할 수 있다는 동작을 명시해야 한다.
- **FR-011**: 칠판은 기본 앞면에서 시작하고 유효한 선택마다 앞면과 그래프 뒷면을 번갈아 표시해야 한다.
- **FR-012**: 오각형 그래프는 Part 1~5를 고정된 순서로 배치하고 실제 `partScores`를 고정 만점 `6/6/9/9/5`에 맞춰 표시해야 한다.
- **FR-013**: 그래프와 함께 Part 1~5의 점수와 기준값을 텍스트로 제공해야 한다.
- **FR-014**: 움직임 감소 설정에서는 회전 없이 그래프를 즉시 표시해야 한다.
- **FR-015**: 칠판 회전 중 반복 선택은 추가 전환을 시작하지 않아야 한다.
- **FR-016**: 요약 및 문제 상세 API 응답은 기존 mapper를 거쳐 각각 `ExamGradingResult`와 `ExamQuestionDetail`로 정규화되어야 한다.
- **FR-017**: 화면은 기존 마스코트 자산을 의미에 맞게 사용하고 신규 캐릭터를 만들지 않아야 한다.
- **FR-018**: 모든 버튼은 보이는 레이블과 보조 기술용 이름을 제공해야 한다.
- **FR-019**: 결과 콘텐츠는 휴대폰/태블릿, 큰 글자 설정과 안전 영역에서 잘리거나 겹치지 않아야 한다.
- **FR-020**: 채점 완료 화면은 완료된 실제 `examId`를 피드백 탭으로 전달해야 한다.
- **FR-021**: 요약과 문제 상세 요청은 화면 전환 또는 대상 변경 시 이전 요청을 취소하거나 늦은 응답을 무시해야 한다.
- **FR-022**: 요약 및 문제 상세의 로딩, 오류와 사용자 재시도 동작을 제공해야 한다.
- **FR-023**: 정적 피드백 fixture와 마이페이지의 목 피드백 진입 카드를 제거해야 한다.
- **FR-024**: `examId` 없이 피드백 탭을 열면 `완료된 시험이 없어요` 메시지와 `모의고사 시작하기` 버튼을 표시하고 요약 API를 호출하지 않아야 한다.
- **FR-025**: 한눈에 보기 섹션은 실제 `strengths`와 `weaknesses`를 별도 카드로 표시해야 한다.

### Key Entities

- **시험 결과**: 실제 요약 응답을 mapper로 정규화한 `ExamGradingResult`이며 결과 화면의 점수, 요약과 피드백을 제공한다.
- **문제 상세**: 실제 문항 응답을 mapper로 정규화한 `ExamQuestionDetail`이며 특정 Q의 평가, 답변, 교정과 추천 답변을 제공한다.
- **파트 표시 모델**: 실제 시험 결과, 고정 파트 메타데이터, Q 범위와 표준 파트 만점 `6/6/9/9/5`를 결합한다.
- **결과 탐색 상태**: 문제 상세 표시 여부, 선택한 파트/Q와 결과 화면 스크롤 위치를 나타낸다.
- **칠판 상태**: boolean 하나로 기본 앞면과 그래프 뒷면을 나타내며 선택할 때마다 전환된다.
- **오각형 점수 그래프**: Part 1~5의 정규화된 위치, 실제 점수, 기준값과 텍스트 대체 정보를 나타낸다.
- **마스코트 배치**: 기존 자산과 점수, 종합 피드백, 파트 또는 칠판 안내의 의미적 연결을 나타낸다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 첫 화면의 한 번의 연속된 세로 스크롤에서 다섯 주요 콘텐츠가 지정된 순서로 확인된다.
- **SC-002**: 단계 숫자, 페이지 점, 옆 인덱스와 다음 학습 추천이 표시되는 사례가 0건이다.
- **SC-003**: 풀어서 채점된 문제 상세의 100%가 소속 파트 카드에서 두 번 이하의 선택으로 접근 가능하다.
- **SC-004**: 문제 상세에서 돌아오면 이전 결과 스크롤 위치가 유지된다.
- **SC-005**: 칠판을 선택할 때마다 1초 안에 앞면과 오각형 그래프 뒷면이 전환된다.
- **SC-006**: 오각형 그래프의 다섯 꼭짓점과 텍스트 점수의 파트/값 불일치가 0건이다.
- **SC-007**: 움직임 감소 설정에서 회전 애니메이션이 실행되는 사례가 0건이다.
- **SC-008**: 지원되는 휴대폰/태블릿과 큰 글자 설정 검증에서 본문, 마스코트, 그래프와 버튼이 잘리거나 겹치지 않는다.
- **SC-009**: lint와 strict TypeScript 검사에서 실제 API 매퍼 및 UI의 기존 도메인 타입 불일치가 0건이다.
- **SC-010**: 실제 채점 완료 `examId`로 요약 API가 정확히 한 결과 화면을 채우고 fixture 텍스트가 표시되는 사례가 0건이다.
- **SC-011**: Q 전환 중 늦은 응답이 현재 선택한 문제를 덮어쓰는 사례가 0건이다.
- **SC-012**: `examId` 없는 피드백 탭 진입에서 API 호출은 0건이며 한 번의 선택으로 모의고사 화면에 이동할 수 있다.

## Assumptions

- 칠판은 boolean 상태 하나로 관리하며 기본값은 앞면이고 선택할 때마다 앞뒤가 전환된다.
- `output/mockups/unified-feedback-flow-v1.png`의 카드 스타일과 마스코트 방향은 유지하되 페이지 구조는 최신 단일 스크롤 요구로 대체한다.
- 파트 상태 배지는 실제 `partScores / 고정 파트 만점` 비율로 UI에서 파생한다.
- 문제 번호는 `totalSolvedQuestions`와 정규 시험 파트 구성을 결합하며 선택 시 실제 상세 존재 여부를 API로 확인한다.
- `retryCount=0`은 최초 응시 회차다. 다시 답변을 추가할 때는 최신 `totalRetryCount`를 새 AnswerKey의 `retryCount`로 사용하고, 동일 답변의 전송 재시도는 그 값을 증가시키지 않는다.
