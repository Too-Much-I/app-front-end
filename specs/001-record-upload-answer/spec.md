## Requirements Source

### Confirmed Facts

- Jira 이슈가 명시한 범위는 모의고사 답변의 녹음과 업로드 로직 구현이다.
- Jira 이슈에는 제목 외에 설명, 댓글, 첨부 파일 또는 연결 이슈가 없다.
- 모의고사는 문항별 준비 구간과 답변 구간을 순서대로 진행하며, 사용자는 지난 문항으로 돌아가지 않는다.

### Confirmed Product Decisions

- 답변 녹음 중 앱이 비활성화되거나 오디오 인터럽션이 발생하면 부분 녹음을 폐기하고 같은 문항을 다시 녹음한다.
- 답변 파일 업로드 또는 채점 요청이 실패해도 다음 문항 진행을 허용하고, 실패한 처리는 백그라운드에서 재시도한다.
- 마지막 답변 종료 후 모든 문항의 답변 업로드와 채점 요청이 성공해야 시험 완료를 확정한다.
- 답변 녹음 중에는 마이크 입력 레벨을 마이크 테스트와 같은 방식의 움직이는 파형으로 표시한다.

## Scope *(mandatory)*

### In Scope

- 각 문항의 답변 구간에 맞춰 음성을 녹음하고 종료하는 동작
- 답변 제한 시간이 끝나거나 사용자가 답변 완료를 선택했을 때 녹음 파일을 확정하는 동작
- 확정된 답변을 해당 시험, 문항 및 응시 회차에 연결해 업로드하고 채점을 요청하는 동작
- 녹음 권한 거부, 녹음 중단, 파일 확정 실패, 업로드 실패 및 채점 요청 실패의 사용자 처리 경로
- 화면 이탈과 앱 상태 변화가 겹쳐도 하나의 문항 답변이 중복 녹음·중복 제출되지 않도록 하는 동작
- iOS와 Android에서 동일한 사용자 흐름과 결과를 제공하는 동작

### Out of Scope

- 채점 모델과 채점 기준의 변경
- 서버에서 수행하는 오디오 변환 방식의 변경
- 마이크 테스트와 음향 테스트의 판정 로직 변경
- 답변 재생, 편집 또는 사용자가 임의 파일을 선택해 제출하는 기능
- 채점 결과 및 피드백 화면의 변경
- 완료된 답변을 장기 보관하거나 기기 파일로 내보내는 기능

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 답변을 녹음해 제출한다 (Priority: P1)

응시자는 문항의 준비를 마친 뒤 답변 구간에 진입하면 별도의 복잡한 조작 없이 자신의 음성이 녹음되고, 답변을 마치면 해당 문항의 답변이 제출되기를 원한다.

**Why this priority**: 답변 녹음과 제출은 모의고사 채점이 성립하기 위한 핵심 흐름이다.

**Independent Test**: 마이크 권한과 네트워크가 정상인 상태에서 한 문항의 답변 구간을 완료하고, 해당 문항에 정확히 하나의 답변이 제출되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 준비 구간이 끝나고 마이크 사용이 가능한 상태에서, **When** 답변 구간이 시작되면, **Then** 해당 문항의 답변 녹음이 시작되고 실제 마이크 입력에 반응하는 파형으로 녹음 중임을 사용자가 알 수 있다.
2. **Given** 답변을 녹음 중일 때, **When** 답변 제한 시간이 끝나면, **Then** 녹음이 자동으로 종료되고 해당 문항의 완성된 답변이 업로드 대상으로 확정된다.
3. **Given** 답변을 녹음 중일 때, **When** 사용자가 제한 시간 전에 답변 완료를 선택하면, **Then** 그 시점까지의 녹음이 한 번만 종료되고 업로드 대상으로 확정된다.
4. **Given** 답변 파일 업로드가 완료됐을 때, **When** 시스템이 제출을 마치면, **Then** 답변은 현재 시험의 현재 문항 및 응시 회차에 연결되어 채점 대기 상태가 된다.
5. **Given** 마지막 문항의 답변이 끝났을 때, **When** 하나 이상의 답변 제출이 아직 처리 중이면, **Then** 모든 답변 제출이 성공할 때까지 시험 완료를 확정하지 않고 처리 상태를 안내한다.

---

### User Story 2 - 답변을 안전하게 연속 진행한다 (Priority: P2)

응시자는 여러 문항을 순서대로 풀 때 이전 문항의 종료와 다음 문항의 시작이 겹치거나 답변이 바뀌어 제출되는 문제 없이 시험을 계속하고 싶다.

**Why this priority**: 한 문항의 답변이 다른 문항에 연결되거나 중복 제출되면 전체 시험 결과의 신뢰성이 훼손된다.

**Independent Test**: 답변 완료 버튼, 제한 시간 종료 및 화면 전환을 가깝게 연속 발생시켜도 문항별로 최대 하나의 완성된 답변만 만들어지고 올바른 문항에 연결되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 현재 문항의 답변 종료 처리가 진행 중일 때, **When** 제한 시간 종료와 사용자의 완료 선택이 연이어 발생하면, **Then** 동일한 녹음 종료 결과 하나만 사용된다.
2. **Given** 이전 문항의 답변이 처리 중일 때, **When** 다음 문항의 준비 또는 답변 구간이 시작되면, **Then** 이전 답변과 다음 답변의 음성 및 문항 식별 정보가 섞이지 않는다.
3. **Given** 준비 구간이나 문제 안내 음성이 재생되는 구간일 때, **When** 사용자가 시험을 진행하면, **Then** 해당 구간의 소리는 답변 녹음에 포함되지 않는다.
4. **Given** 이전 문항의 제출이 실패했을 때, **When** 다음 문항을 시작하면, **Then** 시험은 계속 진행되고 실패한 제출은 다음 문항 녹음과 독립적으로 다시 처리된다.

---

### User Story 3 - 문제 상황을 이해하고 복구한다 (Priority: P3)

응시자는 권한, 기기 오디오 또는 네트워크 문제로 답변을 정상 제출할 수 없을 때 답변이 제출된 것으로 오해하지 않고, 가능한 다음 행동을 안내받고 싶다.

**Why this priority**: 실패를 성공처럼 처리하면 답변 유실을 뒤늦게 발견하며, 복구 방법이 없으면 시험 전체를 다시 시작해야 할 수 있다.

**Independent Test**: 마이크 권한 거부, 녹음 시작·종료 실패, 네트워크 단절 및 채점 요청 실패를 각각 발생시키고 상태 안내와 허용된 복구 행동을 확인한다.

**Acceptance Scenarios**:

1. **Given** 마이크 권한이 없거나 녹음을 시작할 수 없을 때, **When** 답변 구간 진입을 시도하면, **Then** 녹음이 시작되지 않았음을 알리고 권한 설정 또는 시험 이탈 방법을 안내한다.
2. **Given** 녹음 종료 후 유효한 답변 파일을 확정하지 못했을 때, **When** 시스템이 다음 단계를 결정하면, **Then** 해당 문항을 제출 완료로 표시하지 않고 실패 사실과 가능한 복구 행동을 안내한다.
3. **Given** 답변 업로드 또는 채점 요청이 실패했을 때, **When** 실패가 확인되면, **Then** 사용자는 실패 단계에 맞는 상태와 다음 행동을 안내받는다.
4. **Given** 녹음 중 앱 비활성화 또는 오디오 인터럽션이 발생했을 때, **When** 정상적인 녹음을 이어갈 수 없으면, **Then** 부분 녹음을 제출하지 않고 같은 문항을 다시 녹음할 수 있게 안내한다.
5. **Given** 백그라운드 재시도가 끝난 뒤에도 제출하지 못한 답변이 있을 때, **When** 마지막 문항까지 완료하면, **Then** 시험 완료를 확정하지 않고 실패한 답변의 재시도 상태와 행동을 안내한다.

### Edge Cases

- 답변 구간 시작 직후 사용자가 완료를 선택한다.
- 제한 시간 종료와 완료 선택이 동시에 발생한다.
- 녹음 시작 또는 종료를 기다리는 동안 화면을 벗어난다.
- 녹음 중 전화, 알람 또는 다른 앱의 오디오가 끼어든다.
- 녹음 중 앱이 백그라운드로 이동하거나 운영체제가 오디오 세션을 초기화한다.
- 녹음 종료는 성공했지만 유효한 파일을 얻지 못한다.
- 파일 업로드는 성공했지만 채점 요청의 응답만 유실된다.
- 네트워크가 느려 업로드가 오래 걸리거나 업로드 주소가 만료된다.
- 이전 문항 업로드 중 다음 문항 녹음이 시작된다.
- 마지막 문항의 녹음은 끝났지만 하나 이상의 답변이 아직 처리 중이다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 각 문항의 답변 구간이 시작될 때 해당 문항을 위한 새 답변 녹음을 시작해야 한다.
- **FR-002**: 시스템은 준비 구간, 파트 안내 및 문제 안내 재생 구간을 답변 녹음에서 제외해야 한다.
- **FR-003**: 시스템은 답변 제한 시간이 끝나거나 사용자가 답변 완료를 선택하면 현재 녹음을 종료하고 유효한 답변 파일을 확정해야 한다.
- **FR-004**: 시스템은 한 문항의 한 응시 회차에 대해 최대 하나의 녹음 종료 결과와 최대 하나의 제출 흐름만 활성화해야 한다.
- **FR-005**: 시스템은 확정된 답변을 현재 시험, 문항 및 응시 회차와 정확히 연결해야 한다.
- **FR-006**: 시스템은 답변 파일 전송이 완료된 후에만 해당 파일의 채점을 요청해야 한다.
- **FR-007**: 시스템은 이전 문항의 답변 처리와 다음 문항의 녹음을 서로 독립적으로 관리해야 한다.
- **FR-008**: 시스템은 성공적으로 처리된 답변의 기기 내 임시 파일을 더 이상 필요하지 않은 시점에 제거해야 한다.
- **FR-009**: 시스템은 마이크 권한 거부, 녹음 시작 실패, 녹음 종료 실패 및 유효한 파일 부재를 제출 성공으로 처리해서는 안 된다.
- **FR-010**: 시스템은 업로드 실패와 파일 전송 후 채점 요청 실패를 구분해 사용자가 가능한 복구 행동을 판단할 수 있게 해야 한다.
- **FR-011**: 시스템은 화면 이탈, 앱 상태 변화 및 중복 종료 신호가 겹쳐도 열린 녹음 작업과 오디오 사용 상태를 안전하게 정리해야 한다.
- **FR-012**: 시스템은 녹음 중 앱 비활성화 또는 오디오 인터럽션으로 정상적인 녹음을 이어갈 수 없으면 부분 녹음을 폐기하고 같은 문항을 다시 녹음할 수 있게 해야 한다.
- **FR-013**: 시스템은 업로드 또는 채점 요청이 실패해도 다음 문항 진행을 허용하고, 실패한 답변 처리를 다음 문항 녹음과 독립적으로 백그라운드에서 재시도해야 한다.
- **FR-014**: 시스템은 마지막 답변 종료 후 모든 문항의 답변 업로드와 채점 요청이 성공할 때까지 처리 상태를 표시하고 시험 완료를 확정해서는 안 된다.
- **FR-015**: 시스템은 녹음과 제출 상태를 iOS와 Android 모두에서 사용자가 동일한 의미로 이해할 수 있게 표시해야 한다.
- **FR-016**: 시스템은 답변 녹음 중 마이크 입력 metering을 시각적 파형으로 표시하되, 입력 음량이나 무음을 답변 파일 유효성 판정에 사용해서는 안 되며 파형에 의존하지 않는 텍스트 녹음 상태도 함께 제공해야 한다.

### Key Entities

- **시험 세션**: 하나의 모의고사 응시를 나타내며 시험 식별자, 문항 순서 및 진행 상태를 가진다.
- **문항 답변**: 특정 시험의 특정 문항과 응시 회차에 속하는 음성 답변으로, 녹음·파일 확정·업로드·채점 요청 상태를 가진다.
- **답변 파일**: 한 문항의 완성된 음성을 담는 기기 내 임시 데이터로, 유효성 및 처리 완료 여부를 가진다.
- **답변 처리 결과**: 파일 전송과 채점 요청의 성공 또는 실패 단계 및 사용자가 취할 수 있는 후속 행동을 나타낸다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 정상 권한과 네트워크 조건의 검증 시나리오에서 완료한 문항의 100%가 해당 문항과 응시 회차에 정확히 연결된 답변 하나를 생성한다.
- **SC-002**: 제한 시간 종료와 사용자 완료 선택이 동시에 발생하는 검증 시나리오의 100%에서 중복 답변 또는 중복 제출이 발생하지 않는다.
- **SC-003**: 답변 시작 및 종료 상태가 사용자 행동 또는 제한 시간 전환 후 1초 이내에 화면에 반영된다.
- **SC-004**: 권한, 녹음, 업로드 및 채점 요청 실패 시나리오의 100%에서 실패가 성공으로 표시되지 않고 사용 가능한 다음 행동이 제시된다.
- **SC-005**: 화면 이탈, 백그라운드 전환 및 오디오 인터럽션 검증 후 활성 상태로 남아 있는 불필요한 녹음이 0건이다.
- **SC-006**: 동일한 핵심 시나리오가 지원 대상 iOS 및 Android 실기기에서 동일한 결과로 완료된다.

## Assumptions

- 사용자는 실제 모의고사에 들어가기 전에 마이크 테스트를 거치지만, 시험 중 권한이나 오디오 환경이 바뀔 수 있으므로 실제 답변에서도 오류 처리가 필요하다.
- 답변은 사용자가 편집하거나 다시 듣지 않고, 한 번 확정되면 현재 문항의 채점 입력으로 사용된다.
- 최초 응시 회차를 기본 대상으로 하며 재응시도 동일한 회차 식별 규칙으로 확장할 수 있어야 한다.
- 답변 파일은 장기 보관 대상이 아닌 임시 데이터이며, 성공적으로 처리된 뒤 기기에서 제거해도 된다.
- 채점 시스템과 답변 업로드 계약은 현재 서버 동작을 유지한다.

## Integration Dependencies

- submit 응답 유실 뒤 자동 재시도를 안전하게 수행하려면 서버가 동일한
  `(examId, questionNumber, retryCount, fileKey)` 요청을 하나로 처리하고 기존 상태를
  반환해야 한다.
- 문항 상태 조회는 접수 상태와 명확한 미접수 상태를 구분할 수 있어야 한다. 일반 network
  error나 불명확한 4xx/5xx는 미접수 증거로 사용하지 않는다.
- 위 계약을 통합 환경에서 확인하지 못하면 client는 중복 제출 방지를 위해 자동 재-POST를
  활성화하지 않으며, 해당 상태는 기능 완료가 아니라 `submission-unknown`으로 남긴다.
