# Feature Specification: 최초 실행 개인정보 동의 게이트

**Feature Branch**: `008-onboarding-consent-gate`

**Created**: 2026-08-04

**Status**: Draft

**Issue**: N/A (대화 기반 요구사항, Jira 이슈 없음)

**Approval**: 대화로 합의된 내용을 문서화. 사용자가 UI 구현을 승인함.

## Scope *(mandatory)*

### In Scope

- 앱을 기기에서 처음 실행했을 때(또는 로컬 저장소 초기화 이후) 개인정보 수집·이용, 개인정보
  처리방침, 서비스 이용약관에 대한 동의를 받는 화면 1개.
- 필수 항목 3개를 모두 체크해야 "모두 동의하고 시작하기" 버튼이 활성화된다.
- 동의 완료 시점을 로컬 저장소에 기록해, 다음 실행부터는 이 화면을 건너뛰고 메인 탭으로
  바로 진입한다.
- 개인정보 처리방침·이용약관 행은 기존 `SettingsWebView`(정적 웹뷰) 화면을 재사용한다.

### Out of Scope

- 실제 백엔드 액세스/리프레시 토큰 발급 API 연동. 아직 백엔드가 없으므로 이번 작업은
  "동의 여부"만 로컬에 저장하고, 서버 발급 토큰 저장(zustand + SecureStore 조합)은 이후
  백엔드가 준비되면 별도 작업으로 진행한다.
- 목업 이미지에 있던 "토큰 사용 동의" 화면. 목업 생성 과정의 오류로 확인되어 제외한다.
- 약관 버전이 바뀌었을 때의 재동의 플로우. 지금은 단일 버전만 존재하므로 다루지 않는다.
- 동의를 거부했을 때의 "제한적으로 사용하기" 같은 대체 경로. 세 항목 모두 필수이므로
  거부 시 진행할 수 있는 경로 자체가 없다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 최초 실행 시 동의 후 앱 진입 (Priority: P1)

사용자가 앱을 기기에 설치하고 처음 실행하면, 메인 화면 대신 동의 화면이 뜬다. 필수 항목
3개를 모두 확인하고 체크한 뒤 "모두 동의하고 시작하기"를 누르면 메인 탭(홈)으로 이동한다.

**Why this priority**: 이 동의를 받지 않으면 이후 어떤 개인정보 처리(모의고사 채점, 사용자
식별 등)도 시작할 수 없으므로 앱 전체의 진입점이다.

**Independent Test**: 로컬 저장소를 비운 상태로 앱을 콜드 스타트해서 동의 화면이 뜨는지,
체크 전에는 버튼이 비활성화 상태인지, 체크 후 버튼을 누르면 메인 탭으로 이동하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로컬에 동의 기록이 없는 상태, **When** 앱을 실행하면, **Then** 동의 화면이
   메인 탭보다 먼저 표시된다.
2. **Given** 동의 화면에서 필수 항목 중 하나라도 체크되지 않은 상태, **When** 사용자가
   "모두 동의하고 시작하기"를 보면, **Then** 버튼은 비활성화(회색) 상태다.
3. **Given** 필수 항목 3개를 모두 체크한 상태, **When** "모두 동의하고 시작하기"를 누르면,
   **Then** 동의 기록이 로컬에 저장되고 메인 탭으로 이동하며, 뒤로 가기로 동의 화면에
   돌아갈 수 없다.

---

### User Story 2 - 재실행 시 동의 화면 생략 (Priority: P1)

이미 동의를 완료한 사용자가 앱을 다시 실행하면 동의 화면 없이 바로 메인 탭이 뜬다.

**Why this priority**: 매번 동의를 다시 받으면 앱을 쓸 수 없는 수준의 마찰이 생긴다.

**Independent Test**: User Story 1을 완료한 뒤 앱을 완전히 종료했다가 다시 실행해서 동의
화면 없이 메인 탭이 바로 뜨는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로컬에 유효한 동의 기록이 있는 상태, **When** 앱을 재실행하면, **Then** 동의
   화면을 거치지 않고 메인 탭이 표시된다.

---

### User Story 3 - 처리방침/이용약관 상세 확인 (Priority: P2)

사용자가 "개인정보 처리방침 동의" 또는 "서비스 이용약관 동의" 행을 누르면 기존 설정 화면과
동일한 웹뷰로 전체 내용을 확인할 수 있다.

**Why this priority**: 필수 흐름은 아니지만, 체크만 하고 내용을 확인할 방법이 없으면 안 된다.

**Independent Test**: 동의 화면에서 두 행을 각각 눌러 웹뷰가 올바른 경로로 열리는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 동의 화면, **When** "개인정보 처리방침 동의" 행을 누르면, **Then**
   `SettingsWebView`가 `/app-settings/privacy` 경로로 열린다.
2. **Given** 동의 화면, **When** "서비스 이용약관 동의" 행을 누르면, **Then**
   `SettingsWebView`가 `/app-settings/terms` 경로로 열린다.

### Edge Cases

- 로컬 저장소 읽기 자체가 실패하면(드문 경우) 동의하지 않은 것으로 간주해 동의 화면을
  보여준다(무음 실패로 메인 탭에 들여보내지 않는다).
- 저장 쓰기가 실패하면 사용자에게 알리고 동의 화면에 머무른다(진행하지 않는다).
- 폰트 로딩과 동의 기록 조회가 동시에 진행되므로, 스플래시 화면은 둘 다 끝난 뒤에 내려가야
  한다. 하나만 끝난 상태로 첫 화면이 그려지면 깜빡임이 생긴다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 앱 부팅 시 로컬 저장소에서 동의 기록을 조회해야 한다.
- **FR-002**: 동의 기록이 없거나 버전이 다르면 동의 화면을 시작 화면으로 표시해야 한다.
- **FR-003**: 동의 화면은 개인정보 수집·이용 동의, 개인정보 처리방침 동의, 서비스 이용약관
  동의 세 개의 독립적인 체크박스를 제공해야 한다.
- **FR-004**: "모두 동의하고 시작하기" 버튼은 세 체크박스가 모두 선택된 경우에만 활성화되어야
  한다.
- **FR-005**: 버튼을 누르면 동의 기록(버전, 시각)을 로컬 저장소에 저장하고 메인 탭으로
  이동해야 하며, 스택을 리셋해 뒤로 가기로 동의 화면에 돌아갈 수 없어야 한다.
- **FR-006**: 처리방침/이용약관 행을 누르면 기존 `SettingsWebView` 화면을 재사용해 해당
  경로를 열어야 한다.
- **FR-007**: 저장 실패 시 사용자에게 실패를 알리고 화면에 머물러야 한다(조용히 다음
  단계로 넘어가지 않는다).

### Key Entities

- **동의 기록(ConsentRecord)**: `{ version: string; agreedAt: string }`. 항목별이 아니라
  세 필수 항목을 포괄하는 단일 버전으로 관리한다(개인정보 처리방침/이용약관 링크 확인 여부는
  UI 단에서만 체크 상태로 존재하고, 저장되는 것은 "이 버전에 전부 동의했다"는 사실 하나다).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 로컬 저장소가 비어 있는 상태로 콜드 스타트하면 100% 동의 화면이 먼저 뜬다.
- **SC-002**: 동의를 완료한 뒤 앱을 재실행하면 100% 동의 화면 없이 메인 탭으로 진입한다.
- **SC-003**: 필수 항목 중 하나라도 체크 해제하면 시작 버튼이 즉시 비활성화된다.

## Assumptions

- 이번 작업 시점에는 실제 사용자 식별용 백엔드 토큰 발급 API가 없다. 이후 API가 생기면
  "동의 완료 → 토큰 발급 요청" 순서로 이어붙이되, 그 시점에 토큰 저장은 SecureStore +
  zustand 조합으로 별도 설계한다.
- 목업 이미지의 "토큰 사용 동의" 화면은 제외 대상이 맞다(사용자가 목업 생성 오류로 확인).
- 개인정보 수집·이용 동의 카드의 표(수집 항목/이용 목적/보유 기간)는 아코디언 없이 항상
  펼친 상태로 단순화한다. "자세히 보기" 버튼은 `SettingsWebView`의 개인정보 처리방침
  경로로 연결한다.
- 마스코트 이미지는 목업과 동일한 헤드폰 낀 토끼 에셋이 없어 기존 `paper_rabbit.png`로
  대체한다.
