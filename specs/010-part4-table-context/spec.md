# Feature Specification: Part 4 구조화 표 렌더링

**Feature Branch**: `feat/responsive-scaling` (feature ID: `010-part4-table-context`)

**Created**: 2026-08-07

**Status**: Approved (2026-08-07)

**Issue**: N/A (대화 기반 요구사항)

**Approval**: 2026-08-07 사용자가 "코드 수정해서 반영해줘"라고 요청해 명세 범위의 구현 진행을
승인했다. 저장소 게이트에 따라 구현 계획은 별도로 검토받는다.

**Input**: Part 4가 이미지 URL 대신 서버의 `tableContext` 객체를 받고, 고정 컬럼 가정이나
행 필터링 없이 공개 규격에 포함된 모든 표 정보를 누락 없이 표시한다.

## Requirements Source

### Confirmed Facts

- Part 4 정보는 더 이상 이미지 URL이 아니라 구조화된 표 객체로 제공된다.
- 표는 제목, 부제 목록, 메타데이터 목록, 컬럼 정의, 행 목록, 주석 목록으로 구성된다.
- 행의 표시 순서는 행 객체의 속성 순서가 아니라 서버가 제공한 컬럼 순서를 따른다.
- 빈 값은 `null`, 누락 값 또는 빈 문자열이며 숫자 `0`과 boolean `false`는 유효한 표시값이다.
- 행의 상태 설명은 셀 값과 구분된 상태 배지로 표시하며 행 취소선의 영향을 받지 않는다.
- 취소선 지정은 행의 모든 셀 표시값에 적용된다.
- 클라이언트는 상태에 따라 행을 임의로 제거하지 않는다.
- 알 수 없는 표 종류, 값 종류, 컬럼 키도 거부하지 않고 제공된 표시 문자열을 보존한다.
- 셀 값은 이미 표시용으로 생성되므로 날짜, 시간, 통화 등을 클라이언트가 다시 해석하거나
  변환하지 않는다.
- 공개 변환 과정에서 제외된 내부 필드는 클라이언트가 복구할 수 없다.

### Reference Data Verification

- `docs/part4_tables (1).json`은 20개 시험의 표 20개, 행 130개, 컬럼 선언 74개를 포함한다.
- 각 항목의 바깥쪽에는 `mock_exam_id`, `title`, `table_context`가 있으며, 제시된
  `TableContext` 규약은 이 중 `table_context` 객체를 대상으로 한다.
- 모든 `table_context`는 `table_type`, `title`, `subtitles`, `metadata`, `columns`,
  `items`, `notes`를 가지며 각 하위 객체의 필드도 제시된 규약과 일치한다.
- 샘플은 8종의 표 종류, 8종의 값 종류, 31종의 컬럼 키와 6종의 행 상태를 포함한다.
- 모든 행에서 선언 컬럼 대비 누락 셀, 추가 셀 및 중복 컬럼 키는 각각 0건이다.
- 셀에는 문자열, 숫자 및 null이 관측됐고 빈 문자열 30개, null 24개, 숫자 6개가 있다.
  boolean 셀은 관측되지 않았지만 공개 스칼라 규약의 허용값으로 유지한다.
- 취소선 행은 3개, 상태 설명이 있는 행은 5개이며 부제, 메타데이터와 주석이 비어 있지 않은
  표도 포함된다.
- 주석의 `scope` 중 `metadata:meta_minimum_driver_age`는 실제 metadata key
  `minimum_driver_age`와 일치하지 않는다. 따라서 이번 범위에서는 scope를 관계 식별자로
  강제 해석하지 않고 주석 자체의 문자열 정보로 보존한다.

## Scope *(mandatory)*

### In Scope

- Part 4 사전 읽기 화면과 각 Part 4 문제에서 이미지 대신 같은 구조화 표를 표시
- 재답변에서 Part 4 문제 원문을 다시 볼 때도 구조화 표를 표시
- 제목, 부제, 메타데이터, 컬럼, 모든 행, 행 상태 설명 및 주석을 각각 표시
- 컬럼 정의 순서에 따라 모든 행의 셀을 조회하고 누락 셀을 식별 가능한 빈 값으로 표시
- 표시용 문자열을 그대로 보존하고 숫자와 boolean 값을 손실 없이 표시
- 상태 설명과 취소선 행을 서로 간섭하지 않도록 구분해 표시
- 알 수 없는 표 종류, 값 종류, 상태 및 컬럼 키를 기존 표와 같은 기본 표현으로 표시
- 계약 일부가 비어 있거나 셀이 누락된 경우 사용 가능한 정보는 유지하고 진단 정보를 남김
- 구조화 표가 없거나 표 전체를 표시할 수 없는 경우 Part 4 진행을 막고 복구 가능한 오류를 안내
- 휴대폰과 태블릿, 긴 값, 많은 컬럼 및 큰 글자 설정에서 전체 정보에 접근 가능한 반응형 표시
- 기존 45초 읽기, 준비 완료, 문제별 준비와 답변 흐름을 유지

### Out of Scope

- 공개 규격에서 제거된 `item_id`, `active`, `rescheduled_from`, `normalized` 등 내부 필드 복구
- 서버 public 규격 또는 표 생성 로직 확장
- 표 값의 날짜, 시간대, 숫자, 통화 또는 지역별 형식 재변환
- 상태를 근거로 행을 정렬, 병합, 숨김 또는 재분류하는 비즈니스 로직
- Part 4 표 편집, 검색, 정렬 및 필터 기능
- Part 1, Part 2, Part 3 및 Part 5 콘텐츠 표시 변경
- Part 4 읽기 시간과 문제별 준비·답변 시간 변경

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 모든 Part 4 정보를 표에서 확인한다 (Priority: P1)

응시자는 Part 4 문제에 답하는 데 필요한 제목, 부가 정보, 표의 모든 행과 주석을 서버가 정한
순서 그대로 확인한다.

**Why this priority**: 열이나 행이 누락되거나 순서가 바뀌면 질문에 필요한 사실을 잘못 읽어
정답에 직접 영향을 받을 수 있다.

**Independent Test**: 참조 JSON의 20개 표를 차례로 표시해 각 제목, 부제, 메타데이터,
컬럼, 130개 행과 주석이 원본 순서와 값으로 모두 확인되는지 대조한다.

**Acceptance Scenarios**:

1. **Given** 서로 다른 컬럼 키를 가진 Part 4 표, **When** 표가 표시되면, **Then** 고정된
   필드 이름이 아니라 제공된 컬럼 정의와 순서에 따라 헤더와 각 셀을 표시한다.
2. **Given** 제목, 부제, 메타데이터와 주석이 있는 표, **When** 응시자가 전체 화면을
   확인하면, **Then** 표 본문뿐 아니라 모든 부가 정보도 각각 식별 가능하게 표시된다.
3. **Given** 상태가 scheduled가 아닌 행, **When** 표가 표시되면, **Then** 해당 행도
   제거되지 않고 원래 위치에 표시된다.
4. **Given** Part 4 읽기 단계가 끝나 문제로 이동한 상태, **When** 8~10번 문제를 확인하면,
   **Then** 같은 구조화 표를 계속 참고할 수 있다.
5. **Given** Part 4 문제를 재답변하는 상태, **When** 문제 원문을 확인하면, **Then** 이미지가
   없어도 같은 구조의 표 정보를 확인할 수 있다.

### User Story 2 - 상태와 빈 값을 오해 없이 읽는다 (Priority: P1)

응시자는 취소, 변경, 예약 불가 같은 행 상태와 실제 빈 셀을 구분하고, 숫자 0이나 boolean
false도 누락되지 않은 값으로 읽는다.

**Why this priority**: 상태 설명이나 유효한 falsy 값이 사라지면 일정 변경과 이용 조건을
반대로 이해할 수 있다.

**Independent Test**: null, 빈 문자열, 누락 키, 0, false, 상태 설명과 취소선 조합을 가진
표를 표시해 각 값과 상태가 서로 구분되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 셀 값이 null, 누락 또는 빈 문자열인 행, **When** 셀이 표시되면, **Then** 값이
   없음을 나타내는 일관된 대체 기호가 표시된다.
2. **Given** 셀 값이 숫자 0 또는 boolean false인 행, **When** 셀이 표시되면, **Then** 빈
   값 대체 기호가 아니라 각각의 실제 값이 표시된다.
3. **Given** 상태 설명이 있는 행, **When** 행을 확인하면, **Then** 상태와 설명은 셀
   표시값과 구분된 상태 배지로 표시된다.
4. **Given** 취소선과 상태 설명이 함께 있는 행, **When** 행을 확인하면, **Then** 모든 셀
   표시값에는 취소선이 적용되지만 상태 배지에는 적용되지 않는다.

---

### User Story 3 - 새 표 변형도 안전하게 확인한다 (Priority: P2)

응시자는 서버가 새로운 표 종류, 값 종류, 상태나 컬럼을 추가해도 앱 업데이트 전까지 제공된
표시 문자열을 확인할 수 있다.

**Why this priority**: 표 계약은 동적 컬럼을 전제로 하므로 알려진 enum에만 의존하면 정상
데이터가 빈 화면이나 오류로 바뀔 수 있다.

**Independent Test**: 참조 데이터에 없는 표 종류, 값 종류, 상태와 컬럼 키를 가진 표를
표시해 행과 값이 기본 표현으로 남는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 알려지지 않은 표 종류 또는 값 종류, **When** 표가 표시되면, **Then** 표 전체를
   거부하지 않고 제공된 제목, 라벨과 셀 문자열을 기본 표현으로 표시한다.
2. **Given** 처음 보는 컬럼 키, **When** 행이 표시되면, **Then** 컬럼 라벨과 해당 키의 셀
   값을 컬럼 순서에 맞게 표시한다.
3. **Given** 선언된 컬럼에 대응하는 셀 키가 없는 행, **When** 표가 표시되면, **Then** 해당
   셀만 대체 기호로 표시하고 나머지 행과 열은 유지한다.
4. **Given** 주석 scope가 알려진 metadata key와 일치하지 않는 표, **When** 주석을 확인하면,
   **Then** 주석 텍스트가 누락되지 않고 독립된 주석으로 표시된다.

---

### User Story 4 - 다양한 화면에서 표 전체에 접근한다 (Priority: P2)

응시자는 작은 휴대폰, 태블릿 또는 큰 글자 설정에서도 긴 표의 모든 열과 행을 읽고 기존 시험
흐름을 계속 진행한다.

**Why this priority**: 구조화 표는 이미지보다 콘텐츠 크기가 유동적이므로 잘림이나 터치 영역
충돌이 생기면 정보 일부가 사실상 누락된다.

**Independent Test**: 가장 많은 6개 컬럼을 가진 표와 긴 셀 값을 작은 화면 및 큰 글자
설정에서 열어 모든 정보와 준비 완료 행동에 접근할 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 화면 폭보다 넓은 표, **When** 응시자가 표 영역을 이동하면, **Then** 첫 열부터
   마지막 열까지 확인할 수 있다.
2. **Given** 화면 높이보다 긴 표, **When** 응시자가 읽기 화면을 이동하면, **Then** 제목부터
   마지막 주석과 준비 완료 행동까지 접근할 수 있다.
3. **Given** 구조화 표가 정상 표시된 상태, **When** 읽기 단계가 시작되면, **Then** 기존
   45초 타이머와 준비 완료 동작이 유지된다.

### Edge Cases

- 컬럼 또는 행 배열이 비어 있다.
- 한 행의 cells 객체가 없거나 선언된 일부 컬럼 키를 포함하지 않는다.
- cells 객체가 컬럼에 없는 추가 키를 포함한다.
- 컬럼 키, 라벨, 제목, 부제 또는 표시 문자열이 매우 길다.
- 컬럼 키가 서로 중복된다.
- 셀 값이 null, 빈 문자열, 0 또는 false다.
- 상태 문자열은 알 수 없지만 상태 설명은 존재한다.
- 취소선 행에 상태 설명이 함께 있다.
- 주석 scope가 `table`이 아니거나 존재하는 metadata key와 연결되지 않는다.
- 알 수 없는 표 종류와 값 종류가 동시에 제공된다.
- Part 4 표가 없거나 필수 표 구조가 객체가 아니다.
- Part 4 첫 문제에만 표가 있거나 후속 문제에 같은 표가 반복된다.
- 후속 Part 4 문제에 서로 다른 표가 제공된다.
- 표를 읽는 중 화면 폭, 글자 크기 또는 기기 방향이 바뀐다.
- 표 표시 완료와 45초 타이머 종료 또는 준비 완료 선택이 동시에 발생한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 Part 4 정보를 원격 이미지가 아니라 제공된 구조화 표로 표시해야 한다.
- **FR-002**: 시스템은 표의 title, subtitles, metadata, columns, items 및 notes를 각각
  누락 없이 표시해야 한다.
- **FR-003**: 시스템은 subtitles, metadata, columns, items 및 notes의 원래 배열 순서를
  보존해야 한다.
- **FR-004**: 시스템은 각 행의 셀을 columns 순서와 각 column key를 기준으로 조회해야 하며,
  cells 객체의 속성 순서로 표시해서는 안 된다.
- **FR-005**: 시스템은 어떤 행 상태도 클라이언트에서 임의로 필터링하거나 순서를 변경해서는
  안 된다.
- **FR-006**: 시스템은 null, 누락 값과 빈 문자열을 일관된 대체 기호로 표시해야 한다.
- **FR-007**: 시스템은 숫자 0과 boolean false를 빈 값으로 처리해서는 안 되며 boolean은
  사용자가 이해할 수 있는 일관된 문자열로 표시해야 한다.
- **FR-008**: 시스템은 셀의 표시용 문자열을 날짜, 시간대, 통화 또는 숫자로 다시 해석해
  변경해서는 안 된다.
- **FR-009**: 시스템은 status_note가 있으면 status와 설명을 셀 표시값 밖의 별도 상태
  배지로 표시해야 한다.
- **FR-010**: 시스템은 strike_through가 참인 행의 모든 셀 표시값에 취소선을 적용하되 상태
  배지에는 취소선을 적용해서는 안 된다.
- **FR-011**: 시스템은 알 수 없는 table_type, value_type, status, column key 및 note scope를
  이유로 표나 행을 거부해서는 안 되며 제공된 문자열과 기본 표현을 사용해야 한다.
- **FR-012**: 시스템은 선언 컬럼의 셀이 누락되면 해당 셀을 대체 기호로 표시하고, 나머지
  표 정보는 계속 표시하며 개발 환경에서 계약 위반을 식별 가능하게 기록해야 한다.
- **FR-013**: 시스템은 컬럼에 선언되지 않은 추가 cells 키를 임의 열로 만들지 않아야 하며,
  개발 환경에서 계약 위반을 식별 가능하게 기록해야 한다.
- **FR-014**: 시스템은 Part 4 사전 읽기 화면과 Part 4의 각 문제에서 같은 표 정보를 제공해야

- **FR-018**: 시스템은 45초 만료와 준비 완료 선택 중 먼저 발생한 한 동작으로만 첫 문제의

  가로와 세로 이동으로 전체 확인할 수 있게 해야 한다.
- **FR-020**: 시스템은 큰 글자 설정에서도 헤더, 셀, 상태 배지, 주석과 준비 완료 행동이

- **FR-021**: 시스템은 컬럼 헤더, 행 상태와 빈 값 대체 표시를 색상이나 취소선에만 의존하지

- **FR-022**: 시스템은 Part 4 이미지 확대·재시도 동작을 구조화 표에 요구해서는 안 되며,
  Part 4 이외의 기존 문제 이미지 표시를 변경해서는 안 된다.

### Key Entities

- **Part 4 표 컨텍스트**: Part 4의 세 문제에 공통으로 사용되는 구조화 정보로 표 종류,
  제목, 부제, 메타데이터, 컬럼, 행 및 주석을 포함한다.
- **메타데이터 항목**: 표 본문 밖에서 키, 라벨과 scalar 표시값으로 제공되는 부가 정보다.
- **컬럼 정의**: 동적 key, 사용자용 label 및 확장 가능한 value type으로 행의 표시 순서를
  결정한다.
- **표 행**: 컬럼 key별 scalar 셀 값, 확장 가능한 상태, 선택적 상태 설명과 취소선 여부를
  가진다.
- **표 주석**: 확장 가능한 scope와 표시 문자열로 이루어진 보충 설명이며, scope를 해석할 수
  없어도 텍스트는 표시된다.
- **표시 scalar**: 문자열, 숫자, boolean 또는 null이며 null과 빈 문자열만 빈 값으로
  처리된다.

## Assumptions

- 시험 생성 응답과 문제 상세 응답은 기존 Part 4 이미지 필드 대신 `tableContext` 객체를
  제공하며, 객체 내부 공개 필드는 참조 JSON의 `table_context`와 같은 의미를 가진다.
- 참조 JSON의 `mock_exam_id`, 바깥 title 및 `table_context` 래퍼는 샘플 표와 시험을
  연결하기 위한 자료 구조이며, 화면이 직접 표시하는 표 계약은 내부 `table_context`다.
- Part 4 표는 하나의 시험에서 8~10번 문제에 공통이며, 첫 문제에서 확보한 표를 해당 Part 4
  흐름 동안 재사용할 수 있다.
- status와 scope는 확장 가능한 문자열이며 알려진 값별 별도 비즈니스 동작은 요구되지 않는다.
- public 규격에 없는 내부 행 필드는 이번 클라이언트 변경의 입력으로 제공되지 않는다.
