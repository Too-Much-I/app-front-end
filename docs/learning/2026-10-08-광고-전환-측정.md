- 쟁점: 광고 전환으로 보낼 이벤트
  - 처음 판단: "가입이랑 모의고사 완료를 보내야할 것 같아 모의고사를 실제로 보는지"
  - 바뀐 계기: 없음
  - 최종: 가입, 모의고사 완료 두 개.
- 쟁점: 무엇을 "가입"으로 셀까
  - 처음 판단: "정식 가입으로 해야할 것 같아 .게스트 승격은 그래도 우리 앱을 아는 사람들이니까 새로운 회원가입"
  - 바뀐 계기: 없음. AI 설명 — 게스트 시작을 넣으면 앱만 열어본 사람도 세고, 빼면 게스트로만 쓰는 사람이 안 잡힌다.
  - 최종: 정식 신규 가입만. 게스트 시작·승격은 세지 않는다.
- 쟁점: "모의고사 완료"는 코드의 어느 지점인가
  - 처음 판단: "마지막 답안 제출 시점을 모의고사 완료로 보자 ."
  - 바뀐 계기: 코드 확인 — 기존 `exam_completed`는 사용자가 마지막 답을 끝낸 순간이 아니라 답안 업로드가 전부 서버에
    접수된 순간이다(`use-exam-session-controller.ts:339`). AI 설명 — 앞은 업로드 실패한 시험도 세고, 뒤는 네트워크 탓에
    실제 응시자가 빠진다.
  - 최종: "사용자가 마지막 답을 끝낸 순간 (제출 대기 화면에 들어갈 때)". AI 설명 — Amplitude `exam_completed`는 그대로라
    광고 쪽 수가 업로드 실패분만큼 많게 나온다.
- 쟁점: 광고 이벤트를 어디서 보낼까
  - 처음 판단: "어떤 이벤트가 광고로 나가는지가 숨어요.가 무슨 말이야? 그걸 알면 뭐가 좋아?"
  - 바뀐 계기: AI 설명 — `trackEvent` 안에서 같이 보내면 호출부만 봐서는 광고로 나가는지 모른다. 광고 전환은 플랫폼의
    예산 배분을 바꾸므로 중복 호출·이름 변경이 광고비에 영향을 주는데 앱 에러는 나지 않는다. 그대로 두면 모든 이벤트와
    속성(`exam_abandoned`의 `partNumber` 등)이 Meta로 나가 처리방침과 맞추기 어렵다.
  - 최종: "그럼 별도 함수를 만들어서 두 지점에서 따로 호출하도록 하자."
- 쟁점: 가입이 끝나는 세 길(정상 `signup-flow.ts:433`, 응답 유실 후 재확인 `:342`, 활성화 실패 `:312-314`) 중 무엇을 셀까
  - 처음 판단: "앱에 실제로 들어오지 못한 사람이라면  실제로 가입에서 성공하지 못한 사람?"
  - 바뀐 계기: AI 정정 — "앱에 들어오지 못한"은 부정확한 표현이었다. 활성화 실패는 서버에 계정이 이미 만들어졌고
    (문구 `signup-flow.ts:56` "가입은 완료됐어요…") 기기에서 로그인 상태를 만드는 `onComplete`만 실패한 경우다. 다시
    로그인하면 로그인 흐름을 타므로 가입 이벤트가 다시 나가지 않는다.
  - 최종: "complete 맨앞에서 세는 걸로 하자" — 세 길 모두 센다.
- 쟁점: 개발 빌드의 이벤트가 광고 신호에 섞이는 것
  - 처음 판단: (AI가 먼저 꺼낸 쟁점) Meta 앱이 하나이고 Firebase도 "아마 같은 파이어베이스 프로젝트인 것 같으넫".
  - 바뀐 계기: AI 설명 — Amplitude는 환경별 프로젝트로 나눴지만(`amplitude.ts:8-12`) Meta·Firebase는 하나라 개발 중
    테스트 가입·모의고사가 광고 전환으로 잡힌다. 선택지 A 직접 넣고 항상 켜기 / B 직접 넣고 `EXPO_PUBLIC_ENABLE_*`
    스위치로 production만 / C 값도 EAS 환경변수.
  - 최종: "b야". Firebase도 같은 방식. 프로젝트가 같은지는 확인하지 않았지만 B는 어느 쪽이든 안전하다.
- 쟁점: `mock_exam_completed`를 GA4 주요 이벤트로 어떻게 셀까 (콘솔 설정)
  - 처음 판단: (AI 질문) 이벤트당 한 번은 "얼마나 많이 보는지", 세션당 한 번은 "끝까지 보는 사람이 있는지"에 가깝다.
  - 바뀐 계기: 없음
  - 최종: "주요 이벤트로 세션당 한번으로 설정했어." 기본 값은 두 이벤트 모두 설정 안 함(AI 제안 — 매출이 아니다).
- 쟁점: iOS ATT 팝업을 언제 띄울까
  - 처음 판단: "b에 띄우는게 낫지 않을까? 어차피 회원가입이나 로그인 단계에서는 사용자들이 동의나 여러 가지 절차가 많다는
    걸 이해하니까 빨리 넘어가려고 허용을 해줄 수 있는데 오히려 나중가서 뜨면 더 진지하게 이게 뭔데 지금 허용을 해달라는거지?
    라고 생각을 할 것 같아서."
  - 바뀐 계기: AI 설명 — 이벤트는 보내는 순간 권한이 있어야 IDFA가 실린다(A 안 띄움 / B 첫 실행 / C 가입 후 / D 첫 모의고사
    후). AI 지적 — 근거는 "로그인·가입 단계"인데 B는 "첫 실행 직후"라 위치가 다르다(켜자마자 / 로그인 화면 직후 / SNS 버튼
    직후). 로그인 화면을 거치지 않는 기존 회원은 따로 정해야 한다.
  - 최종: "로그인 화면이 뜬 직후에 하자. 로그인한 사용자는 업데이트 후 앱을 처음 켤 때 물어보자" → 구현은 "첫 화면(로그인
    또는 홈)이 뜬 직후 아직 묻지 않았다면"으로 묶는다(AI 제안 — iOS가 물었는지를 기억한다). 설치 이벤트는 IDFA 없이 나간다.
- 쟁점: ATT 설명 문구
  - 처음 판단: "사용자 분들이 어떤 경로로 토선생을 발견했는지를 확인하고 더 나은 서비스를 만들기 위한 데이터 수집에 활용이
    돼요 이렇게할까? 데이터를 수집한다고 하면 더 안하려나?" → "관심 있을 만한 소식을 전해드리는 데 사용돼요." / "이렇게
    정직하게 쓰면 아무도 안해줄 것 같은데"
  - 바뀐 계기: AI 설명 — ATT는 광고 추적 전용 권한이라 실제 용도와 다른 설명("더 나은 서비스", "소식")은 반려 사유가 될 수
    있다. 시스템 팝업 제목이 "추적을 허용하겠습니까"로 고정이라 허용률은 문구보다 시점에 달렸고, 거부한 사람도
    SKAdNetwork로 집계된다.
  - 최종: "토선생을 알게 된 경로를 확인하고, 더 관련 있는 광고를 보여드리는 데 사용돼요."
- 쟁점: Meta 광고 측정을 계속 둘까
  - 처음 판단: Meta·Google 둘 다 붙인다(처음 요청 목록). Meta 앱 활성화 이벤트까지 에뮬레이터에서 확인했다.
  - 바뀐 계기: 사업 결정 — Meta 광고 중단.
  - 최종: "메타 광고를 안하는 걸로 하고 결정이 됐어. 너무 cpc가 안나와서 sdk 설치한 거 지워" — 위 쟁점들의 Meta 관련 판단
    (표준·맞춤 이벤트, Meta 허용 알림)은 더 이상 적용되지 않는다.
- 쟁점: Meta를 뺀 뒤에도 ATT를 할까
  - 처음 판단: 위 ATT 쟁점의 결정(로그인 화면 직후).
  - 바뀐 계기: 사용자 질문 "IDFA가 정확히 어떤 용도로 쓰는 거였지?" → AI 설명 — 광고 클릭과 전환을 같은 기기로 잇는 열쇠다.
    없으면 노출·클릭·비용, 캠페인별 설치 수(SKAdNetwork, 늦고 묶음), GA4 전체 횟수, Google 추정 전환은 남고 광고그룹·키워드별
    귀속, 설치 후 전환의 정확한 귀속, iOS 잠재고객은 사라진다. Android는 영향이 없다.
  - 최종: "ios 광고 비중이 더 큰 건 아닌데, 허용해주는 사람들이 많이 없을 것 같아서 저 정보 자체가 주는 데이터의 정확성의
    기대치가 너무 낮아 저것도 없애는 걸로 하자."
- 쟁점: 결제 라이브러리를 무엇으로, 언제 넣을까
  - 처음 판단: "넣어야 상품 등록이 가능ㅇ하면 넣어야지" (AI가 "결제 라이브러리가 든 빌드가 필요하다"고 설명한 뒤)
  - 바뀐 계기: AI 정정 — Play 도움말상 조건은 테스트 트랙 이상 업로드 + BILLING 권한이고 라이브러리 자체는 아니다(D안 권한만).
    사용자 질문 "애초에 이용권 화면만 있으면 되고 그걸 선택했을 때 적절한 링크로 연결만 해주면 되는 거 아닌가?" → AI 설명 —
    링크가 아니라 라이브러리로 스토어 결제창을 띄우고 영수증을 받아 서버에 넘기고 처리 완료를 알린다(Google은 3일 안에
    안 하면 자동 환불). → "그럼 expo-iap이 제일 좋은 거네 저걸로 앱스토어랑 구글 플레이 스토어를 둘 다 쓸 수 있는 거 아냐?"
    → AI 지적 — 두 스토어 지원은 react-native-iap도 같다. 차이는 Expo 모듈인지 Nitro 모듈인지다.
  - 최종: "엑스포 모듈로 통일하자. 그리고 지금 그냥 expo-iap까지 넣어도 결국 sdk만 설치하고 코드 변경은 없는 거자나 그럼
    그렇게 해도 될 것 같은데" — 상품은 "몇일권", 검증은 "서버에서 한대".
