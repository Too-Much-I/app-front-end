# 학습 기록

작업 방식 3단계(구현 전 예상)와 5단계(시나리오 지도·흐름 설명)를 남기는 곳이다.
배경: [결정 기록](../decisions/2026-09-30-뼈대-대신-구현-전-예상.md), [작업 방식](../how-we-work.md).

- 파일: `YYYY-MM-DD-<작업>.md`, 작업(PR) 하나에 하나.
- 동작이 바뀌는 PR은 학습 기록이 있어야 머지된다. CI(`pnpm check:learning`)가 PR에서 **새로 추가된**
  이 폴더의 파일 중 하나라도 "구현 전 예상", "내가 찾은 것", "흐름 설명", "예상과 달라진 것"이 모두
  채워져 있는지 본다. 주석과 빈 템플릿 항목(`- 예상:`)만 있으면 비어 있는 것으로 본다.
  제목 표기는 너그럽게 받는다: `#` 개수, `#` 뒤 공백, 제목 안 띄어쓰기(`흐름설명`)를 가리지 않는다.
  이전 작업의 기록을 수정한 것은 인정하지 않는다. 여러 PR에 걸친 작업은 PR마다 새 기록을 쓴다.
- CI는 내용이 맞는지 검증하지 못한다. 칸을 채우는 것 자체가 목적이 되면 기록의 의미가 없다.
- 사람이 쓰는 섹션은 AI가 대신 쓰거나 다듬지 않는다. 틀린 예상도 고치지 않고 남긴다.
- "동작 변화 없음"으로 선언한 작업은 파일을 만들지 않고 PR 본문에 `동작 변화 없음: <사유>`를 적는다.
  `<사유>` 자리표시를 그대로 두면 선언으로 보지 않는다.
  문서만 바꾼 PR은 선언 없이 통과한다.

## 형식

```markdown
# <작업>

## 구현 전 예상
<!-- 사람이 구현 전에 쓴다. 2분 분량. "모르겠다"도 기록이다. -->
- 예상:
- 이유:
- 반증:

## 시나리오 지도
<!-- AI가 PR 후에 쓴다. 시작 조건·찾을 질문·지나가는 함수(파일:줄)만. 답과 힌트는 쓰지 않는다. -->

## 내가 찾은 것
<!-- 사람이 쓴다. 시나리오마다 확인 전 예상 한 줄 → 코드에서 확인한 결과. -->

## 흐름 설명
<!-- 사람이 자기 말로 쓴다. 이 변경이 어떻게 동작하는가. -->

## 예상과 달라진 것
<!-- 사람이 쓴다. 구현 전 예상·시나리오 예상과 실제 결과의 차이. CodeRabbit이 찾은 것과도 비교한다. -->
```
