# 답변 익히기 이관 기록

## 설계 논의

사용자 최초 판단:

> app-front-end 레포에 있는 가장 최신의 코드를 pull 해오고, 여기서 새로운 브랜치를 파서 지금 작업했던 코드를 기존의 코드를 최대한 건드리지 않는 선에서 새로운 학습 기능을 추가한 브랜치로 만들어주면 됨

공개 저장소 콘텐츠 범위를 물은 뒤 사용자 판단:

> 데이터들은 s3,mongoDB에 저장할거고, 이걸 백엔드와 통신하면서 주고 받게 할거야. 그래서 이런 데이터를 api를 통해 주고 받는다는 것 까지 다 생각해서 어떤 api를 날리면 백엔드에서 어떤 걸 보내주고 이런것까지 전부 고려해서 만들고, 프론트엔드가 보았을때 바로 이해할수 있는 문서까지 만들어주면 됨

AI 제안: 프리뷰 진입점을 복사하지 않고 학습 모듈/탭만 합류한다. 기존 로그인 인증과 React Query를 사용하고 서버 데이터는 검증/매핑 후 화면에 전달한다.
최종 작업 범위는 최신 앱 + 학습 기능 + API 계약/가상 응답/테스트를 별도 브랜치로 전달하는 것이다. 실제 AWS 배포는 이번 브랜치에 포함하지 않는다.
다룬 실패 범위: 문항/등급/버전 불일치, 서명 URL 만료, 업로드 유실/실패, 늦은 STT/재생 이벤트, 중복 제출, 완료 저장 실패.
다루지 않은 범위: 서버 구현/계정별 실서비스 종단 검증, 모델 정확도, 전체 콘텐츠 업로드.
반증: 사용자의 별도 작성은 아직 받지 않았다. AI가 대신 작성하지 않는다.

## 시나리오 지도

1. Q8을 IH로 열어 둔 중에 서버의 답안 버전이 바뀐다. 제출 시 어떤 버전으로 처리되는가? `getLearningUnit` → `useLearningSubmission` → `createLearningSubmission`.
2. S3 PUT은 성공했으나 휴대폰에서 응답을 받지 못했다. 다시 제출하면 어떤 ID/오디오를 사용하는가? `uploadLearningSubmission` → `useLearningSubmission`.
3. 녹음 중 앱을 나갔다가 다른 계정으로 돌아온다. 녹음 파일과 조회 캐시는 어떻게 되는가? `LearningLessonSession` → 기존 auth runtime의 cache clear.

## 내가 찾은 것

사용자의 코드 추적 결과는 아직 받지 않았다. 인수인계 브랜치에 테스트 결과를 별도로 기록하며 사용자 검증으로 대체하지 않는다.

## 흐름 설명

사용자의 설명은 아직 받지 않았다. 개발자용 실행/연동 설명은 `docs/answer-learning-handoff.md`에 있다.

## 설계와 달라진 것

AI 구현 사항: 로컬 JSON/asset require를 API 조회로, 로컬 완료 저장을 서버 upsert로 변경했다.
녹음 전송은 백엔드 중계 대신 백엔드 발급 S3 URL로 전송한 뒤 confirm하는 계약을 사용한다.
이 문서는 사람의 리뷰가 완료되었다는 기록이 아니며 자동 머지 승인이 아니다.

## 2026-10-13 기존 브랜치 통합 후속 작업

사용자 요청: “거기서 작업을 계속해서 머지만 하면 앱에 적용이 가능할 정도로 코드를 짜줘. 절대 메인에 있는 코드는 건들면 안됨.”

AI 구현: 기존 feature 브랜치에서만 수정한다. 계정 통합 완료 시 서버 캐시를 갱신하고, 진행 중인 학습 문항·오디오·버전은 세션 진입 시점의 한 묶음으로 유지한다. 재조회로 녹음 화면을 분리하거나 초기화하지 않는다. API 경로와 DTO는 유지한다. 실제 AWS 적용/새 네이티브 배포와 사람 리뷰는 완료했다고 표시하지 않는다. 사용자 반증·코드 추적 답변을 대신 작성하지 않는다.

## 2026-10-13 실제 앱 로컬 실행

사용자 요청: “아니 로그인부터 이런것까지 다 테스트 못해?”, “aws에서 못찾아? 시크릿 메니저에 없나”, “파이어베이스 켰어”.

AI 확인: AWS의 Firebase 시크릿은 서버 서비스 계정이다. 사용자가 열어준 Firebase 콘솔에서 앱 설정 파일을 내려받아 Git 제외 로컬 설정에 연결했다. 일반 앱은 빌드에 성공했지만 iOS 27에서 `UIScene lifecycle is required`로 시작하지 못했다.

AI 구현: 일반 앱에 Scene 시작 플러그인을 추가하고 Firebase 초기화·Expo launch hook·OAuth URL 복귀를 보존했다. 샘플 인증으로 로그인 성공을 대체하지 않는다. 사용자 계정의 실제 인증과 테스트 서버 학습 API 배포는 이 빌드 검사로 완료 처리하지 않는다. 사용자의 반증·추적 답변은 아직 받지 않았다.

## 2026-10-13 최종 프론트 전달

사용자 확인: “잘 되는거 확인했어.” (별도 아이폰 테스트 앱 설치 후)

사용자 요청: “프론트 메인 레포를 보고, 코드를 기존의 코드를 최소한으로 건들면서 내가 지금 짜놓은 코드와 기능들이 작동하도록 전에 만들어둔 학습 브랜치에 올리고” 기능 설명도 작성해 달라고 했다.

AI 작업 범위: 최신 원격 main의 변경을 기존 feature 브랜치에 반영하고, 실제 테스트에 사용한 미커밋 변경을 검증·업로드한다. main 브랜치와 별도 원본 checkout의 작업은 수정하지 않는다. 기존 앱 설정 본문을 유지하는 구성 함수로 config diff를 줄인다. 기능·파일별 변경 이유·테스트/운영 빌드 환경·서버 책임·검증의 한계를 인수인계 문서로 정리한다.

검증 경계: 사용자 확인은 아이폰 테스트 사용에 대한 확인이다. 모든 파트/권한 거절/계정 병합/Apple 로그인/푸시/Android 및 운영 서버 수용 검증이 끝났다는 뜻으로 확대하지 않는다. 자동 검사는 별도로 기록한다. 사용자에게 개발 지식이나 코드 추적 설명을 요구하지 않고 이번 전달을 진행하되, 사람의 코드 리뷰를 대신 작성하지 않는다.
