# Android 마이크 권한 복구(expo-image-picker 설정)

## 설계 논의
<!-- AI가 1·2단계 대화를 모아 쓰고 사람이 확인한다. 사람의 판단은 원문 인용, AI 발언은 "AI 제안"으로 표시. -->
- 쟁점: 마이크 테스트에서 처음부터 "앱 설정에서 권한 허용"이 뜨는 원인
  - 처음 판단: 사용자 "왜 마이크 테스트 시작하려고 하면 마이크 테스트 하려고 하면 앱 설정에서 권한 허용이 뜨는데 이게 뭐야>" → AI가 `denied` + `canAskAgain: false`일 때의 문구라며 예전에 거부한 기기일 수 있다고 설명
  - 바뀐 계기: 사용자 "그게 왜 바꼈어?" → AI가 마이크 코드는 9월 이후 그대로이고, #109에서 넣은 `expo-image-picker`의 `"microphonePermission": false`가 "이 플러그인이 마이크를 요청하지 않음"이 아니라 "어떤 패키지도 RECORD_AUDIO를 넣지 못하게 매니페스트에서 지움"(`withBlockedPermissions`, `tools:node="remove"`)이라는 것을 확인. 로컬 `android/app/src/main/AndroidManifest.xml`에 remove 줄이 있음. Android의 모든 녹음(모의고사·챌린지·재답변·학습)이 막히고, 3.1.0 Android 빌드도 같다. iOS는 같은 값이 `NSMicrophoneUsageDescription`을 지우는 동작이라 빌드 18에서 확인 필요
  - 최종: AI 제안 — `"microphonePermission": false` 한 줄만 지운다(카메라 `false`는 의도한 차단이라 둔다). 경로는 (가) develop fix PR → 출시 PR 다시 / (나) main 핫픽스 → 역반영 중 (가) 추천. 사용자 "(가)로 바로 올려"
- 다룬 실패 범위: Android 매니페스트에서 RECORD_AUDIO가 지워져 권한 팝업 없이 영구 거부되는 경우, iOS 마이크 사용 문구가 지워질 수 있는 경우
- 다루지 않은 것: iOS 빌드 18 Info.plist 실제 확인(빌드 결과물에서 따로 본다), 다른 플러그인의 `false` 권한 설정 점검
