## 흐름 설명
마이페이지에서 달의 이력을 조회하는 것은 해당 페이지에서 매번 발생한다. 현재 달은 무조건 조회를 하고 보고 있던 이전 달이 있다면 해당 달도 조회를 한다.캐시를 유지 하는 대신 매번 새로 조회를 하는 건 다른 기기에서 문제를 푼 사용자의 업데이트를 현 화면에 반영하기 위함이다. 닉네임은 바뀌지 않는 값이므로 한 번 fetch를 해두면 계속 쓰지만 계정 로그아웃 후에 새로운 로그인을 하는 과정에서는 변경될 수 있으므로 로그아웃을 하면 캐시를 비우고 코디네이터 상태가 로그아웃으로 바뀌면 네비게이터가 변경되면서 아예 마이페이지 화면도 날라가서 훅을 다시 호출해야하는 상태가된다. 이때 닉네임을 다시 받아오게 된다. 이전 달로의 변경은 서버에서 받아오는 데이터가 있냐 없냐에 따라 달라진다. 해당 데이터를 못 받아오고 캐시도 없는 경우라면 달력 표시를 안하지만 이전 달 버튼을 눌러서 이전 달 데이터를  못 받는 경우 failure 상태를 바꿔 팝업을 띄우는 걸로 대신한다. 문제를 푼 갯수는 마이페이지에도 있으나 해당 날짜를 클릭해서 스테이지에 들어가는 경우 파라미터로 넘기지는 않는다. 그 화면에서 조회해야할 데이터이기 떄문

## 설계와 달라진 것
기존에는 이력을 조회할 수 없는 경우 달력을 렌더링하지 않는 방안을 생각했으나 이전 달력으로 넘기던 중에 조회에 실패해서 아예 달력이 사라지는 것은 사용자가 당황스러울 것이라고 생각해서 조회에 실패했다는 팝업을 띄우는 것으로 대신했다.

- AI 조정(2026-10-11 사용자 요청으로 추가): 설계 논의에는 닉네임을 `/users/me`에서 받는다는 것만 있었다. 기존 401 재발급 재시도(`apiFetchWithAuthRetry`)는 Learning Core 주소에만 붙어 있어, 같은 재발급 경로를 Identity 주소로도 쓰도록 공용 API 클라이언트에 `identityFetchWithAuthRetry`를 추가했다(`src/lib/api/authenticated-client.ts`). 세션 복구의 `getCurrentAccount`처럼 토큰을 직접 받아 호출하지 않은 이유는 마이페이지가 세션 상태를 건드리지 않고 다른 조회와 같은 재발급 규칙을 따르게 하려는 것이다.
