- 쟁점: Google 기억을 언제 지울까
  - 처음 판단: "내가 로그인한 수단만 알고 계정을 모르는 상태 그리고 계정을 알더라도 다른 계정을 잘못 누를 수 있다는 걸 고려하면 계정을 한번 선택하고 나서 바꿀 수 있는 기회를 줘야한다.는 상황을 고려했을 때 구글 sdk에서 취소하는 건 필요한데 언제 취소할지가 중요하잖아"
  - 바뀐 계기: AI 설명 — 계정을 바꿔야 하는 상황 6개와 A·B·C가 각각 놓치는 상황. 기록에 없던 두 길: 계정 찾기에서 Google을 누르면 `cancelLogin`을 거치지 않아 같은 계정으로 다시 들어감(`auth-coordinator.ts:629`, `:658`), 가입 중 강제 종료. B는 로그아웃 없이 로그인 화면에 온 사용자에게도 계정 선택을 띄움.
  - 바뀐 계기: AI 제안 — 세션을 지울 때 Google도 지우는 방법. → "근데 세션을 지우는 경우에 로그아웃을 자동으로 한다고 하더라도 같은 사람이 화면에 들어오는데 치르는 비용이 달라지는게 아니라 명목상의 사유만 달라지는 거라 치르는 비용은 동일하잖아."
  - 바뀐 계기: 리프레시 토큰 수명 — 명세 예시 14일, 회전 시 연장 여부는 명세에 없음(AI 설명) → 서버 확인 "14일 다시 받는 거라는데 그럼 로그인 화면에서 계정 한 번 더 선택하게 해도 괜찮을 것 같아"
  - 바뀐 계기: "구글 버튼을 클릭했을 때 애초에 선택창을 안띄우고 계정 A(로그인한 계정)으로 로그인하게 했으면 이런 일이 안생겼다는 거야. 물론 회원가입을 새로하고 싶을 수도 있지만" → AI 설명 — 세션 만료 때는 지금도 A가 남아 바로 들어간다. A가 사라지는 건 직접 로그아웃·탈퇴·재설치뿐이다. 로그아웃 때 A를 남겨도 SDK는 마지막으로 고른 계정을 기억하므로 B를 고른 뒤에는 A로 되돌릴 수 없다.
  - 최종: "아 직접 로그아웃을 선택한 경우에는 지워지는구나 그렇네 근데 B의 방식으로 하면 로그아웃한 사용자뿐만이 아니라 그냥 토큰이 지워진 사용자도 계정 선택을 해야하네. 음...로그아웃을 본인이 직접하는 경우는 거의 없을 것 같은데 보통은 그냥 안쓰면 안쓰지 로그아웃을 적극적으로 하지는 않으니까? 근데 그렇다고 해도 다른 계정을 선택못할 떄 계속 회원가입 창으로만 가게 되는 건 문제가 있어. A로 하고 findAccountFromSignup에도 지우는 걸 넣을까?" → "A로 하게 되면 기본적인 정상 만료 토큰으로 인한 로그인 화면에서는 사용자가 바로 계정 선택없이 수단만 확인해서 로그인을 다시 할 수 있잖아"
- 쟁점: 무엇을 지울까
  - 처음 판단: (AI 설명 — 지금 지우는 함수 `firebase.signOut()`은 Firebase와 Google을 함께 지운다. 계정 찾기는 넘어오자마자 Firebase에 전화번호로 로그인하므로(`account-recovery-flow.ts:419`, `:586`) 늦게 끝난 Firebase `signOut`이 그 사용자를 내보낼 수 있다.)
  - 최종: "구글 기억만 지워서 파이어베이스랑의 경합을 피하자."
- 쟁점: 지우기가 끝나기 전에 다시 누르면
  - 처음 판단: (AI 설명 — 지우기는 비동기라 취소 직후, 또는 계정 찾기의 "Google로 로그인" 직후 `signIn()`이 먼저 시작될 수 있다.)
  - 최종: "다시 누를 떄의 경합은 signInGoogle을 기다리게 하자."
- 다룬 실패 범위: 가입 화면 취소, 병합 화면 취소, 진행 중·오류 화면 취소(모두 `cancelLogin`), 가입 중 계정 찾기로 넘어간 뒤 Google 로그인(`findAccountFromSignup`), 지우기 직후 다시 누름(`signInGoogle`이 기다림), 계정 찾기의 Firebase 전화번호 로그인과의 경합(Google만 지움).
- 다루지 않은 것: 가입 중 강제 종료("강제 종료 한바퀴 도는 건 감수하도록 하고"), 이미 회원인 다른 계정을 잘못 고른 경우(로그아웃이 이미 지움), iOS에서 선택 창을 건너뛰는지, Kakao·Apple, iOS 재설치 뒤 기억이 남는지.
- 반증:모르겠다.
