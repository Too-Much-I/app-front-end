  - 최종: "(나)로 하자" → 기존 회원도 한 번 띄우고, 새 회원은 지금처럼 가입 후 첫 홈에서 띄운다. 순서(적용 결과 → 유료 전환 → 친구 초대)와 뜨는 순간 기록하는 규칙은 그대로
- 쟁점: "한 번"을 무엇 기준으로 세나
  - 처음 판단: AI가 (가) 기기 기준(서버 일 없음, 재설치·기기 변경 때 다시 뜸) / (나) 계정 기준(서버에 본 기록 API 필요)을 냄
  - 바뀐 계기: —
  - 최종: "뒤의 논의는 (가)로 하자" → 기기 기준
- 쟁점: Guest도 포함하나
  - 처음 판단: AI가 Guest에게 추천 코드가 발급되는지 모른다며 물음(D11 때와 같은 잘못된 질문)
  - 바뀐 계기: 사용자 "게스트는 홈에서 팝업을 누를 방법이 없어"
  - 최종: Guest는 따로 다루지 않는다
- 쟁점: 유료 전환 안내에서 "이용권 보러 가기"를 누르면 친구 초대 팝업은 (시나리오 3에서 나옴)
  - 처음 판단: "PaidTransitionNotice는 화면 종속적이라 사라져"
  - 바뀐 계기: AI가 `PassPurchase`는 루트 스택에 `MainTabs` 위로 쌓여 HomeScreen이 언마운트되지 않고, `dismiss()` 뒤 `notice`가 `referral-invite`가 되어 결제 화면 위에 친구 초대 모달이 겹쳐 뜨고 `seen`이 기록된다고 알림(기기 미확인). D11에서는 유료 전환 안내를 받는 2.x 회원이 `done`이라 없던 조합이고, 첫 구현 리뷰에서 놓침. AI가 (가) 홈이 보일 때만 홈 팝업을 고름(`useIsFocused`) / (나) 이번 실행에서는 친구 초대를 건너뛰고 다음 실행에 띄움 / (다) 그대로 둠을 냄
  - 최종: "(나)로 하자" → "이용권 보러 가기"를 누르면 친구 초대를 이번 실행에서는 띄우지도 기록하지도 않는다. 다음 실행에 뜬다
- 다룬 실패 범위: 업데이트를 받은 기존 회원(기록 없음 → 한 번 뜸), 재설치 뒤 로그인(기기 기준이라 다시 한 번 뜸), 이미 본 기기(`seen`, 다시 안 뜸), 같은 기기에서 계정을 바꾼 회원(기기 기준이라 다시 안 뜸)
- 다루지 않은 것: 알림 권한 안내(`PushPermissionPrompt`)와 홈 팝업이 동시에 뜨는 문제(홈 팝업 순서 밖에 있음, 이번 결정 대상 아님), 재설치 직후 알림 허용 뒤 화면이 빠르게 지나간 현상(Android, 원인 미확인, 녹화 대기), 계정 기준 기록
