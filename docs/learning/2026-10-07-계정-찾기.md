## 흐름 설명
현재 구현에서는 3가지가 변경됐다. 
- 사용자가 마지막 로그인 수단을 기억할 수 있게 저장하는것. 
- 로그인 화면에서 계정 찾기로 넘어오는 흐름. 
- 전화 번호 인증까지 하고 conflict가 나서 다시 계정 찾기를 하는 부분 

첫번째꺼부터 설명을 하면 지금 로그인 수단은 완전히 사용자의 가입과 로그인이 끝나고 실제 서버의 멤버 토큰을 받아서 해당 토큰을 active를 시키고 나서 로그인 수단을 저장하고 있다. 가입을 완료한 것과 로그인을 완료한 것에는 차이가 있으므로 중간 과정에서 이탈자의 로그인 수단을 클라이언트 단에서 저장하지 않게 하기 위함이다. 저장은 또한 secureStore에 해서 ios같은 경우에는 앱을 지우더라도 보장을 하고 있고 키를 분리해 다른 저장 항목과 엮이지 않도록 하였다. 잘못 덮어써지지 않도록. 

두번째로 로그인 화면에서 계정 찾기로 넘어오는 경우에는 전화 번호 인증을 먼저 해야한다. 
우리가 계정을 복구하는 과정에선는 해당 계정 복구에 대한 복구키가 필요한데 화면 진입시 해당 키는 바로 발급을 받는다. 만약 해당 키가 번호 인증 전에 만료가 되어 사용자가 여러번 같은 행동을 반복하는 어려움을 겪지 않게 하기 위해서 키의 복구는 1분 타이머를 설정해 만료 시간이 1분 미만으로 남아있는 경우에 다시 발급을 받고 화면이 백그라운드나 인액티브 상태에 들어간 경우에도 다시 만료 시간을 확인해서 발급을 받을 수 있도록 하고 있다. 번호 인증이 끝나면 받은 crdential을 사용해 로그인한 수단을 확인시켜준다. 

세번째로는 회원가입 단계에서 번호 인증시에 막히는경우인데 이미 계정이 있는 번호인 경우 사용자에게 기존 계정을 찾을 수 있는 방법을 안내하고 이 경우에는 사용자가 다시 전화 번호 인증을 반복하지 않도록 무조건적으로 prepare api를 호출해서 계정 찾기로 넘어가더라도 다시 전화 인증을 하지 않을 수 있도록 했다.
