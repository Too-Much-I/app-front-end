## 내가 찾은 것
- 시나리오 1: 강제 화면이 뜨고 나서 앱에 다시 돌아오고 나면 저 check가 돌텐데, 지금 상태가 required이므로 다시 return을 바로 해준다. required를 가지고 있으니까 그대로 앱 업데이트 강제 화면을 보여주게 되낟.
  - 질문 1: 질문1에 대한 답은 비행기 모드에서 들어왔을 때 앱 버전 확인 요청은 다시 나가지 않아 .지금 상태를 required로 메모리에 들고 있기 때문에 그냥 체크 함수에서 리턴을 해줘버리거든.
  - 앱을 완전히 종료하고 비행기 모드에서 새로 실행하면(AI 추가 질문): 그러면 네트워크 연결 에러 팝업이 뜨겠지 .
- 시나리오 2: 1. check는 버려지지 않는다. check는 콜백 함수라 해당 함수를 기억하고 플랫폼이 변경됐을 때랑 transition이 함수가 변경됐을 때만 버려지는데, 현재 버려질 조건이 없다. 네트워크로 인한 상태가 변경된다고 해서 2. 1초에 한번씩 재시도를 하고 있다. RETRY_DELAY_MS는 1초로 하고 MAX_ATTEMPTS는 3으로 하면 2번까지 재시도를 한다. 처음 시도 후 캐치문으로 빠지면 아직 최대 시도이상이 아니므로 1초 기다렸다가 루프가 돌고 그 다음에도 실패를 하면 1초를 기다리므로 다시 요청을 보내고 그 다음에 1초를 기다리고 그 다음에는 시도가 맥스를 넘겨서 connection-failed를 돌려주므로 총 3초를 기다리게 된다. 3. 마지막 상태는 connection-failed로 변경돼서 네트 워크 연결 오류 팝업이 나온다.
  - (AI 지적 뒤) 계속 기다릴 것 같은데 난 1의 질문이 이해가 안가는게 그럼 check 안에서 앱 업데이트 필요조건 함수를 기다리고 있는 상태에서 앱 상태가 변경되면 위에 있는 조건문으로 다시 실행이 된다는 거야? 함수 스택에 쌓여서 기다리는 건 변경이 안되지 않나?아 그러네 끝난 후에는 이미 넘겨서 도달을 안하는 구나 1부터 시작을 했으니까.
  - 아 무슨 말인지 알겠어 첫번째 실행은 await으로 멈춰있고 두번째 실행은 조건문에서 이미 checking으로 변경되어있으니까 그냥 리턴 당해서 첫번째 실행이 실행돼.
  - (AI 설명, 사용자 요청으로 추가) 처음 헷갈린 지점: "함수가 다시 실행된다"를 멈춰 있던 실행이 위로 되돌아가는 것으로 읽었다. 실제로는 같은 함수의 **별개 실행이 하나 더** 시작된다. 멈춘 실행은 `await` 자리에서 그대로 기다린다.

    ```
    [첫 번째 check 실행]                     [두 번째 check 실행]
     조건문 통과
     transition(checking)
     await getAppUpdateRequirement ... (멈춰서 기다리는 중)
            │                              ← 백그라운드에서 돌아옴, AppState 리스너가 check()를 또 부름
            │                                조건문부터 새로 시작
            │                                stateRef.current.status 읽기 → checking → return
            ▼
     기다리던 결과가 오면 그 자리에서 이어서 진행 → transition(connection-failed)
    ```
- 시나리오 3: 로그인한 상태에서 오프라인으로 새로 시작을 한다 함음. 앱을 완전히 종료하고 실행을 하는 것을 의미하고 현재 상태에서는 앱 버전 확인 상태를 메모리에 들고 있으므로 idle에서 시작을 해서 다시 앱 업데이트 여부를 서버에 물어보는 단계가 필요하다.서버에 물어보는 과정에서 현재 비행기 모드로 인해 재시도 2회가 실패할 것이고, 재시도가 실패하면 connection-failed 화면이 뜨게 된다. 네트워크 연결이 실패했다는모달이 뜨고 그걸 끄게 되면 홈화면이 보여야한다. 로그인한 상태라고 하면 이미 인증은 완료가 된 상태인데 현재는 비행기 모드로 들어가고 있으므로 네트워크연결이 안되ㅓ 저장된 세션이 실패했다는상태로 변경이 된다. 인증 에러 화면이 뜬다. 다시 시도하기를 누르면 인증은 다시 뜨겠지만 버전 확인은 같이 돌지 않는다. 지금 현재는 앱 버전 확인이 앱  활성화로 도므로 인증을 재시도하는 건 트리거가 안된다.
  - (AI 지적 뒤) 그니까 원래 로그인에 성공했고 잠깐만 앱버전이 실패했던 거라면 홈이 보여야지 근데 지금은 아예 둘 다 연결이 안되는 거니까 인증 에러 화면이 뜨는 거고
  - 순서: 그럼 백그라운드에서 인증이 돌고 재시도를 안하니까 인증 복구 화면이 먼저 보이게 되는건가? 그러고 나서 좀 있다가 네트워크 모달은 그냥 위에 뜨는 거고?

## 흐름 설명
앱은 기본적으로 체크가 한번 돌고 앱 상태가 변경됐을 때 체크 함수가 돌도록 이벤트 리스너를 등록해놔. 앱으로 돌아왔을 때 check함수가 돌아가고 check함수 내부에서는 현재 상태가 required나 checking 중이거나 이런 경우에는 얼리리터을 하고,  앱 업데이트 체크 상태를 checking상태로 바꾸고 connection-failed인지 아닌지에 따라서 안내를 보여줄지 말지를 먼저 결정한다. 그리고 getAppUpdated를 불러서 업데이트를 해야하는 미니멈 버전을 받고 다시 상태를 바꿔 지금 여기서 required가 나오면 (앱 업데이트가 필요하다는 의미니까. ) 강제 업데이트 화면에 머물게 된다.
(AI 지적 뒤 정정) 아 그렇네 미니멈 버전을 받는게 아니라 결국 앱버전을 파싱하는 함수를 불러서 필요한지 아닌지에 대한 결과를 돌려주고 있구나 그래서 상수에 키 값으로 결과를 쓸 수 있는거고

## 설계와 달라진 것
최초 설계시에 이미 "업데이트"가 필요해요라고 받은 경우에는 네트워크 오류등으로 상태가 변경되더라도 그 화면을 띄우는 것으로 했다. 그런데 앱 실행을 다시 한다는건 사용자의 환경이 바뀌었다는 의미이고, 서버가 지원하는 최소 지원 버전등에도 변경이 생겼을 수 있으므로 일단 앱이 켜져있는 동안만 유지를 하는 것으로 수정했다.
