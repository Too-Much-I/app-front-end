# 학습 화면 흐름 (파트 → 퍼즐 → 쉐도잉 → 채점)

## 설계 논의

- 쟁점: 파트 화면에 "이어서 하기"를 둘지
  - 처음 판단: AI 제안 B안(진행률 + 이어서 하기 카드)을 골라 "그 B 시안을 발전시킬 건데 … 저기에 이어서 하기 버튼을 위에 그려줘", 이후 "이거만 공통적으로 빼서 CTA 박스는 간단히 하는거롤하자"(진행 줄 제거)
  - 바뀐 계기: "저 이어서 연습하기는 뭐야? 서버에서 받을 수 있어?" → AI가 Swagger를 확인. 마지막 학습을 돌려주는 API가 없고 문항별 `completed`만 있으며, Part 2~5는 채점까지 끝나야 완료로 저장된다
  - 최종: "이어서 하기를 뺴고 어떤 파트부터 시작할까요?로 시작해서 하는 건 어떨가" → 상자 삭제, 제목 + 파트 목록
- 쟁점: 파트 화면 배경과 캐릭터
  - 처음 판단: 참고 이미지 + 토끼 그림, "고양이랑 새 버전을 그리고 … 꽃이나 바다나 간단한 이미지를 비슷한 톤으로 배경을 만들어줘"
  - 바뀐 계기: AI가 B2에 임의로 인사 문구를 넣어 "왜 새로 추가된 거에는오늘은 어디부터 할까요?가 붙었어? 그냥 저 캐릭터들 다 뺴도 될 것 같기도 해" → 1번(캐릭터·문구 모두 빼기). AI가 SVG로 그린 배경이 "2번째 3번째 시안이 은근 비슷해" → 사용자가 그림 3장을 직접 가져옴
  - 최종: "저 파트B의 배경을 각 난이도별 색상에 맞는 이미지로 매칭해서 넣어줘", 이번 구현에서 "3 배경그림은 난이도별로 이미지가 달라지게 지금처럼 해야지". Easy 바다, Medium 해돋이, Hard 꽃 언덕(색 매칭은 AI 제안)
- 쟁점: 파트 아이콘과 버튼 모양
  - 처음 판단: P1·P2 글자 → AI가 세 방향 제시, "1으로 해봐"(Feather 아이콘)
  - 바뀐 계기: 화면을 보고 "저 뒤에 있는 배경을 없애고 아이콘만 남겨보면 또 어떨까?", "그리고 재생 버튼에 그림자가 있는 것도 별로야"
  - 최종: 아이콘 선만, 바탕·그림자 없음
- 쟁점: 이번 구현 범위
  - 처음 판단: "B로 파트 화면을 만들고 2번에 2 그리고 3번에 2 이렇게 화면만 구현해서 연결되는 흐름만 확인할 수 있게 해줘"
  - 바뀐 계기: AI가 ① 퍼즐 자리를 물음 → "아 퍼즐도 필요하지", 범위는 "(나)"(실제 동작까지)
  - 최종: 파트(B) → ① 퍼즐 → ② S2 → ③ G2
- 쟁점: 단계 나누기
  - 처음 판단: "2번은 화면별로 등록하게 해주고"
  - 바뀐 계기: 없음
  - 최종: 단계마다 route
- 쟁점: 데이터
  - 처음 판단: "4은 스웨거를 기반으로 목데이터를 넣어줘"
  - 바뀐 계기: 없음
  - 최종: Swagger 응답 형태 목데이터. `chunks`는 합의한 `{from, to}` 형태로 목데이터에만(AI 제안)
- 쟁점: 파트를 누르면 어느 세트로 들어갈지
  - 처음 판단: "지금 파트별로 여러 문제가 있는건가?" → AI가 세트(unit)·문항(lesson) 구조를 보여 주고 첫 세트 / 세트 목록 화면 / 안 한 세트 자동 고르기를 제시. "아직안한 세트를 자동으로 고르는 건 어떻게 하지? 아직 안한 세트가 뭔지를 알아야하잖아"
  - 바뀐 계기: AI가 `GET /learning/units`의 `lessons[].completed`(사용자·등급·콘텐츠 버전 기준)로 알 수 있다고 답하고 함정 셋을 제시 — Part 2~5는 채점까지 끝나야 완료, 등급마다 따로, 콘텐츠 버전이 바뀌면 초기화
  - 최종: "어 그럼 서버 기준으로 안한 것부터 해줘" → `completed: false` 문항이 있는 첫 세트의 첫 미완료 문항
- 쟁점: 버튼
  - 처음 판단: "5번은 버튼이 다양해서 기존 꺼를 못쓸 것 같고"
  - 바뀐 계기: AI가 AGENTS.md 규칙(기존 variant가 안 맞으면 `Button`에 variant 추가)과 부딪힌다고 물었으나 답 없이 "반증은 모르겠다 구현 시작해"
  - 최종: AI 제안 — 공용 `Pressable`로 화면에서 직접 그림(등급 카드 CTA와 같은 방식)
- 쟁점: 답을 받지 못하고 구현에 들어간 것(모두 AI 제안)
  - 처음 판단: "반증은 모르겠다 구현 시작해"
  - 바뀐 계기: 없음
  - 최종: 다 끝낸 파트는 첫 세트부터 다시 / 진동(`expo-haptics`) 없이 흔들림만(재빌드 피함) / 소리·녹음 없이 단어 시각대로 하이라이트, 따라 말하기·채점은 목 결과 / Part 1은 퍼즐·채점 없이 ② → 완료
- 쟁점: 등급 카드를 눌러도 넘어갈지
  - 처음 판단: "저기 난이도 선택하는 화면에서 버튼뿐 아니라 카드를 클릭해도 넘어가게 할 수 있어? 다음 스테이지로?"
  - 바뀐 계기: AI 제안 — 옆 카드는 바로 들어가지 않고 가운데로 옮김(넘기다 스친 카드로 잘못 들어가는 것 방지)
  - 최종: 가운데 카드 = 파트 화면, 옆 카드 = 가운데로 이동
- 쟁점: 따라 말하기가 무엇을 보여 줄지
  - 처음 판단: AI가 작업 예상에 기기 STT를 넣자 "stt가 왜 필요해? 지금 저기있는 기능들이 api 연결만으로 불충분하니?", 이어서 "저 따라 말하기는 말할 때 내가 하는 말을 어디 하고 있는지 노래방 가사 따라 하듯이 표시해주기 위함이지?"
  - 바뀐 계기: AI가 지금 구현은 재생 하이라이트와 따라 말하기(가짜 결과)가 따로 논다고 설명하고, (가) 모범 음성 속도로 가사 진행(STT 불필요) / (나) 내 목소리를 STT로 따라 칠하기를 제시. STT는 옛 브랜치 기능을 AI가 묻지 않고 이어받은 가정이었다
  - 최종: "(가)로 변경해서 확정" — 모범 음성 속도로 가사가 흘러가고 사용자는 동시에 따라 말한다. STT 없음

- 다루지 않은 것: 서버 호출, 세트 목록 화면, 이어서 하기, 채점 한도(`LEARNING_RATE_LIMITED`)
- 반증: "반증은 모르겠다"(사용자가 쓰지 않음)
