# 10초 챌린지 화면 뼈대

작성일: 2026-08-25. 구현 전에 사용자가 직접 쓴 뼈대 코드와 그 자리에서 정리한 생각이다.
`how-we-work.md`의 3단계 산출물이라 실행되지 않으며, 타입·임포트·스타일은 일부러 빠져 있다.

구현된 결과는 [`src/screens/ten-second-challenge/`](../../src/screens/ten-second-challenge/)에 있고,
뼈대와 달라진 점은 구현 시점에 따로 보고했다. `src/` 아래 두면 tsc·oxlint가 실행 코드로 읽으므로
여기로 옮겨 원문 그대로 보관한다.

```tsx

// 지금 중요한 게 당초 계획과 달리 10초 챌린지를 홈에서 클릭했을 때 바로 이 화면으로 넘어오는게 아니라 스테이지 화면에서
// 본인이 오늘 어디까지 풀었는지를 볼 수 있고 아직 안푼 문제를 클릭했을 때 이 문제 화면으로 넘어오고 이미 문제를 푼 경우에는 해설(결과) 화면을 띄워주는 것으로 한다. 
// 결과 화면인지 문제 화면인지 구분하기 위해서는 상태관리가 필요한데 이 컴포넌트 내부에 상태로 두면 컴포넌트 생명주기에 얽히므로 
// 외부로 빼야 하고 그렇다고 전역으로 상태 관리를 하기에는 그래도 두 컴포넌트 간에 걸쳐있으나 메모리에 들고 있어야한다는 단점이 있는데 
// 어차피 이 데이터의 소스는 서버이므로 최초에 스테이지 화면에 들어올 때 서버에서 받은 데이터를 prop으로 내려줘서 
function TenSecondChallengeScreen({isCompleted}: {isCompleted: boolean}) {
    const [timeLeft, setTimeLeft] = useState(10);
    const [question, setQuestion] = useState("목데이터로 받아올 한글 문제"); //나중에 api로 받아올 문제
    const [submitAnswer, setSubmitAnswer] = useState(false);
    //오디오로 입력 받기 오디오 입력은 어떻게  받아야할지 감이 안옴. 

    useEffect(() => {
        //api 호출 
        const timer = setInterval(() => {
            setTimeLeft((prev) => {
                if (prev <= 1) {
                    clearInterval(timer);
                    return 0;
                }
                return prev - 1;
            });
        }, 1000);

        return () => clearInterval(timer);
    }, []);

    useEffect(() => {
        if (timeLeft === 0) {
            setSubmitAnswer(true);
        }
        if (submitAnswer) {
            //제출 로직
            console.log("제출 완료");
            //api 호출
        }
    }, [timeLeft,submitAnswer]);

    return (
        {isCompleted ? <ResultScreen /> : <ChallengeScreen />} // 이렇게 조건 분기를 할 수 있는데 
        // 이 아래 내용이 그럼 챌린지 스크린으로 들어가야할 것 같다. 근데 이렇게 되면 10초 챌린지 컴포넌트에 들어와서도 챌린지 스크린으로 한 단계 더 타고 들어가야하는 약간의 마찰이 있으나 
        // 아 취소하고 여기서 prop을 받을 필요 없이 이전 스테이지 컴포넌트에서 isCompleted를 기준으로 navagate를 해주면 되겠다.
        // 10초 챌린지 스크린 안에 결과 스크린이랑 챌린지 스크린을 따로 분기 처리하는게 더 안좋은 것 같다.
        
        // 근데 문제가 이렇게 되면 완료를 하고 채점 대기하다가 결과 화면으로 내비게이트를 해야한다. 어떤게 더 나을까?
        // 사실 둘 사이에 공유해야하는 상태는 딱히 없다. 
        // 그렇다면 굳이 같이 둘 필요 없이 구분하는게 나으려나?
        <View>
            <Header title="10초 챌린지" />
            <Title>오늘의 10초 </Title>
            <Text>{timeLeft >= 10 ? "00:"+ timeLeft : "00:0" + timeLeft}초</Text> //이걸 별도 함수로 분리하는게 더 나으려나? 조건 분기가 복잡한 거 같아서. 
            <NoteBook>
                <View>
                    <Start/>
                <Text>오늘의 문장</Text>
                </View>
                <Text>{question}</Text> //목데이터로 받아올 한글 문제 
                <DashedLine />
                <Image source={require('../../assets/images/drawingcat.png')} />
            </NoteBook>
            <Button onPress={() => setSubmitAnswer(true)} disabled={submitAnswer}>
                <Text>완료</Text>
            </Button>
        </View>
    );
}```
