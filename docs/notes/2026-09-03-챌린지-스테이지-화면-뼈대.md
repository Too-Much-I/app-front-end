`how-we-work.md`의 3단계 산출물이라 실행되지 않으며, 타입·임포트·스타일은 일부러 뺀다.

쓴다: 상태 정의, 분기 조건, 상태 전이, 에러 처리 갈래, 상태별 UI 대응
생략한다: import, 타입 선언, 매퍼, 스타일링, try/catch 보일러플레이트, API 시그니처 정확도

## 이 뼈대를 쓰기 전에 정한 것

| # | 결정 |
|---|---|
| 만료 | `expiresInSeconds` 상대 타이머. 기기 절대 시각과 비교하지 않는다 |
| 진행도 조회 | 스테이지가 소유. TanStack Query. 갱신 계기 3개(진입/포커스 · active 복귀 · 만료 타이머). 폴링 없음 |
| 포커스 배선 | `focusManager` 전역 배선은 하지 않는다. 조회 훅 안에서 `useFocusEffect` + `AppState` |
| 카드 상태 | `locked` / `next` / `done` 3종. `gradingStatus`는 보지 않는다(배지 없음) |
| 날짜 | 스테이지가 route param으로 넘긴다. 문제 화면은 `CHALLENGE_DATE_CHANGED`면 재시도 대신 스테이지로 돌아온다 |
| 스택 | 홈 배너를 스테이지로 교체. 홈 → 스테이지 → 문제/결과. `goToStage` = `goBack` 유지 |
| 한 문장 더 | 스테이지가 `nextQuestionNumber`를 넘긴다. 항상 안 푼 문제로 가고, 다 풀었으면 버튼이 없다 |
| 목 데이터 | `withDevMockFallback` + `DEV_MOCK_CHALLENGE_TODAY` |

아직 열려 있는 것 (뼈대를 막지는 않음)

- `resultAvailable`의 뜻 — `attemptStatus: submitted`인데 `false`인 구간이 있나. 있으면 `done` 카드에 갈래가 하나 붙는다
- 챌린지를 `OPERATIONAL_ERROR_CODES`에 넣을지 — 진행도 조회는 이 기능의 유일한 시작점이다
