# 마이페이지

## 문제

다음 업데이트에서 마이페이지 탭을 추가한다. 닉네임 인사, 10초 챌린지 참여를 당근으로 보여 주는 월 달력, 설정에서
옮겨 올 메뉴가 들어간다. 시안: 캔버스 "마이페이지 당근 달력"(https://claude.ai/artifact/LdzfzHpeymP8NZimfHTAKQ).

쓰는 서버 계약:

- `GET /api/v1/users/me`(Identity): `nickname`이 있다. 앱은 지금 세션 복구 때만 부르고 `accountType`만 쓴다
  (`get-current-account.ts:5`). 닉네임을 바꾸는 API는 없다.
- `GET /api/v1/challenges/history?yearMonth=YYYY-MM`(Learning Core, 10초 챌린지 명세 6.7): 날짜별
  `solvedQuestionCount`(0~3). 이번 달은 KST 오늘까지, 미래 달은 400. 앱에 아직 연결되지 않았다.
- 명세와 실제 서버가 다른 점(서버 확인, 2026-10-11): 명세 3.2·6.7·6.8은 1시간 제출 만료도 푼 문제로 센다고 적었지만,
  실제로는 제출 API까지 정상 접수된 것만 센다. 같은 날 만료된 문제는 새 attempt를 만들어 다시 풀 수 있다(명세 1절
  "최대 한 번", 6.3 "같은 attemptId 반환"과 다르다). 그래서 푼 문제는 항상 1번부터 이어진다.

## 선택지

| 결정 지점 | 안 | 비용 |
| --- | --- | --- |
| 닉네임 출처 | 세션 컨트롤러가 복구 때 받아 보관 | 인증 코드에 프로필 책임이 섞인다. 새 로그인 경로(`acceptSession`)는 `/users/me`를 부르지 않아 비어 있다 |
| | 가입 때 기기에 저장 | 다른 기기·계정 찾기에서는 없다 |
| | 마이페이지가 한 번 불러 메모리에 보관 | 같은 API를 두 곳에서 부른다. 계정이 바뀌면 지워야 한다 |
| 이력 갱신 | 제출 성공 시 지움 | 다른 기기 제출이 반영되지 않는다 |
| | 마이페이지 진입마다 조회 | 들어올 때마다 요청 1번 |
| 지난 날짜 스테이지의 개수 | 달력이 가진 개수를 넘김 | 달력 조회 시점 값 |
| | 스테이지가 `/results`(문제 번호 없음)로 다시 조회 | 요청 추가, 실제 서버 미확인 형태 |
| 0문장 지난 날짜 | 빈 스테이지 / 누를 수 없음 / 안내 팝업 | 시안: "푼 문제 없는 날 팝업" |

## 결정

대화에서 사용자가 명시한 결정(원문):

- 화면: "사용자 닉네임을 표시해주고 안녕하세요 00님 오늘도 힘내봐요", 토끼는 양손 흔드는 토끼. 당근은 "당근 절반만
  칠해지고 2개 수행하면 당근은 다 칠해지는데 이파리가 없고 다 해야 이파리까지 채워지는 식", 칠해지지 않은 영역의
  선은 칠하지 않는다.
- 게스트: "게스트는 아예 저걸 볼 일이 없다니까". 탭 화면은 `authenticated`에서만 열린다(`RootNavigator.tsx:154`).
- 닉네임: "users/me를 불렀을 때. 저장해두면 될 것 같은데" — 세션 컨트롤러 밖, 마이페이지가 불러 메모리에 둔다.
- 달력: "지난 날짜는 모두 빈당근으로 하자", "다음 달 버튼을 막자. 서버의 challeng-date로 판단", 이전 달은 "제한 없이".
- 통계 카드: "완성한 당근과 연속참여는 일단 뺴자".
- 갱신: "그냥 마이페이지 진입시마다 하고" (처음 결정 "제출에 성공하면 저장해둔 이력을 지우는 걸로"를 대체).
- 날짜 누름: "그날 결과 화면 스테이지로 이동". 지난 날짜는 달력의 개수를 넘긴다. 오늘은 "오늘은 다르게 체크해야겠다"
  — 기존 오늘 스테이지로 간다. 0문장 지난 날짜는 "팝업으로 이날은 푼 문제가 없어서 결과를 조회할 수. 없어요. 를
  띄우고 닫기 버튼", 토끼는 "놀란토끼".
- 메뉴: 문의하기·로그아웃 노출, 나머지는 설정으로 연결, 버전은 하단 작은 글씨. "홈의 설정 버튼은 없애는 걸로 하고
  마이페이지 안으로 넣자".
- 실패·정리: "설정 화면의 응원카드는 없애주고 이력이 실패한 경우에는 달력을 띄우지 않는 걸로 해줘 내부적 재시도는
  기존 레포 규칙에 따라 하되 그리고 닉네임이 없는 경우에는 00님을 비워줘". 저장소 규칙은 조회 자동 재시도 없음
  (`query-client.ts`), 401만 재발급 뒤 한 번.
- 달 이동 실패(구현 뒤): "이전 달에서 조회가 실패하면 더 이상 넘길 수 없다는 팝업을 띄우고 달력 자체는 그대로 유지해줘
  그 넘기기 전달에서" — 받은 뒤에 넘기고, 실패하면 보던 달 유지 + 팝업.
- 당근 그리기: "어차피 이거랑 결제 넣으면서 다시 업데이트 올릴거니까 설치해서 쓰자" — `react-native-svg` 추가.
- 범위 밖: "알림은 이번에 빼." 모든 기기 로그아웃·SNS 연결 관리는 넣지 않는다.

## 코드 흐름 변화

이전: 탭은 홈·모의고사·피드백. 설정은 홈 헤더 버튼으로 들어간다(`HomeScreen.tsx:91`). 스테이지는 오늘 전용
(`ChallengeStage: undefined`, `useChallengeToday`).

이후: 탭에 마이페이지(`MyPageScreen`)를 더했다. `useMyProfile`이 `/users/me`를 한 번 읽어
(`identityFetchWithAuthRetry` — Identity 주소로 같은 401 재발급 경로를 타도록 공용 클라이언트에 추가) 닉네임을 쓰고,
`useChallengeCalendar`가 이번 달(`yearMonth` 없이)과 보고 있는 달의 이력을 읽어 `toChallengeCalendarState`로 그린다.
포커스마다 이력을 다시 읽고, 닉네임은 없을 때만 다시 읽는다. 칸을 누르면 `decideChallengeCalendarDayAction`이
오늘 → `ChallengeStage`, 푼 지난 날짜 → `ChallengeDayStage`(날짜·개수), 0문장 지난 날짜 → 안내 팝업을 고른다.
당근은 `react-native-svg`로 그린다(새 의존성, 네이티브 빌드 필요). 로그아웃 확인 훅은 `features/auth`로,
버전 표기는 `features/app-version/installed-app-version.ts`로 옮겨 설정과 함께 쓴다. 홈의 설정 버튼과 설정의 응원
카드를 없앴다.
