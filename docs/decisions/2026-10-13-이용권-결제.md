# 이용권 결제

## 문제

이용권 화면(`PassPurchase`)은 상품만 보여 주고 결제 버튼은 동작하지 않는다. 모의고사는 누구나 시작할 수 있다.
결제는 RevenueCat SDK로 하고, 이용권 지급·기간 계산·응시 판정은 Billing 서버가 맡는다.

## 서버에서 정해진 것

2026-10-13 답장, 2026-10-14 Billing 명세(Notion)와 추가 답.

- RevenueCat: iOS·Android 모두 `com.toteacher.app`. 공개 SDK 키 iOS `appl_eXvEgUFsXPXTHvwqPquqRFDQfYO`,
  Android `goog_rzNOZCTPqKollmgNmEClbnorMZw`. Offering `premium`, 소모성 상품, Entitlement는 쓰지 않는다.
- Billing 테스트 주소 `https://billing-test.to-teacher.com`. Identity Access Token의 audience에 Billing이 들어
  있어 같은 토큰을 쓴다. 네 API 모두 기본 OFF.
- `POST /payments/purchase-account`: 본문 없음, `purchaseAccountRefId`(UUID v4)를 RevenueCat `app_user_id`로
  쓴다. 사용자·환경마다 고정. 익명 구매·임의 ID 금지.
- `GET /payments/products`: Billing이 이용권으로 바꿔 줄 수 있는 상품(offerCode·기간·스토어별 연결). 가격 없음.
- `POST /payments/sync`: 결제 뒤 `{store, transactionId}` + Idempotency-Key. 서버에 거래 검증·반영을 시키는
  요청이다. 202 PENDING이면 같은 요청으로 다시, 200 APPLIED면 끝. 웹훅은 sync 누락 대비.
- `GET /entitlements`: 진입 여부는 `examAvailability.canTakeExam`(true/false로 준다). `paid`·`benefits`는 안내용.
  시험 시작은 `POST /exams`가 최종 확인한다.
- 정해지지 않은 것: sync의 `transactionId`로 SDK의 어느 값을 보낼지(실거래로 확정), `POST /exams` 거절 코드.
  테스트 서버 웹훅 미연결, Google 상품 비활성.

## 결정

대화에서 사용자가 명시한 결정(원문은 학습 기록 `docs/learning/2026-10-13-이용권-결제.md`):

- 결제 라이브러리: expo-iap를 빼고 `react-native-purchases`.
- 판매 목록: Billing `products`와 Offering을 대조해 둘 다 있고 연결(packageId·productId)이 맞는 상품만 판다.
  가격은 스토어, 기간은 Billing, 이름(1일권·3일권·1주권·2주권·4주권)과 묶음은 앱이 offerCode로 붙인다.
  불러오지 못하면 상품 화면 대신 재시도 버튼만 보인다.
- 결제용 ID: 로그인·세션 복원 때 확보하고 AsyncStorage에 둔다(iOS 키체인은 앱 삭제 뒤에도 남는다). 저장돼
  있으면 다시 받지 않는다. 로그인 화면에 오면 비우고 RevenueCat `logOut` — 앱 안에 계정 전환이 없어 로그인
  화면에 왔다는 것 자체가 계정이 바뀔 수 있다는 뜻이다.
- 결제 확인: 5초 간격 6번(약 30초) 확인한 뒤 "확인 중"을 알리고 멈춘다. 키·거래 ID를 기기에 저장해 다음
  로그인·이용권 화면에서 다시 확인하고, 로그인 화면에서 지운다. 반영되면 알림만, 문의가 필요하면 문의하기
  버튼만.
- 모의고사 진입: 준비 화면에 들어올 때 확인한다(세 진입로 공통, 마이크 테스트 전). true면 시작하고 무료
  응시권 사용·이용권 기간·결제 처리 중을 안내한다. false면 결제 화면. 결제 처리 중이면 결제 화면으로
  보내지 않는다(두 번 결제 방지). 확인할 수 없으면 막고 다시 시도하게 한다.
- PR: 서버 기능이 켜진 뒤 Sandbox로 확인하고 올린다.

## 코드 흐름 변화

- 인증 runtime이 로그인 상태가 되면 결제용 ID 확보 → RevenueCat `logIn` → 남은 결제 확인을 다시 보낸다.
  로그인 화면 상태(noSession·guest·비활성·탈퇴 안내)가 되면 결제용 ID와 남은 결제 확인을 지운다.
- 이용권 화면: `products`+Offering 대조 → 결제 → sync 확인 → 결과 알림 → 이용권 조회 갱신.
- 준비 화면: 포커스마다 `entitlements` → 시작 버튼 허용 여부와 안내. 응시권이 없으면 결제 화면으로 한 번 보낸다.

확인할 것: 서버 기능 ON 후 Sandbox 첫 거래로 `transactionId`, `canTakeExam` 실제 값, `.env.local`의 Identity·
Learning을 테스트 서버로 맞추기, 개발 빌드 다시 만들기. Android는 Google 상품 활성화 후.
