# 회원 탈퇴

## 문제

회원이 앱에서 계정을 삭제할 방법이 없다. App Store는 계정을 만들 수 있는 앱에 앱 안 탈퇴를 요구하고, Sign in with
Apple을 지원하면 탈퇴 때 Apple 토큰 revoke를 요구한다(가이드라인 5.1.1(v)). 기존 `api/logout.ts`는 이름과 달리
Guest용 `/users/withdraw` 호출이다.

서버 계약(Identity Swagger·서버 가이드 6·7절, 2026-10-07 확인과 서버 답):

- `POST /api/v1/users/withdraw`, Bearer + body `{ refreshToken, firebaseIdToken }`. 서버 합의로 `auth_time` 검사
  없이 지금 토큰을 그대로 보낸다(가이드 6.1의 recent reauthentication은 적용하지 않음).
- 200 `{ status: WITHDRAWN, withdrawnAt, cleanupStatus }`. `cleanupStatus`와 관계없이 탈퇴 확정이다. 이미 탈퇴한
  계정이면 다시 보내도 200(멱등). withdraw가 `401 ACCOUNT_WITHDRAWN`을 줄 일은 원칙상 없지만 낮은 확률로 올 수 있다.
- 탈퇴하면 모든 RefreshSession이 폐기되고, 다른 기기는 reissue와 `/users/me`에서 `401 ACCOUNT_WITHDRAWN`을 받는다.
- 학습 기록은 실제로 삭제된다. Firebase User 삭제·identity release는 서버가 비동기로 한다. 정리 전 재가입은
  `409 WITHDRAWAL_CLEANUP_PENDING`이고, 정리 뒤 재가입은 새 User다.
- 서버는 Apple 토큰 revoke를 하지 않는다. RNFirebase 26.4의 `revokeToken`은 iOS만 동작한다(Android는 미구현).

## 선택지

| 결정 지점 | 안 | 비용 |
| --- | --- | --- |
| 재인증 | 모든 탈퇴에 Provider 재인증 | 매번 SNS 창. 잠금 풀린 폰 대비 |
| | 지금 토큰 그대로 (서버 합의) | 잠금 풀린 폰으로 탈퇴 가능 |
| 이미 탈퇴한 계정 판별 | 탈퇴 전 매번 reissue | 회전·응답 유실 복구가 매 탈퇴에 붙음 |
| | `getIdToken` 실패 때만 reissue | 드문 경로만 무거움 |
| `ACCOUNT_WITHDRAWN` 문구 | 맥락별(완료 / 사실 고지) | 문구 둘 |
| | 하나로 통일 | 다른 기기에선 "왜?"가 남을 수 있음 |
| Apple 사용자 판별 | 마지막 로그인 수단 | 힌트라 없을 수 있음 |
| | `providerData`의 `apple.com` | 한 계정 SNS 하나 전제 |
| Apple 창 취소 | 탈퇴 중단 | 사용자가 다시 시작 |
| | revoke 없이 진행 | 가이드라인 미충족 사용자 생김 |

## 결정

대화에서 사용자가 명시한 결정(원문):

- 재인증: "서버랑 정했어. 둘 다 토큰 값 그냥 보내면 된다고 했어."
- 판별: "실패할 때만 리이슈를 하는 걸로 하자." Firebase에만 없는 계정은 "우선순위가 낮은 것 같아".
- 문구: "그냥 다 통일해 어차피 탈퇴가 처리됐다는 건 동일하고 굳이 축하해줄 필요가 없을 것 같아 .해요체로 해"
  → 200·`ACCOUNT_WITHDRAWN` 모두 "계정이 탈퇴됐어요." 안내와 전환은 한 번만.
- 확인 팝업 한 번: "탈퇴할까요?" / "지금까지의 학습 기록이 모두 삭제되고, 되돌릴 수 없어요. 다시 가입하면 새
  계정으로 시작해요." [취소 / 탈퇴하기]
- 로컬 정리: "세션이랑 파이어베이스 토큰 그리고 쿼리 클라이언트 다 지우면 될 것 같은데, store에 저장하는 것도 다
  지우고" + 마지막 로그인 수단 + "installation-id도 그냥 지워".
- 재가입 정리 중: 가이드 문구를 해요체로 — "계정 정보를 정리하고 있어요. 잠시 후 다시 시도해 주세요."
- 네트워크 오류: "네트워크 오류 … 잠시 후 다시 시도해 주세요", 공용 처리 없이 탈퇴 흐름 안에서.
- Apple: "revoke를 먼저 하는게 나은 것 같아", `providerData` 기준, "취소하면 탈퇴를 멈추는 걸로",
  "안드로이드에서는 revoke를 안하는 걸로 하자."
- 대상은 회원뿐이다. Guest 세션은 로그인 화면에 머물러 설정에 들어오지 못한다.

남는 위험: Android의 Apple 가입자는 Apple 연결이 남는다(설정 목록에 앱 이름이 남는 정도). 잠금 풀린 폰으로
탈퇴할 수 있다(서버 합의).

## 코드 흐름 변화

이전: 회원이 탈퇴할 입구가 없고, 재발급·`/users/me`의 `ACCOUNT_WITHDRAWN`은 처리되지 않아 복구 불가 화면으로 빠진다.

이후: 설정 "계정" → 회원 탈퇴 → 확인 모달(`ConfirmModal`) → `auth-runtime.ts` `withdraw`(연속 클릭은 한 번) →
`account-withdrawal.ts` `runAccountWithdrawal`(`prepareTokenPair`로 같은 세션의 토큰 쌍 → `getCurrentIdToken(false)`,
실패 시 `recoverUnauthorized`로 재발급해 탈퇴 여부 확인 → `apple.com` 연결이면 `revokeAppleSignIn`, 취소 시 중단 →
`withdrawAccount`, 401은 한 번 고쳐 재전송) → `session-controller.ts` `endWithdrawnSession`(서버 폐기 없이 기기 세션
삭제 → `account-withdrawn` 알림) → 코디네이터 `accountWithdrawn`(안내 화면) + runtime 기기 정리(Firebase·Google
로그아웃, 마지막 로그인 수단, installation-id, 동의 기록 2종, 가입 초안. 조회 캐시·병합 추적은 계정 변경 알림이 비움)
→ [확인] → 로그인 화면. 다른 기기 탈퇴는 재발급·`/users/me`·`recoverUnauthorized`의 `ACCOUNT_WITHDRAWN`이 같은
`account-withdrawn` 알림으로 들어와 같은 안내·정리를 탄다. 안내는 코디네이터가 `authenticated`·`consent`에서만
바꾸므로 여러 요청에서 받아도 한 번이다.

추가 결정(원문, 3단계 뒤): 오류 문구 "문구 그대로"(400·404·409·`FIREBASE_ACCOUNT_NOT_ALLOWED` 등은 "탈퇴하지
못했어요. 잠시 후 다시 시도해 주세요."), "로딩 보여주고", "동의기록까지 지우고", "새 탈퇴api로 변경해야지".

구현 중 정한 것(설계 논의에 없던 것):

- 안내 화면 본문 "다시 가입하면 새 계정으로 시작해요."와 버튼 "확인". 안내 카드가 본문을 요구해 승인된 팝업 문장을
  다시 썼다.
- 로그인(exchange)의 `WITHDRAWAL_CLEANUP_PENDING`도 같은 문구로 "다시 로그인"을 띄운다. 탈퇴 직후 같은 SNS로
  들어오는 가장 흔한 경로인데 처리되지 않아 "도움을 요청해 주세요"로 빠졌다.
- Apple revoke가 취소가 아닌 오류로 실패하면 탈퇴하지 않고 실패 문구를 보인다(revoke가 탈퇴의 조건이라서).
- 확인·진행·실패를 공용 `ConfirmModal` 하나로 보여준다(2026-10-07 시안 비교 뒤 사용자 "시안 A로 해줘"). 네이티브
  Alert는 앱의 다른 되돌릴 수 없는 확인(계정 찾기·병합)과 모양이 달랐다. 진행 중에는 모달이 화면을 덮어 로그아웃도
  막고, 실패 문구는 모달 안에 보여 바로 다시 시도할 수 있다. Apple 창을 닫으면 모달을 닫는다. `ConfirmModal`의
  확인 버튼에 `pending` 동안 스피너를 붙였다(지금 `pending`을 넘기는 다른 화면은 없다).
- 설정의 회원 탈퇴 행은 빨간 강조 없이 다른 행과 같은 모양이다. 사용자: "너무 잘보이게 하지 않는게 우리 서비스에는
  좋을 것 같아."
- 에뮬레이터에서 발견해 이번에 함께 고친 것(사용자 "일단 여기 넣어서", "그냥 여기 넣어"):
  - `transport.ts`: Expo 57이 전역 `fetch`를 expo/fetch로 바꿔, 연결 실패가 `TypeError`가 아니라
    `FetchError`("fetch failed: …", `Error` 상속)로 온다. `TypeError`만 연결 오류로 보던 탓에 앱 전체의 오프라인
    재발급이 "도움 요청" 화면에 갇혔다. `message.startsWith('fetch failed')`를 연결 오류에 더했다(사용자 선택.
    `fetch()` 호출만 따로 감싸는 안, `EXPO_PUBLIC_USE_RN_FETCH`로 되돌리는 안은 택하지 않음).
  - `Button.tsx` danger·`ConfirmModal.tsx` 오류 문구: 공용 `Text`의 기본 `text-ink`가 이겨 빨간 글자가 검게
    보였다. `!text-exam-danger`로 고쳤다. danger 버튼을 쓰는 다른 확인 모달에도 적용된다.
- 알려진 문제(서버 요청함, 2026-10-07): 가입의 전화번호 연결(`linkWithCredential`)이 Firebase 토큰의
  `sign_in_provider`를 `phone`으로 바꾼다(에뮬레이터에서 연결 전 `apple.com` → 후 `phone`, 강제 갱신해도 같음).
  서버 탈퇴는 이 토큰을 `403 FIREBASE_PROVIDER_NOT_ALLOWED`로 거절해, 새로 가입한 회원은 다음 SNS 로그인 전까지
  탈퇴할 수 없다. SNS로 다시 로그인하면 탈퇴된다(확인함). 앱은 지금 일반 실패 문구를 보인다.
- 알려진 빈틈(받아들임): 탈퇴 안내와 기기 정리는 메모리의 notice로만 이어진다. 정리 도중 앱이 죽으면 다음 실행은
  `signed-out`만 읽어 안내·정리 없이 로그인 화면으로 가고, 못 지운 값(마지막 로그인 수단 등)이 남는다. 사용자:
  "일단 넘어가는 걸로 하자. 빨리 머지를 해야하니까. 드문 경우야."
 옛 `auth-controller.ts`(쓰는 곳 없음)도 새 API를 부른다.

건드린 파일: `api/withdraw-account.ts`(이름 변경), `account-withdrawal.ts`(신규), `api/reissue-tokens.ts`,
`session-controller.ts`, `session-restoration-types.ts`, `auth-coordinator.ts`, `auth-runtime.ts`,
`firebase-auth-sdk.ts`, `firebase-auth-types.ts`, `last-login-provider.ts`, `installation-id.ts`,
`consent-storage.ts`, `optional-consent-storage.ts`, 가입·승격·병합 흐름 문구, `RootNavigator.tsx`,

## 기준 충돌

결합도: `auth-runtime.ts`가 consent feature의 저장소 삭제 함수를 직접 부른다(아키텍처 경고 2건, 차단 아님). 동의
기록을 지우는 일을 consent 쪽 구독으로 옮기면 auth가 consent를 몰라도 되지만, 탈퇴 정리 목록이 여러 곳으로
흩어지고, 다른 feature가 인증 알림을 직접 구독하는 첫 사례가 된다. 기존 방식(`auth-consent-controller.ts`의
직접 호출, runtime의 계정 변경 정리)을 따라 직접 호출로 둔다. 사용자: "어 기존 방식을 따르게 하자."

다음 결제 업데이트 때 볼 것: 스토어 구독은 탈퇴로 취소되지 않으니 팝업 안내, 결제 기록 보관 시 "모두 삭제" 문구.
