# 포그라운드 복귀 시 인증 자동 복구

## 문제

백그라운드에서 인증 저장소 읽기 등이 실패하면, 앱에 돌아와도 오류 화면이 남고
사용자가 직접 재시도해야 했다. 기존 AuthProvider에는 앱 복귀 처리가 없었고,
새 auth-runtime은 백그라운드 세션 저장 실패만 복귀 시 재시도했다.
실제 기기에서 발생한 오류가 잠금 상태의 SecureStore 접근 제한 때문인지는 미확인이다.

## 선택지

| 안 | 이점 | 비용 |
| --- | --- | --- |
| 저장소 실패만 자동 복구 | 대상이 좁음 | 연결·서버 일시 장애는 수동 복구 |
| 자동 실행 가능한 인증 실패 전반 복구 | 복귀 후 사용자의 추가 행동 감소 | 단계별 자동 실행 가능 여부 판단 필요 |
| Error Boundary로 오류 처리 | 렌더링 예외의 대체 화면 제공 | 비동기 인증 실패를 자동 포착하지 않으며 실패 단계 재개를 대신하지 못함 |

## 결정

사용자는 복구 가능한 인증 오류 전반의 자동 재시도를 선택하고 별도 브랜치 구현을 요청했다.
Error Boundary 대신 인증 컨트롤러의 복구 정책과 앱 생명주기를 연결한다.
아래 세부 대상·제외 조건은 에이전트 구현 내용이며 사용자 설명·평가는 아직 받지 않았다.

## 코드 흐름 변화

구현 결과, 사용자 확인 대기:

- `auth-foreground-recovery.ts`: background/inactive → active 복귀당 한 번 재시도.
  복귀 시 작업 중이면 결과를 관찰한다. 실패 알림이 늦게 와도 처리하며,
  원래 작업의 finally 이후 실행하도록 다음 이벤트 루프로 넘긴다.
- 컨트롤러는 `busy`/`retryable`/`settled`로 자동 복구 가능 여부를 제공한다.
  성공·사용자 입력 대기에 도달하면 이번 복귀의 재시도 기회를 닫는다.
- `AuthProvider.tsx`와 `auth-runtime.ts`가 각각 구독하고 해제한다.
  예약 이후 background 전환·수동 재시도·해제 시 현재 상태를 다시 확인한다.
- `AuthRecoveryScreen.tsx`: 재시도 중에는 오류 문구·버튼 대신 진행 화면을 표시한다.
  자동 재시도도 실패하면 기존 수동 재시도·문의 UI로 돌아간다.
- 최초 active 실행에서 발생한 실패는 복귀 이벤트가 아니므로 기존 수동 복구를 유지한다.

자동 실행 범위:

| 경로 | 대상 | 자동 실행하지 않는 작업 |
| --- | --- | --- |
| 기존 앱 | 시작 시 저장소 읽기·설치 ID/세션 저장·서버 동의 조회·동의 사본 저장 | Guest 발급, 사용자 동의 제출, 토큰 재발급 실패의 재전송 |
| 새 runtime | 복구 정책이 허용한 세션 복원·약관 조회, Identity exchange/prepare, 받은 세션 활성화 | SNS 인증, 재로그인 요구, 가입·병합·동의 제출, 도움받기 상태 |

기존 앱의 재발급 API에는 요청 ID 기반 replay 계약이 없다. 응답이 유실됐을 때
이미 사용된 refresh token을 자동 재전송하지 않도록 해당 실패는 수동 경로에 남겼다.
새 runtime은 기존 `refresh-uncertain` 차단 및 요청 ID 보존 정책을 그대로 따른다.
현재 앱은 여전히 기존 AuthProvider 경로이며 새 runtime 활성화는 이번 변경에 포함하지 않는다.

## 뼈대 → 구현에서 달라진 것

이번 작업은 사용자가 설명 후 직접 구현을 요청했으며 별도 스켈레톤은 없었다.
복귀 시점의 오류만 검사하면 진행 중이던 요청의 늦은 실패를 놓치므로 인증 상태도 구독했다.
수동 재시도 중에도 같은 진행 UI를 사용한다. 인증 오류를 렌더링 예외로 바꾸지 않았다.

## 기준 충돌

기존/새 컨트롤러의 상태 모델은 유지하고 앱 복귀 횟수·구독 수명 관리만 공유했다.
자동 재시도 대상 판단은 각 컨트롤러에 두었다. 최종 사용자 설명·평가는 대기 중이다.

검증: `node scripts/check-auth-restoration.mjs` — 기존 앱 읽기 복구, 새 복원,
늦은 실패, 중복 active, 지속 장애, 수동 재시도 경합, 구독 해제, 재로그인 제외를 포함.
실제 기기 잠금·해제와 백그라운드 복귀 UI 검증은 별도로 필요하다.
