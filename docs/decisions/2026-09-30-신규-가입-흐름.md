# 신규 가입 흐름 (닉네임 · 약관 · 전화 인증 · signup)

## 문제

exchange가 `ENROLLMENT_REQUIRED`를 주면 앱은 "준비 중" 화면만 보여줬다. 신규 사용자가
닉네임·약관 동의·전화 인증을 마치고 `/firebase/signup`으로 MEMBER가 되는 경로가 없었다.

## 선택지

| 안 | 장점 | 부담 |
| --- | --- | --- |
| 코디네이터 state 확장 | 인증 상태가 한 곳에 모인다 | 코디네이터가 가입 세부 단계까지 커진다 |
| 별도 signup 컨트롤러 | `renderEnrollment` 경계와 맞는다 | flowId·취소를 두 곳에서 맞춰야 한다 |

## 결정

사용자 결정(2026-09-30):

- 별도 signup 컨트롤러가 흐름을 소유하고 코디네이터는 진입(`signingUp`)·출구(`onComplete`/`onCancel`)만 맡는다.
- 고정 순서 닉네임 → 약관 → 전화 인증 → 제출. 한 화면에 한 목적이라 닉네임과 약관 화면을 나눈다.
- 닉네임·약관은 signup body 필수이고 이를 보내는 API가 signup뿐이라 항상 받는다. 전화 인증만 요구사항에 따라 건너뛴다.
- `EMAIL_VERIFICATION`은 SNS 로그인 경로에서 쓰지 않는다(서버 확인).
- 약관 버전은 약관 화면 진입 시 공개 API `GET /api/v1/policies/consents`로 받는다.
  실패하면 5/10/20초 + 지터로 재시도하고, 그래도 실패하면 오류 화면([다시 시도]/[이전 단계]).
  오류 화면에서 앱이 포그라운드로 돌아오면 다시 조회한다.
- 만료는 제출 직전에만 확인한다. 뒤로 가기는 이전 단계, 첫 단계는 경고 팝업 후 로그인 화면(SNS 재인증).
- 전화 인증은 실제 SDK로 연결하고, 앞 단계에 다녀와도 완료를 유지한다. 다른 계정의 번호는 안내 후 번호 입력에 머문다.
- 품질 검토(선택) 동의도 가입 중에 받고 "전체 동의"에 포함한다. 동의하지 않으면 `false`+버전을 보낸다.
- 사용자는 이번 작업의 스켈레톤을 생략하도록 했다.

## 코드 흐름 변화

이전: `signingUp` → `EnrollmentUnavailableScreen`

이후: `signingUp`(direct) → `SignupNavigator` → `appAuthRuntime.startSignup` → `signup-flow` 상태별 화면
→ 제출 성공 → `coordinator.completeEnrollment` → 세션 활성화·약관 확인. Guest의 `signingUp`·`mergeRequired`는 여전히 준비 중 화면이다.

- `signup-flow.ts`: 단계·약관 조회·제출·오류 code별 복구. 화면이 사라지면 dispose해 늦은 결과를 버린다.
- `signup-phone-verification.ts`: 입력 번호(+82)로 SMS 발송 → 같은 uid에 `linkWithCredential`. 번호가 바뀌면(`phoneRevision`) 다시 받는다.
- `api/get-policy-versions.ts`, `api/submit-firebase-signup.ts`: 새 endpoint 모듈.
- `auth-coordinator.ts`: `signingUp`에 Firebase `uid`(토큰 아님)를 싣는다. 제출 직전 같은 사용자의 증명을 강제 갱신하는 데 쓴다.
- `signup-draft-store.ts`: `qualityReview` 동의 추가. 전체 동의가 선택 항목까지 켜고 끈다.
- 화면: `SignupProfileScreen` → `SignupNicknameScreen` + `SignupConsentScreen`. `SignupFailureScreen` 추가. 단계 표시는 전체 단계 수를 받는다.
- 검사: `scripts/check-signup-flow.mjs` 16개.

## 뼈대 → 구현에서 달라진 것

스켈레톤이 없어 구현하며 정한 것을 적는다. 확인이 필요하다.

- **품질 검토 필드는 아직 보내지 않는다.** 서버 필드 이름이 미정이다. 받은 동의는 store에 있고 이름이 확정되면 body에 넣는다.
- 계약에 code가 없는 4xx(닉네임 형식·약관 버전 불일치 등)는 "정보 수정하기" → 첫 단계로 묶었다.
- 약관 조회가 재시도해도 소용없는 오류(응답 형식 등)면 기다리지 않고 바로 오류 화면이다.
- enrollment 충돌·만료로 exchange를 다시 하는 것은 제출 한 번에 한 번이다. exchange가 `AUTHENTICATED`면 응답이 유실된 이전 가입으로 보고 그 세션으로 완료한다.
- Android 자동 인증은 받은 코드를 채우기만 하고 확인 버튼은 사용자가 누른다. `provider-already-linked`는 인증 완료로 보고 서버가 제출 때 검증한다.
- 전화 인증 중 Firebase 사용자가 바뀌거나 재인증이 필요하면 "로그인 화면으로" 오류로 보낸다.
- 준비 중 화면의 `signingUp` 문구를 Guest 회원 전환 안내로 바꿨다.

## 기준 충돌

- 재동의 화면(`ConsentScreen`)의 품질 검토 문구를 가입 약관 화면에 옮겨 적었다. 화면 영역 간 import가 금지돼 공유보다 중복을 택했다.
- `AuthRecoveryScreen`을 재사용하지 않고 `SignupFailureScreen`을 새로 만들었다. 제목·버튼 구성이 달라 옵션을 늘리는 대신 분리했다.

- 구현 후 리뷰(실행 `49feed4d`) 지적 3건을 사용자가 모두 유용하다고 평가해 적용했다.
  제출 오류 판단을 순수 함수(`resolveSignupSubmitFailure` 등)로 분리하고 루프는 실행만 한다(가독성-맥락보다 판단 검증을 택함).
  입력 수정 안내는 400·422로 좁혔고, void switch에 `never` 누락 검사를 더했다.

사용자의 구현 확인·흐름 설명은 아직 받지 않았다.

검증: lint·TypeScript·architecture·naming·format 통과. 가입 흐름 16개, 인증 복원 49개, 전화 검증 6개,
Firebase 인증 18개 통과. 실서버(`policies/consents` 미배포)·실기기 SMS는 검증하지 않았다.
