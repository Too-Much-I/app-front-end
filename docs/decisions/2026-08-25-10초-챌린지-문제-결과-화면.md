# 10초 챌린지 문제·결과 화면

## 문제

뼈대는 한 화면에서 카운트다운 → 제출까지를 그렸다. 실제로는 마이크 권한·오디오 세션
준비, 업로드, 비동기 AI 채점이 끼어들고 각각 실패할 수 있다. 실패마다 사용자가 할 수
있는 일이 달라서 "제출했다" 불리언 하나로는 화면을 결정할 수 없다.

## 선택지 — 채점 대기를 누가 들고 있나

| 안 | 대기 위치 | 트레이드오프 |
|---|---|---|
| A | 문제 화면 (재답변 방식) | 실패 시 재녹음으로 되돌리기 쉽지만, 결과 화면에도 같은 폴링이 또 필요하다 |
| B | 결과 화면 | 문제 화면은 업로드·접수까지만. 대기 중 이탈해도 스테이지 → 결과로 복귀된다 |
| C | 대기 전용 화면 (모의고사 방식) | 10초짜리 루프에 화면 3개는 과하다 |

## 결정

B. 결과 화면은 스테이지에서도 열리므로 어차피 "채점 중"을 그릴 줄 알아야 하고, 대기를
문제 화면에도 두면 폴링이 두 곳에 생긴다. 경계는 **접수 통지 성공**이다 — 그 전의 실패는
로컬 파일로 회복되고(재업로드·재녹음), 그 후의 실패는 녹음을 다시 올려서 고칠 수 없다.

## 코드 흐름 변화

```text
뼈대: setInterval(10s) → submitAnswer=true → console.log
이후: useChallengeQuestion → useChallengeRecorder(10초) → useChallengeSubmission
      → replace(ChallengeResult) → useChallengeResult 폴링
```

- `features/challenge/`: 조회·녹음 어댑터·제출·결과 폴링, `api/` 4개, 오류 코드, 매퍼
- `screens/ten-second-challenge/`: 문제 화면, 결과 화면, 노트 카드·헤더·액션바·스켈레톤
- 라우트 2개를 루트 스택에 추가. 둘 다 `{ challengeDate?, questionNumber }`만 받는다

## 뼈대 → 구현에서 달라진 것

**뼈대에 없던 상태와 그 이유**

| 추가 | 왜 필요했나 |
|---|---|
| `preparing` | 권한 팝업·`prepareToRecordAsync` 때문에 마운트와 녹음 시작 사이에 빈 구간이 생긴다 |
| `permission-denied` / `record-failed` | 권한 거부, 마이크 선점, 백그라운드 전환은 회복 행동이 서로 다르다 |
| `reviewing` | 확정된 녹음을 들어보고 다시 녹음할 수 있어야 한다 |
| `submitting` / `submit-failed` | 업로드 중 이탈하면 S3에만 파일이 남는다. 이 동안 나가기를 잠근다 |
| `question-failed` + 재시도 | 조회 실패로 화면을 떠나보내면 짧은 루프에 왕복이 붙는다 |
| `loading` 스켈레톤 | 조회가 몇 초라 스피너는 "오래 걸린다"는 잘못된 신호를 준다 |

**뼈대의 가정을 바꾼 것**

- `setInterval` 카운트다운 삭제 — 별도 타이머를 두면 네이티브 녹음 종료와 초가 어긋난다.
  표시 시간의 출처를 `recorder.remainingMs` 하나로 합쳤다.
- 자동 종료를 `finalizing`으로도 받는다 — 미터 폴링이 네이티브 정지 직전에 걸리면 훅의
  확정이 화면보다 앞서고, 남은 시간만 보면 화면이 `recording`에 갇힌다.
- `isCompleted` 분기 삭제. 대신 조회 응답의 `attemptStatus=submitted`면 결과로 replace한다.
- 날짜를 앱이 만들지 않는다. 서버가 준 `challengeDate`를 `X-Challenge-Date`로 되돌려 보내
  자정을 넘긴 화면을 서버가 걸러내게 했다.
- 제출 재시도가 응시를 두 번 소비하지 않도록 `Idempotency-Key`를 성공까지 보관하고,
  업로드 URL이 만료되면 새 attempt가 아니라 attempt API 재호출로 URL만 받는다.
- 접수 응답의 `referenceAnswer`를 결과 화면에 씨앗 값으로 넘겨 첫 조회를 기다리지 않는다.
- 접수 성공 시 `transferOwnership` 후 녹음 파일을 지운다. 실패 시에는 녹음기가 계속 소유해
  재녹음·이탈 경로가 알아서 정리한다.

**디자인에서 바꾼 것**

- 타이머를 노트 상단 드레인 바로 옮기고 완료 버튼을 외곽선으로 낮췄다. 10초는 안 눌러도
  끝나는데 채움 CTA가 화면에서 가장 무거워 문장이 밀렸다.
- 절대배치의 기준을 패딩 없는 컨테이너로 바꿨다. RN에서 `top-0`이 패딩 안쪽부터 잡혀
  구멍·뜯긴 가장자리·타이머 바가 내용 위로 올라탔다.

## 기준 충돌

- **중복 vs 결합도**: `formatCountdown`은 재답변의 `formatDuration`과 규칙이 같지만 복사했다.
  분 단위까지 가는 재답변과 10초로 끝나는 챌린지가 표기를 함께 바꿀 이유가 없다.
- **재사용 vs 결합도**: 파형(`AudioWaveform`)과 업로드(`uploadAnswerAudio`)는 mock-exam·exam
  모듈에서 그대로 가져왔다. 재답변이 이미 같은 선례를 만들었고, 챌린지 전용 사본을 두면
  네이티브 예외 처리가 두 벌이 된다. 업로드는 `contentType` 인자만 열었다.
- **응집도**: 노트 카드의 장식(구멍·테이프·뜯긴 가장자리·괘선)을 한 파일 안 작은 컴포넌트로
  두었다. 서로 같은 좌표계를 공유해서 떨어뜨리면 위치가 어긋난다.
  - *2026-08-28 갱신*: 결과 화면이 같은 장식을 쓰게 되면서 **구멍과 테이프만** `components/paper/`로
    꺼냈다. 두 화면이 실제로 공유하는 것이 그 둘뿐이고, 괘선과 뜯긴 가장자리는 대지+속지 두 겹이
    있어야 성립해 노트 안에 남는다. 꺼낸 둘도 좌표를 prop으로 열지 않는다 — `fit`/`side`/`tone`처럼
    유한한 변형만 노출하고, 부모만 아는 값(구멍 뒤에 비치는 색)만 `carvedFrom`으로 받는다.
