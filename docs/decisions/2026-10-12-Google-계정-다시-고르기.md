# Google 계정 다시 고르기

## 문제

Google로 기존과 다른 계정(가입 안 된 계정)을 고르면 가입 화면이 뜬다. 취소하고 Google을 다시 눌러도 계정 선택
창 없이 같은 계정으로 들어가 또 가입 화면이 뜬다(2026-10-10 발견, `auth-remaining-todos.md`).

원인: Google SDK는 앱 로그인에 성공한 계정이 아니라 **선택 창에서 마지막으로 고른 계정**을 기억하고,
`GoogleSignin.signIn()`은 기억한 계정이 있으면 선택 창을 건너뛴다. 이 기억을 지우는 `GoogleSignin.signOut()`은
로그아웃·탈퇴의 `signOutDevice`(`firebase-auth-sdk.ts:165`)에만 있다. 가입 취소 `cancelLogin`
(`auth-coordinator.ts:566`)은 `firebase.cancel()`만 부른다.

같은 원인으로 막히는 길이 하나 더 있다(코드로 추정, 기기 미확인). 가입 중 번호가 다른 계정 것으로 나오면
`findAccountFromSignup`(`auth-coordinator.ts:629`)이 계정 찾기로 보내는데, 여기서 "Google로 로그인"을 누르면
`finishAccountRecovery`(`:658`)가 곧바로 `signIn('google')`을 불러 방금 잘못 고른 계정으로 다시 들어간다.

## 선택지

| 언제 Google 기억을 지우나 | 놓치는 상황 | 비용 |
| --- | --- | --- |
| A 취소할 때(`cancelLogin`) | 계정 찾기로 넘어간 경우, 가입 중 강제 종료 | 취소 경로가 늘 때마다 넣어야 함, 지우기 직후 다시 누르면 경합 |
| B Google 버튼마다 먼저 | 없음 | 세션 만료로 로그인 화면에 온 사용자도 매번 계정 선택 |
| C 가입 단계 취소에서만 | A에 더해 진행 중·오류 취소 | A와 같음 |
| (세션을 지울 때) | — | B와 같은 사용자가 같은 비용을 치름, 이름만 다름 |

리프레시 토큰은 회전할 때마다 14일을 새로 받는다(서버 확인). 꾸준히 쓰는 사용자는 만료되지 않고, 세션 무효화도
드물다. 직접 로그아웃하면 지금도 기억이 지워진다.

## 결정

대화에서 사용자가 명시한 결정(원문):

- 지우는 시점: "A로 하고 findAccountFromSignup에도 지우는 걸 넣을까?" → A + `findAccountFromSignup`
- 근거: "A로 하게 되면 기본적인 정상 만료 토큰으로 인한 로그인 화면에서는 사용자가 바로 계정 선택없이 수단만
  확인해서 로그인을 다시 할 수 있잖아"
- 지우는 범위: "구글 기억만 지워서 파이어베이스랑의 경합을 피하자." 계정 찾기는 넘어오자마자 Firebase에 전화번호로
  로그인한다(`account-recovery-flow.ts:419`, `:586`). Firebase까지 지우면 늦게 끝난 `signOut`이 그 사용자를
  내보낼 수 있다.
- 다시 누를 때의 경합: "signInGoogle을 기다리게 하자." 진행 중인 지우기가 끝난 뒤 `signIn()`을 부른다.
- 가입 중 강제 종료: "강제 종료 한바퀴 도는 건 감수하도록 하고". 다시 켜면 가입 화면이 한 번 더 뜨고, 거기서
  취소하면 지워진다.

## 코드 흐름 변화

이전: 가입·병합·진행 중·오류 취소 → `cancelLogin` → `firebase.cancel()`. Google 기억은 남는다.
이후: `cancelLogin`과 `findAccountFromSignup`이 `firebase.cancel()`에 더해 Google 기억만 지운다(Firebase
로그인은 건드리지 않음). `signInGoogle`은 진행 중인 지우기를 기다린 뒤 `GoogleSignin.signIn()`을 부른다.
세션 만료·무효화와 로그아웃·탈퇴의 동작은 바뀌지 않는다.

확인할 것: iOS에서도 선택 창을 건너뛰는지, Kakao·Apple도 같은 문제가 있는지.
