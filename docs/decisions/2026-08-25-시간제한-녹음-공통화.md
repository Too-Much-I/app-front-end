# 시간제한 녹음 공통화

## 문제

10초 챌린지도 모의고사와 같은 권한 요청, 오디오 모드 전환, 제한 시간, 파일 검증·정리,
AppState 중단 처리가 필요하다. 기존 `useAnswerRecorder`는 이 생명주기를 이미 처리하지만
`AnswerKey`와 `FinalizedAnswer`에 직접 결합돼 챌린지가 그대로 사용할 수 없었다.

## 선택지

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| 시험 훅 직접 확장 | `AnswerKey`에 챌린지 식별자를 섞는다 | 구현은 작지만 두 도메인이 결합된다 |
| 공통 훅 + 시험 어댑터 | 녹음 생명주기를 공통화하고 기존 훅은 계약만 변환한다 | 파일이 나뉘고 어댑터 한 단계를 거친다 |
| 챌린지 훅 별도 구현 | 시험 코드를 건드리지 않는다 | 네이티브 예외 처리와 파일 수명주기가 중복된다 |

## 결정

사용자가 두 번째 안을 선택했다. 공통 훅은 도메인을 모르는 `TContext`를 녹음 시작부터
완료까지 보존하고, 시험 어댑터는 `AnswerKey`를 복제해 기존 `FinalizedAnswer`로 되돌린다.
챌린지 어댑터는 스테이지 API의 서버 기준 `date`와 `questionNumber`를 함께 보존한다.

## 코드 흐름 변화

```text
이전: useAnswerRecorder → Expo 녹음 + AnswerKey 결합
이후: useAnswerRecorder → useTimedAudioRecorder<AnswerKey> → Expo 녹음
      useChallengeRecorder → useTimedAudioRecorder<{ date, questionNumber }> → Expo 녹음
```

- `features/audio/`가 오디오 세션, 권한, 녹음 파일, 시간제한 녹음 생명주기를 소유한다.
- 기존 exam 모듈 경로는 재수출·어댑터로 유지해 시험과 재답변 호출부를 바꾸지 않는다.
- 챌린지 어댑터는 제한 시간을 10초로 고정하고 날짜·문제 번호를 완료 파일에 다시 붙인다.
- 답변 업로드는 공통 파일 검증·삭제를 사용하되 업로드 오류 타입은 그대로 유지한다.

## 뼈대 → 구현에서 달라진 것

새 UI 상태나 전이는 없어서 별도 뼈대 대신 기존 `useAnswerRecorder`의 공개 계약을 기준으로
삼았다. 공통 오류 문구에서 도메인 표현인 “답변”만 제거했고 상태·실패 단계는 유지했다.

## 기준 충돌

가독성의 시점 이동과 결합도 감소가 충돌했다. 공통 훅으로 한 단계 이동하지만 권한·오디오
세션·파일 정리처럼 함께 바뀌어야 하는 네이티브 생명주기를 한 곳에 두고, 도메인 식별자
변환만 얇은 어댑터에 남기는 쪽을 선택했다.
