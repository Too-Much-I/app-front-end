# 답변 익히기 프론트 인수인계

## 현황과 요청

로컬 학습 앱은 200개 단위/360문항/1,000개 답변과 로컬 음성을 정적으로 import하고 별도 프리뷰 인증을 썼다.
원격 main에는 이후 로그인 복구, 마이페이지, 푸시, 오류 수집이 추가되어 프리뷰 진입점을 덮어씌우면 기존 기능이 사라진다.
사용자는 최신 app-front-end를 기준으로 기존 코드를 최대한 보존하는 새 브랜치 업로드를 요청했다.

## 논의한 범위

- 프리뷰 앱 전체 복사: 기존 기능 교체와 충돌 위험이 있어 사용자의 최소 수정 요구에 맞지 않는다.
- 학습 기능 모듈을 기존 navigator에 추가: 최신 기능을 유지하며 합류할 수 있다.
- 실제 자료를 공개 저장소에 넣을지 별도 전달할지 확인했으며, 사용자는 S3/MongoDB 및 백엔드 API 연동을 선택했다.

## 결정

- origin/main 3e17478을 기준으로 feat/answer-learning. 원래 로컬 프리뷰 작업은 별도 checkout에 그대로 보존.
- 신규 학습 화면/domain/API 모듈 추가 + 기존 탭/권한/디자인 기본값 유지하는 작은 확장.
- 데이터와 미디어는 커밋하지 않고 인증된 백엔드에서 로딩. 완료는 서버, 중간 진행은 세션 메모리.
- AI 제안/구현: 업로드 URL을 백엔드가 발급하고 앱이 S3에 PUT한 뒤 submit으로 검증·채점 시작을 요청한다.
  원래 로컬 서버의 binary 중계 방식에서 달라지는 계약이며 API 문서에 명시했다.
- 모델 호출은 백엔드/Lambda에만 둔다. 채점 API 미구현 상태를 가짜 결과로 대체하지 않는다.
- 아직 배포되지 않은 API 계약/예시/연동 순서를 문서화한다. Lambda 배포는 이 인수인계 이후의 별도 작업.

## 수용 기준

최신 기존 기능을 보존하고, 기밀/개인 파일 없이 새 checkout에서 타입·린트·구조·이름·학습 검사가 통과한다.
문항/음성/표/타이밍/채점 계약의 요청과 응답을 개발자가 소스와 함께 대조할 수 있어야 한다.
실제 서비스 API 종단 검증과 사람의 PR 학습 기록은 수행한 것처럼 표시하지 않는다.
