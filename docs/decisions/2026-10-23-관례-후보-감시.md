# 관례 후보 감시

## 문제

아무도 정하지 않은 코드 습관이 AI 코드가 쌓이면서 저장소의 관례가 된다. 예를 들어 버튼 콜백에서 Promise를
버리는 `() => void fn()`은 사람이 의도해서 넣은 적이 없는데 계속 늘었다.

| 시점 | `=> void ` 개수 (`src/`) |
| --- | --- |
| 2026-09-11 | 21 |
| 2026-10-01 | 33 |
| 2026-10-22 | 49 |

이 습관 자체가 틀린 건 아니다. React Native `Pressable`은 `onPress`가 돌려준 값을 쓰지 않아서 `void`가 있든
없든 동작이 같고, lint 규칙으로 강제되지도 않는다. 문제는 아무도 판단하지 않았는데 기준처럼 퍼진다는 점이다.

이렇게 된 이유는 두 가지다.

- 구현 리뷰 훅(`docs/code-review-cycle.md`)이 `.codex/hooks.json`에만 등록돼 Codex 세션에서만 돈다. Claude Code
  세션에서는 돌지 않아 마지막 실행이 2026-10-01이다.
- 훅이 돌아도 이 문제는 못 잡는다. 리뷰는 변경 하나를 기존 기준 구현과 비교하므로 이미 퍼진 습관을 따른 코드는
  "일관적"이라 통과한다. "몇 번째 반복인데 정한 적이 없다"는 diff 하나에서는 보이지 않는다.

`02-conventions.md` 1.2절("코드에서만 읽히는 컨벤션")이 같은 일을 2026-08-31에 한 번 했지만, 그 뒤로 갱신하지 않았다.

## 결정

하나의 흐름으로 막는다(사용자 결정). 변경마다 리뷰 → PR마다 반복 관용구 찾기 → 사람이 판단 → 정한 것은 정본·lint로
고정하고, 정하지 않은 것은 "의도 없음"으로 기록한다.

**1. 리뷰 훅을 Claude Code에도 연결한다.** `.claude/settings.json`에 Codex와 같은 `SessionStart`·`Stop` 훅을
등록하고 커밋한다(사용자 선택 (나), 저장소 공유). `.gitignore`의 `.claude/`는 `settings.json`만 예외로 둔다.
`settings.local.json`은 계속 개인 설정이다. Claude Code 훅의 입력(`session_id`, `stop_hook_active`,
`last_assistant_message`)과 출력(`decision: "block"`, `additionalContext`)은 지금 스크립트가 쓰는 이름과 같아서
스크립트는 바꾸지 않는다.

**2. 반복 관용구는 AI가 찾는다(사용자 선택 (ㄴ)).** 감시 목록을 세는 방식은 목록에 없는 새 관례를 못 찾고, 리뷰 훅에
붙이는 방식은 훅을 거치지 않은 코드를 못 본다.

**3. PR마다 CI가 고정 댓글 하나로 보여 준다(사용자 선택 2).** `anthropics/claude-code-action`으로 돌린다.

- push할 때마다 돈다: "pr 열때만 이면 이후에 쌓인 코드는 검사를 안하는거잖아". 같은 PR에서 앞선 실행이 아직 돌고
  있으면 취소한다.
- 댓글은 숨은 표식(`<!-- convention-watch -->`)으로 찾아 하나만 고쳐 쓴다. 작성자가 봇이라 CodeRabbit 댓글과 구분된다.
- Claude는 저장소를 읽고 결과 파일만 쓴다. 댓글은 다음 단계(`github-script`)가 달아서 Claude 단계에는 GitHub 쓰기
  권한이 없다. 관용구를 찾는 절차는 `.agents/skills/convention-watch/SKILL.md`에 있다.
- 필수 검사가 아니다. 머지를 막지 않는다.
- 인증은 구독 토큰(`CLAUDE_CODE_OAUTH_TOKEN`)으로 한다(사용자 선택). 따로 과금되지 않고 토큰을 만든 사람의
  구독 사용량에서 빠진다. 팀원 PR도 같은 한도를 쓰고, 그 사람의 구독이 바뀌면 멈춘다.
- 공개 저장소라 GitHub Actions 실행 시간은 무료다. 포크 PR에는 시크릿이 전달되지 않아 돌지 않는다.

**4. 판단 결과는 장부에 남긴다.** 다음 실행이 이미 판단한 관용구를 다시 올리지 않게 한다. 장부는 `02-conventions.md`의
새 절로 두고(AI 제안), 항목마다 "관례로 정함(정본·lint 위치)" 또는 "의도 없음(그냥 둠 / 줄여 나감)"을 적는다.
`=> void`는 "판단 대기"로 처음 넣는다.

## 사람이 해야 하는 설정

1. 로컬에서 `claude setup-token`을 실행해 토큰을 만든다.
2. `gh secret set CLAUDE_CODE_OAUTH_TOKEN`으로 저장소 시크릿에 넣는다. 토큰은 채팅에 붙이지 않는다.

시크릿이 없으면 workflow는 실패하지 않고 건너뛴다. workflow 토큰(`github.token`)을 넘겨서 Claude GitHub App은
설치하지 않아도 된다.

## 하지 않은 것

- 관용구를 찾는 기준을 고정하지 않았다. AI 판단이라 실행마다 흔들릴 수 있다. 몇 번 돌려 보고 장부와 비교해 정한다.
- 정본이 없는 영역의 리뷰 기준. 영역별 정본 작업(`05-declarative-code.md`)이 따로 진행한다.
- 이미 퍼진 `=> void`를 고칠지. 장부에서 판단한 뒤 정한다.
