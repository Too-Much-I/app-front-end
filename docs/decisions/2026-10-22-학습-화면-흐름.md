# 학습 화면 흐름 (파트 → 퍼즐 → 쉐도잉 → 채점)

## 문제

등급 카드 → 파트 고르기까지는 있지만(#89), 파트를 누르면 빈 학습 화면에서 멈춘다. 학습 API는 Swagger
(`api-test.to-teacher.com`)에 9개가 올라와 있으나 테스트 토큰이 없고, 퍼즐 조각(`chunks`)은 서버가 합의대로
추가하기로 했지만 아직 응답에 없다. 화면이 실제로 어떻게 이어지는지 먼저 손으로 확인할 수 있어야 다음 결정
(채점 유지, 세트 목록, 이어서 하기)을 할 수 있다.

## 선택지

시안: [학습 파트·학습 화면](https://claude.ai/artifact/LzjSYzi1RgEUkrErbVgAxw) — 파트 B3~B5, ② S2, ③ G2.

| 주제           | 안                                                       | 트레이드오프                                                                 |
| -------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------- |
| ① 퍼즐 범위    | 모양만 / 실제 동작(누르면 붙음·틀리면 흔들림·줄 나눔)    | 모양만은 금방 끝나지만 퍼즐이 손에 어떻게 느껴지는지 확인할 수 없다          |
| 단계 나누기    | 화면별 route / `LearningSession` 한 화면 안 단계 상태    | route는 뒤로 가기·param 타입이 분명하다. 한 화면은 단계 간 값 공유가 쉽다    |
| 파트 화면 배경 | 등급별 그림 3장 / 한 장                                  | 3장은 그림 파일이 레포에 늘어난다                                            |
| 데이터         | Swagger 형태 목데이터 / 상세 API 연결                    | API 연결은 토큰이 없어 확인할 수 없다                                        |
| 버튼           | 공용 `Button` 기존 variant / 새 variant / 화면에서 직접  | 시안 버튼이 등급색·흰색·외곽선 등으로 다양해 기존 variant로는 맞지 않는다    |

## 결정

- 흐름: 파트(B) → ① 조각 퍼즐 → ② 듣기·쉐도잉(S2 문장 카드) → ③ 채점(G2 토선생의 한마디).
- ① 퍼즐은 실제 동작까지 만든다.
- 단계마다 화면을 따로 등록한다.
- 파트 화면 배경은 등급별로 다르다. Easy 바다, Medium 해돋이, Hard 꽃 언덕.
- 데이터는 Swagger 응답 형태를 따른 목데이터. `chunks`는 서버와 합의한 `{from, to}` 형태로 목데이터에만 넣는다.
- 버튼은 기존 `Button`을 쓰지 않는다.
- 파트를 누르면 서버 완료 기록(`lessons[].completed`) 기준으로 안 한 문항이 있는 첫 세트의 첫 미완료 문항부터 한다.

답이 없어 AI 제안으로 정한 것(되돌리기 쉬운 쪽):

- 다 끝낸 파트는 첫 세트 첫 문항부터 다시.
- 버튼은 화면에서 공용 `Pressable`로 직접 그린다(등급 카드 CTA와 같은 방식).
- 진동(`expo-haptics`)은 넣지 않는다. 네이티브 의존성이라 개발 빌드를 다시 해야 한다. 틀리면 흔들림만.
- 소리·녹음 없음. 재생은 `words[].start/end`대로 하이라이트만, 따라 말하기·채점은 목 결과.
- Part 1은 퍼즐·채점 없이 ② → 완료.

## 코드 흐름 변화

- 이전: 파트(A) → `LearningSession`(등급·파트만 보여 주는 빈 화면).
- 이후: 파트(B) → `pickNextLesson` → `LearningPuzzle` → `LearningShadowing` → `LearningGrading` →
  같은 세트 다음 문항이면 파트로 돌아간 뒤 그 문항의 퍼즐, 마지막이면 파트로. Part 1은 `LearningShadowing`에서 끝.
- 데이터: `learning-mock-source.ts`가 `mock/learning-mock.json`(Swagger 형태)을 zod 스키마 → 매퍼로 읽는다.
  완료 기록은 메모리에만 둔다. API를 붙일 때 이 파일 함수만 바꾼다.
- 건드린 파일: `navigation/types.ts`·`RootNavigator.tsx`(route 3개), `screens/learning/*`(화면 3개 + 부품),
  `features/learning/*`(매퍼 3개·퍼즐·문항 고르기·목 출처), `types/learning.ts`, `theme/tokens.js`
  (`learningScene`·`learningPuzzle`), `public/learning/scene-*.jpg`. `LearningSessionScreen.tsx` 삭제.

## 기준 충돌

- 결합도 vs 중복: 종이 카드는 챌린지의 `ChallengeSentenceCard`와 거의 같지만, 화면 영역끼리 import할 수 없어
  `LearningPaperCard`로 따로 만들었다. 공용으로 올리면 챌린지 코드도 바뀌어 범위를 넘는다.
- 결정 기록(2026-10-19)과 다른 점: 조각이 날아가 붙는 움직임 대신 제자리에서 나타나고, 이음매는 SVG 모양이 아니라
  둥근 꼭지 하나로 흉내 냈다. 줄 끝에서 조각이 단어 사이로 갈라지는 것은 단어마다 따로 놓는 방식으로 지켰다.

## 이후 결정 (2026-10-23)

- 등급 카드: 가운데 카드를 누르면 버튼과 같이 파트 화면으로 간다. 옆 카드를 누르면 가운데로 옮기기만 한다
  (넘기다 스친 카드로 원하지 않은 등급에 들어가지 않게). 구현·에뮬레이터 확인 완료.
- 따라 말하기는 **(가) 모범 음성 속도로 가사가 흘러가는 방식**으로 확정. 모범 음성을 틀면 `words[].start/end`대로
  단어가 칠해지고, 사용자는 그걸 보며 동시에 따라 말한다(원래 뜻의 쉐도잉). 기기 STT는 쓰지 않는다 — 패키지 추가·
  재빌드·기기별 인식률 문제가 없고, 서버가 이미 단어 시각을 준다. 끝난 뒤 내 녹음 다시 듣기는 붙일 수 있다(STT 불필요).
  - 지금 화면은 재생(하이라이트)과 따라 말하기(가짜 "내 문장" 카드)가 따로 있다 → 다음 작업에서 (가)로 합친다.
- 버린 안: (나) 내 목소리를 STT로 따라가며 칠하기. 인식이 늦거나 놓친 단어에서 멈추고, 앱 재빌드가 필요하다.

## 이후 결정 (2026-10-23, API 연결)

퍼즐은 서버 `chunks`가 아직 없어, 지금 Swagger API로 만들 수 있는 따라 말하기부터 붙인다.

- 목록(`GET /learning/units`)과 상세(`GET /learning/units/{id}`)를 실제 API로. 퍼즐도 서버 데이터를 쓰고,
  `chunks`는 합의대로 온다고 보고 받되 없으면 세 단어씩 자른다.
- 따라 말하기 (가)를 상세 응답의 `sentences[].audio` + `words[].start/end`로 구현. 재생 직전에 `expiresAt`이
  지났으면 `GET /learning/media/{id}/url`로 새 주소.
- 불러오는 중은 작은 원 회전, 실패는 `error.png` 토끼 + 다시 불러오기.
- Part 1은 끝나면 `PUT /lessons/{id}/completion`(`level: common`, `submissionId` 없음)으로 완료 저장.
  이유(사용자): 나중에 이어서 하기 버튼을 두고 그 API를 서버가 줄 예정이라 서버가 완료 여부를 알아야 한다.
- 따라 말하기는 Part 1~5 모두 모범 음성을 들으며 녹음하고, 끝나면 내 녹음을 다시 들을 수 있다. 녹음 파일은 화면을
  나가면 지운다. 마이크 권한이 없으면 필요하다고 알리고 멈춘다. 스피커로 들으면 모범 음성이 섞일 수 있다는 안내를
  화면에 들어올 때마다 잠깐 띄운다.
- 채점(Part 2~5)은 목 그대로. 다음 작업 단위로 미룬다.
- 이어폰 확인은 다음 작업 단위에서 Expo local module로(`expo-audio`는 소리가 나가는 곳을 모르고,
  `react-native-device-info`는 Android에서 지원 중단 API를 쓴다).

## 서버 확정 (2026-10-24)

- `chunks`가 Swagger `LearningSentence`에 들어왔다. 선택 필드이고 `{from, to}`(words 0-based, 양끝 포함)이며, 순서대로
  중복·빈틈 없이 전체 단어를 덮는다. 생략되면(Part 1 등) 앱이 퍼즐을 만든다. 지금 매퍼의 형태와 같다.
- `GET /api/v1/learning/resume?part=&level=`: 기존 정렬 순서에서 첫 미완료 세트의 `unitId`와 `allCompleted`를 준다.
  "마지막으로 연 세트"가 아니다. 다 끝냈으면 `{unitId: null, allCompleted: true}`이고, 이때 전체 완료 화면을 띄운다.
  Part 3·4는 세트 안 모든 문항이 끝나야 완료다. 본문·음성은 `unitId`로 기존 상세 API를 불러서 받는다.
  404 `LEARNING_NOT_FOUND`는 전체 완료로 해석하지 않는다. 503 `LEARNING_UNAVAILABLE`은 잠시 후 다시 시도한다. 402는 판정하지 않는다.
  진도는 현재 콘텐츠 버전 기준이고, 새 버전으로 자동 이전되지 않는다.
  - 이어하기 버튼 위치와 지금 `pickNextLesson`과의 관계는 아직 정하지 않았다.

## 이후 결정 (2026-10-25, PR #106 리뷰 대응)

- Part 1 완료 저장은 응답의 `completed`가 true일 때만 성공으로 본다. 형식만 맞고 false면 실패 문구를 띄우고 다시 누르게 한다.
- 완료 저장 성공 뒤 할 일을 두 곳에 나눈다. 캐시 무효화는 화면이 사라져도 맞춰야 하므로 `useMutation` 옵션(훅 쪽)에,
  파트 화면으로 돌아가기는 요청을 보낸 화면이 살아 있을 때만 의미가 있으므로 `mutate(lesson, { onSuccess })`(부르는 쪽)에 둔다.
  훅 쪽 콜백은 화면이 언마운트돼도 실행돼, 응답 전에 나가 다른 문항을 열면 늦게 온 응답이 새 화면을 닫을 수 있다.
- 녹음 없이 "다음 문장"·"연습 끝내기"로 넘어가는 것은 막지 않는다. 마이크 권한을 거부하면 녹음만 멈추고 진행은 그대로라는
  2026-10-23 결정과 맞춘다.
- 모범 음성이 끝난 뒤 0.8초 마무리 타이머는 새 녹음 시작·마무리·화면 정리 때 취소한다. 남은 타이머가 새 녹음을 일찍 끝내지 않게 한다.
- 내 녹음 다시 듣기에서 재생 오류가 나면 `failed`로 바꾸고 보고한다. 재생 중 상태에 멈춰 있지 않게 한다.

## 남은 결정

- 퍼즐·쉐도잉을 지금처럼 단계별로 묶을지(문장 전부 퍼즐 → 전부 쉐도잉), 문장마다 번갈아 할지.
- ③ 채점을 연습에 남길지(Part 2~5 완료 저장은 채점 완료가 조건).
- 다 끝낸 파트 처리, 진동(`expo-haptics`) 여부 — 지금은 AI 제안(처음부터 다시, 진동 없음)으로 구현돼 있다.
- 실제 API 연결 전 서버 확인: 테스트 토큰, `chunks` 배포 일정, 운영 배포, 체크리스트 항목 규칙.
