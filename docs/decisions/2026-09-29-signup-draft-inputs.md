# 가입 입력의 메모리 보관

## 문제

화면 로컬 state는 스택에서 화면을 제거하면 사라진다. 전화번호 입력 후 뒤로 갔다가
다시 진입해도 닉네임·약관 동의·전화번호를 유지할 필요가 있다.

## 선택지

| 안 | 장점 | 부담 |
| --- | --- | --- |
| 화면별 로컬 state | 화면 안에서 읽고 변경 | pop한 화면의 입력 유실 |
| 가입 영역 부모 state | 영역 종료 시 자연스럽게 폐기 | 여러 화면에 값·변경 함수 전달 |
| 가입 전용 메모리 store | 화면 수명과 무관하게 입력 공유 | 완료·취소 등 초기화 경계 필요 |

## 결정

사용자는 가입 전용 store를 선택하고 닉네임·약관 동의뿐 아니라 전화번호도 보관하도록 했다.
가입 중 화면 이동에는 유지하고 완료·취소·계정 변경에는 초기화한다.
앱 종료 시 초기화되는 A안에 따라 기기 저장용 persist는 사용하지 않는다.
사용자는 이번 입력 관리 구현에는 스켈레톤을 생략하도록 명시했다.

## 코드 흐름 변화

구현 결과이며 사용자 흐름 설명·확인 대기:

- `signup-draft-store.ts`: 흐름별 Zustand store. 동의에는 해당 약관 버전을 함께 보관한다.
  버전이 없으면 동의 처리하지 않고, 변경된 약관의 동의만 해제한다.
- `SignupProfileScreen.tsx`: 닉네임·동의를 store에서 읽고 변경한다. 검증 오류만 로컬에 둔다.
- `AuthPreviewNavigator.tsx`: navigator 소유 store를 context로 공유한다.
  전화 화면을 pop해도 번호는 유지하고, 가입 첫 화면까지 제거하면 초안을 초기화한다.
  SMS 코드·인증 결과는 전화 화면 로컬 상태여서 재진입 시 번호 입력부터 시작한다.
- 번호 변경·reset 시 `phoneRevision`이 증가한다. 번호를 수정했다가 원래 값으로
  되돌려도 기존 인증 화면 상태를 재사용하지 않는다. 실제 SMS SDK 연결은 후속 작업이다.
- `auth-coordinator.ts`: 새 로그인 시작·취소·세션 활성화 성공·dispose에서 초안을 초기화한다.
  활성화 실패 시에는 보존한다. 이전 flowId의 완료는 현재 초안을 지우지 않는다.
- `RootNavigator.tsx`: 가입 renderer에 해당 코디네이터의 `draftStore`를 전달한다.
  최종 가입 요청 담당은 이 store의 값을 읽을 수 있다.

## 뼈대 → 구현에서 달라진 것

이번 작업에는 스켈레톤이 없다. store를 전역 싱글턴 대신 흐름 소유자가 생성하므로
미리보기와 실제 runtime의 입력이 섞이지 않는다. 인증번호·인증 증명은 store에 넣지 않았다.

Guest의 약관 버전은 prepare 응답에서 전달한다. 일반 신규 가입의 실제 약관 공급 경로는
아직 미확정이어서 임의 버전을 넣지 않는다. 미리보기는 명시적인 `preview-*` 버전만 쓴다.
미리보기의 전화 인증 완료는 서비스 가입 완료가 아니므로 초안을 비우지 않는다.
실제 signup·SMS 요청, 필요한 화면 선택, enrollment 재조회는 이번 입력 보관 범위 밖이다.

## 기준 충돌

사용자는 화면별 보관의 단순함보다 화면 제거 후에도 입력을 유지하는 store 방식을 선택했다.
화면에서 쓰는 값은 selector로 구독하고, 초기화 책임은 가입 흐름 소유자에게 뒀다.
사용자의 구현 확인·흐름 설명은 아직 받지 않았다.

검증: lint·TypeScript·architecture·naming 통과. 인증 복원 회귀 49개 통과.
초안 격리·초기화, 약관 변경, 전화번호 변경, 완료·취소·늦은 완료 및 Guest 버전 전달을 포함한다.
실기기의 스택 이동·스와이프 동작은 아직 검증하지 않았다.
