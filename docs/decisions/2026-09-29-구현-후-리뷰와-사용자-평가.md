# 구현 후 리뷰와 사용자 평가

## 문제

사용자의 학습용 스켈레톤을 AI가 자동 완성하거나 리팩토링하지 않으면서,
AI 구현의 구조 리뷰와 그 지적이 유용했는지 확인하는 기록을 연결해야 한다.
검사 횟수 증가만으로 코드 품질이 좋아졌다고 판단할 수 없다.

## 선택지

| 방식 | 이점 | 부담 |
| --- | --- | --- |
| 리뷰 지시문만 사용 | 구조적 판단 기준을 제공 | 실행·평가 기록이 빠질 수 있음 |
| 검사 훅만 사용 | 실행 결과를 기계적으로 확인 | 추상화·책임 분리는 판단하지 못함 |
| 검사 훅 + 리뷰 스킬 + 사용자 평가 | 검사와 판단, 지적의 유용성을 함께 추적 | 실행 상태와 반복 방지가 필요 |

## 결정

사용자는 검사 통과 후 리뷰하고 오탐을 확인하는 사이클을 프로젝트에 적용하도록 요청했다.
리뷰는 제안으로 남기며, 사용자의 평가를 대신 결정하지 않는다.
스켈레톤 작성 단계는 제외하고 컴파일 실패 시 리뷰하지 않는다.
타당하지만 범위 밖인 지적과 사실과 다른 지적을 구분한다.
후속 요청에 따라 지적이 있는 완료 보고에는 평가 질문을 붙인다. 누락 시 종료 훅이
한 번 보완을 요청하고, 사용자 답변을 기다리는 반복 차단은 하지 않는다.

## 코드 흐름 변화

기존: AI가 필수 검사를 실행하고 완료 보고.
추가: begin 기준 상태 → 명시적 ready → Stop에서 필수 검사 → 리뷰 스킬 →
submit → 사용자 평가 rate → 버전별 stats.

- `.codex/hooks.json`: SessionStart 안내와 Stop 실행.
- `.agents/skills/review-completed-code/SKILL.md`: 변경 범위 구조 리뷰·평가 기록.
- `scripts/code-review/`: 검사·반복 방지·스냅샷·결과/평가 기록.
- `scripts/check-code-review-hooks.mjs`: 임시 저장소에서 회귀·프로세스 검증.
- `docs/code-review-cycle.md`: 활성화·사용·재개와 지표 정의.

## 뼈대 → 구현에서 달라진 것

별도의 사용자 코드 뼈대 대신 이번 대화에서 합의한 사이클을 구현했다.
컴파일만 통과하는 미완성 함수도 있으므로 begin/ready를 명시적으로 추가했다.
주석 비중·import 유무로 완성도를 추측하지 않는다.
검사 실패를 자동 수정시키는 종료 반복은 추가하지 않았다.
코드 변경·검사 실패 후에는 명시적으로 다시 ready 해야 한다.
검사 전용 비교 모드도 제공하되 같은 작업 난이도나 모델 조건은 도구가 보장하지 않는다.

## 기준 충돌

훅은 기계적 검사만 실행하며 구조 판단은 프로젝트 규칙에 따라 AI가 제안한다.
가독성·결합도 등 기준이 충돌하는 리팩토링은 자동 적용하지 않는다.
기존 architecture/naming 규칙과 사용자 스켈레톤은 수정하지 않았다.
사용자의 최종 실행 확인·흐름 설명은 아직 진행하지 않았다.
