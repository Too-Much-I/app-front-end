# 문의하기 API 연결

## 문제

앱 문의 화면(`SupportInquiryScreen`)은 계약이 정해지기 전에 만들어져 전송 자리(`sendInquiry`)가 비어 있다. 로그인 도움,
Guest 병합, 계정 복구에서 열 수 있지만 보내지지 않는다. 설정의 문의하기는 웹뷰(`/app-settings/contact`)를 연다.

서버 계약(Identity Swagger `POST /api/v1/support/inquiries`, 2026-10-07 확인):

- `Idempotency-Key` 헤더 필수. 문의별 소문자 UUID v4, 재시도할 때 같은 값. 같은 키에 다른 내용이면 409
  `SUPPORT_INQUIRY_REQUEST_CONFLICT`.
- `category` AUTH·GENERAL은 로그인 선택, REFUND는 로그인 필수(401 `SUPPORT_REFUND_AUTH_REQUIRED`). 인증 헤더가
  있으면 검증하고, 잘못된 인증을 익명으로 바꾸지 않는다.
- `message` 앞뒤 공백 제거 후 10~2000자(Java 문자열 길이 = JS `length`). `replyEmail` 선택, 254자 이하.
  `context`(screen·errorCode·requestId·appVersion·platform) 선택, 필드마다 형식 제한. 본문 16KiB 이하.
- 201 새 접수, 200 같은 문의 재전송. 둘 다 접수 완료. 400·403·413·429·503.
- `inquiryId`는 앱에 보관하지 않아도 된다(서버 답).

## 선택지

| 결정 지점 | 안 | 비용 |
| --- | --- | --- |
| 토큰 | 로그인 상태면 붙이고 401에 재발급 | 문의가 계정에 연결된다. 401 재시도가 GET 전용이고 인증 클라이언트가 learning 서버 고정이라 둘 다 넓혀야 한다 |
| | 붙이지 않음 | 401이 생기지 않아 단순하다. 문의가 계정에 연결되지 않는다 |
| category | 화면 안에서 상수 | 단순. 진입마다 다르면 고쳐야 한다 |
| | 진입하는 쪽이 넘김 | 진입 화면이 분류를 정한다는 판단이 코드에 드러난다 |
| errorCode | 서버 원본 코드를 상태까지 전달 | 가장 정확. auth 흐름 여러 곳 수정 |
| | 스토어에 잠깐 저장 | 언제 지울지에 따라 낡은 코드가 다른 문의에 붙는다 |
| | 보내지 않음 | 원인 추적 정보가 줄어든다 |
| 본문 수정 후 재전송 | 같은 키 | 첫 요청이 접수됐는데 응답만 잃었으면 409 |
| | 본문이 바뀌면 새 키 | 응답을 잃은 첫 문의와 고친 문의가 둘 다 접수될 수 있다 |

## 결정

- 토큰은 붙이지 않는다: "그냥 일반이랑 인증은 포함을 안해서 보내도 되겠다. 선택 사항으로 뒀으니까"
- category는 진입하는 쪽이 넘긴다. 로그인 도움·Guest 병합·계정 복구는 AUTH: "로그인이나 병합이나 로그인 과정에서
  생기는거니까"
- 설정의 문의하기는 웹뷰를 끊고 앱 화면으로 바꾸며, 사용자가 인증 에러(AUTH)·일반 문의(GENERAL)를 고른다.
- REFUND는 결제가 생길 때 토큰과 함께 추가한다: "지금 결제가 없으니까"
- 본문이 바뀌면 새 키, 같은 본문 재전송은 같은 키: "다른 내용을 보내면 막히는 구나 그러면 다른 키를 만들어야겠다"
- context는 screen·appVersion·platform. errorCode는 일단 보내지 않는다.

## 코드 흐름 변화

- 이전: 진입 → `SupportInquiryScreen`(sendInquiry 없음, 전송 버튼 비활성). 설정 → `SettingsWebView`.
- 이후: 진입이 `{ category, screen }`을 넘김 → 화면이 Identity 서버로 토큰 없이 전송. 설정 → 같은 화면, 분류 선택.
- 파일: `features/support/support-inquiry.ts`(분류·검증·같은 문의 판정·실패 문구),
  `features/support/api/submit-support-inquiry.ts`(요청·context), `screens/support/use-support-inquiry.ts`(키 재사용),
  `SupportInquiryScreen.tsx`(분류 선택), `navigation/types.ts`·진입 3곳·`MemberRootNavigator`·`SettingsScreen.tsx`.
