# 시험 뒤로가기 보호

## 문제

시험 화면의 커스텀 나가기 버튼은 확인 모달을 열지만, iOS 엣지 스와이프와 Android 시스템
뒤로가기는 버튼 콜백을 거치지 않아 시험을 즉시 종료할 수 있었다. `ExamSession`은
native-stack의 기본 gesture를 사용하며 별도 route 제거 방지가 없었다.

## 선택지

| 안 | 동작 | 트레이드오프 |
|---|---|---|
| `gestureEnabled: false` | iOS 스와이프를 완전히 끈다 | 단순하지만 Android 뒤로가기와 팝업 UX를 따로 처리해야 한다 |
| `beforeRemove` | 제거 이벤트를 직접 막는다 | native-stack에서 완전히 지원되지 않는다 |
| `usePreventRemove` | 네이티브 제거를 막고 RN에서 분기한다 | 의도한 programmatic 이동을 별도로 허용해야 한다 |

## 결정

`usePreventRemove`를 iOS와 Android에 같이 적용한다. 일반 응시 중 뒤로가기는 기존 나가기
확인 모달을 표시한다. 진행 불가능한 `part-prelude-error`에서는 모달 없이 시험 첫 화면으로
나간다. `submission-barrier`와 `completed`에서는 채점이 진행되지 않는다는 전용 문구의
나가기 확인 모달을 표시한다. 완료 안내 중 모달이 열리면 채점 대기 화면 자동 이동을 멈추고,
모달을 닫은 뒤 다시 시작한다.

## 코드 흐름 변화

```text
시스템 뒤로가기/스와이프
├─ 일반 응시 → 제거 취소 → 나가기 모달
├─ part-prelude-error → 제거 취소 → popToTop 허용
└─ submission-barrier/completed → 제거 취소 → 채점 전용 나가기 모달

명시적 나가기/홈/GradingWait 이동
→ pendingNavigation 기록
→ preventRemove=false 렌더
→ 목적지 이동
```

## 뼈대 → 구현에서 달라진 것

사용자 결정 외 동작 변경은 없다. React state 갱신과 navigation dispatch가 같은 tick에 실행될
때 재차 차단되는 것을 막기 위해 이동 intent를 state에 기록하고 effect에서 실행한다.

## 기준 충돌

없음. 네이티브 제거 정책과 기존 확인 모달을 화면 한 곳에서 연결하고 각 오디오·제출 훅의
정리 책임은 변경하지 않았다.
