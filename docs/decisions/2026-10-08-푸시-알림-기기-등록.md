# 푸시 알림 기기 등록

## 문제

서버(Learning Core, TMI-198)가 KST 21:00~21:15에 오늘 모의고사를 다 제출하지 않은 MEMBER에게 리마인더를 보낸다.
서버는 앱이 등록한 기기와 앱이 보고한 OS 권한만 보고 대상을 고른다. 앱에는 FCM·알림 권한 코드가 없다
(`@react-native-firebase/app`·`auth`만 있음).

서버 계약(명세 2026-10-07, develop a77a53f):

- `PUT /api/v1/notifications/devices` — 등록·토큰 갱신·권한 보고 공용. body `installationId`(소문자 UUID v4),
  `platform`, `pushToken`(FCM), `permission`(AUTHORIZED/DENIED/UNKNOWN, 생략하면 UNKNOWN), `permissionObservedAt`.
- `DELETE /api/v1/notifications/devices/{installationId}` — 없는 설치도 200.
- 두 API 모두 Bearer + `X-Installation-Secret`(32바이트 난수, base64url 43자). ID·secret은 설치 단위로 보관하고
  계정 전환 때 유지, 재설치 시 새로 발급. 로그아웃 전 DELETE → 새 계정 로그인 후 같은 ID·secret으로 PUT.
- 400·403은 자동 반복 금지, 409는 secret 불일치·다른 설치의 같은 토큰·오래된 관측 시각, 503만 지연 후 재요청.
- 권한 보고가 30일보다 오래되면 발송 제외. Android는 앱 알림과 학습 채널이 모두 허용일 때만 AUTHORIZED.
- 푸시 payload에 `channel_id`가 없다. 테스트 서버는 실제 발송 OFF.

## 결정

고른 안만 적는다. 판단 과정과 사용자 원문은 [학습 기록의 설계 논의](../learning/2026-10-08-푸시-알림-기기-등록.md#설계-논의)에 있다.

- 라이브러리: RNFB messaging + expo-notifications. FCM 수신은 RNFB 한쪽으로 고정하고 Expo 수신 서비스는 뺀다.
- 학습 채널: 앱이 `study` 채널을 만들어 FCM 기본 채널로 지정한다.
- 권한 안내: 회원 화면에서 OS 권한이 `granted`가 아니고 `canAskAgain`이면 사전 안내를 띄운다. "다음"만 두고 허용·거절은
  OS 팝업에서 정한다. 앱 플래그는 두지 않는다. 게스트는 등록하지 않는다. 거절한 사람은 설정의 알림 항목 → OS 설정.
- PUT 시점: 로그인 후와 앱 활성화(콜드 스타트 포함)마다.
- 겹친 PUT: 앞 요청이 끝난 뒤 새로 보낸다. 권한과 `permissionObservedAt`은 보내는 순간에 읽는다.
- 실패: 503만 다시 보낸다. 사용자에게 보이지 않는다. 포그라운드에서는 알림을 띄우지 않는다.
- 로그아웃: DELETE를 먼저 보내고, 실패해도 로그아웃은 진행한다.
- 탈퇴: 앱은 DELETE를 보내지 않고 서버가 연결을 끊는다(서버에 요청, 2026-10-11).
- ID·secret 저장: 인증용과 분리한 알림용 ID와 secret을 한 항목으로 SecureStore에 둔다. 첫 실행 표시는 AsyncStorage.
  읽기에 실패하면 재시도 후 새로 만들어 덮어쓴다.
- Android 백업: 전체 끈다(`allowBackup: false`).
- iOS 키체인: `WHEN_UNLOCKED_THIS_DEVICE_ONLY`.
- 알림 목록 화면: 만들지 않는다.
