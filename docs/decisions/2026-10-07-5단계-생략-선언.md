# 5단계 생략 선언

## 문제

동작이 바뀌는 PR은 학습 기록의 사람 섹션 4개("설계 논의", "내가 찾은 것", "흐름 설명", "설계와 달라진 것")가
채워져야 머지된다(`pnpm check:learning`). 생략 예외는 앱 동작이 바뀌지 않는 작업(`동작 변화 없음`)뿐이다.

문의하기 API 연결(2026-10-07)은 설계 논의에서 쟁점이 모두 정해져 결과를 예상할 수 있었다. 그래도 5단계를 끝내야
머지할 수 있어, 급한 구현도 시나리오 추적과 흐름 설명을 기다린다. `동작 변화 없음`을 선언하면 통과는 하지만
사실이 아닌 선언이 된다.

## 선택지

| 안 | 비용 |
| --- | --- |
| 규칙 유지, 머지 전에 사람 섹션을 채움 | 급한 구현도 5단계를 기다린다 |
| 관리자 권한으로 이번만 예외 머지 | 예외가 규칙 밖에 남고 사유가 기록되지 않는다 |
| `동작 변화 없음` 선언 | 사실이 아닌 선언. 검사가 의미를 잃는다 |
| `5단계 생략: <사유>` 선언 추가 | 사람이 흐름을 따라가 보는 기회가 줄어든다. 사유를 남겨 생략이 선택으로 보인다 |

## 결정

"이건 설계 논의 기록만 적고 바로 pr 올리자 그 구현 기록 안해도 급한 내용은 빨리 올릴 수 있잖아. 그리고 이건 어느
정도 예상 가능한 범주에 있는 구현 같아." → "그럼 해당 pr을 먼저 올리자."

`5단계 생략: <사유>` 선언을 추가한다(AI 제안 형태). 3단계 설계 논의는 그대로 필수다.

## 코드 흐름 변화

- `scripts/code-review/learning.mjs`: `SKIP_FLOW_REVIEW` 선언. 선언 읽기를 `readDeclarationReason`으로 묶어 주석 안·
  자리표시 규칙을 두 선언이 같이 쓴다. 선언이 있으면 새 학습 기록의 "설계 논의"만 요구한다.
- `scripts/check-code-review-hooks.mjs`: 선언 유무·빈 설계 논의·기록 없음·주석·자리표시·이전 기록 수정 경우 검사.
- 리뷰 훅 `begin`은 원래 설계 논의만 확인하므로 바꾸지 않았다. 리뷰 완료 때 빈 사람 섹션 알림도 그대로 둔다.
