# 광고 전환 측정

## 문제

Meta·Google 광고를 집행 중인데 앱에 광고 측정 SDK가 없어 광고로 들어온 사람이 가입했는지, 앱을 실제로 쓰는지
광고 플랫폼이 모른다. 플랫폼은 전환 신호를 보고 "비슷한 사람"에게 예산을 쓰므로 신호가 없으면 최적화가 안 된다.

이미 있는 것:

- 제품 분석은 Amplitude(`src/lib/amplitude.ts` `trackEvent`, 이벤트는 `analytics-events.ts` union).
  초기화 옵션에 "광고 식별자는 쓸 곳이 없다"(`amplitude.ts:61`)는 전제가 있다.
- `exam_completed`는 답안 업로드가 전부 서버에 접수된 순간 보낸다(`use-exam-session-controller.ts:339-341`).
- 가입 이벤트는 없다. 정식 가입은 `signup-flow.ts:309` `complete()`로 모인다.
- 선택 동의는 답변 검토용뿐이다(`optional-consent-storage.ts:4`). 광고 측정 동의는 없다.

범위: Firebase Analytics, Meta App Events, iOS ATT·SKAdNetwork, 전환 이벤트 2개. 결제 라이브러리는 같은 업데이트에
넣지만(Play Console은 결제 라이브러리가 든 빌드를 올려야 인앱 상품을 만들 수 있다) 결정이 따로라 여기서 다루지 않는다.

## 선택지

| 결정 지점 | 안 | 비용 |
| --- | --- | --- |
| 가입으로 셀 것 | 게스트 시작 포함 | 앱만 열어본 사람도 전환 |
| | 정식 신규 가입만 | 게스트로만 쓰는 사람은 안 잡힘 |
| | 게스트 승격 포함 | 이미 앱을 아는 사람이 광고 성과로 잡힘 |
| 모의고사 완료 시점 | 마지막 답을 끝낸 순간(`submission-barrier` 진입) | 업로드가 끝내 실패한 시험도 완료. Amplitude와 수가 다름 |
| | 기존 `exam_completed`(업로드 전부 성공) | Amplitude와 같음. 네트워크 탓에 실제 응시자가 빠짐 |
| 광고 이벤트 보내는 곳 | `trackEvent` 안에서 함께 | 호출부 그대로. 광고로 나가는 이벤트가 숨고 모든 속성이 Meta로 감 |
| | 별도 함수를 두 지점에서 호출 | 광고 이벤트가 보임. 같은 지점에 호출 두 번 |
| | 광고 목록을 두고 `trackEvent`가 거름 | 호출부 그대로, 목록 한 곳. 간접 단계 하나 |
| 가입을 세는 위치 | `complete()` 맨 앞 | 정상·응답 유실·활성화 실패 모두 셈 |
| | `onComplete` 성공 뒤 | 활성화 실패한 가입자는 다시 로그인해도 영영 빠짐 |
| 개발 빌드 이벤트 | 값 직접, 항상 켬 | 단순. 개발 중 테스트가 광고 전환으로 섞임 |
| | 값 직접, `EXPO_PUBLIC_ENABLE_*` 스위치로 production만 | 신호 깨끗. 개발 중 확인하려면 켜야 하고 그때는 섞임 |
| | 값도 EAS 환경변수 | 테스트용 Meta 앱이 생기면 유리. 지금은 앱이 하나라 B와 같음 |

## 결정

대화에서 사용자가 명시한 결정(원문):

- 전환 이벤트: "가입이랑 모의고사 완료를 보내야할 것 같아 모의고사를 실제로 보는지"
- 가입: "정식 가입으로 해야할 것 같아 .게스트 승격은 그래도 우리 앱을 아는 사람들이니까 새로운 회원가입"
- 완료 시점: "마지막 답안 제출 시점을 모의고사 완료로 보자 ." → 두 지점을 나눈 뒤 "사용자가 마지막 답을 끝낸 순간
  (제출 대기 화면에 들어갈 때)". Amplitude `exam_completed`의 정의는 바꾸지 않는다.
- 보내는 곳: "그럼 별도 함수를 만들어서 두 지점에서 따로 호출하도록 하자."
- 가입을 세는 위치: "complete 맨앞에서 세는 걸로 하자"
- 개발 빌드 이벤트: "b야" — Meta App ID·Client Token(공개 값)은 설정에 직접 넣고, 스위치가 켜진 빌드에서만 Meta·Firebase로
  보낸다. Firebase는 "아마 같은 파이어베이스 프로젝트"라 같은 방식으로 다룬다.

남는 위험: 광고 쪽 모의고사 완료 수가 Amplitude보다 업로드 실패분만큼 많다. 활성화에 실패하고 다시 로그인하지 않은
사람도 가입으로 남는다. 광고 측정 동의가 필요한지는 개인정보처리방침 담당 확인 전이다.

## 코드 흐름 변화

이전: 광고 플랫폼으로 가는 이벤트가 없다.

이후: `index.ts`가 `initializeAdConversion()`을 부르고, `EXPO_PUBLIC_ENABLE_AD_CONVERSION=true`인 빌드에서만 Firebase
수집을 켜고(`setAnalyticsCollectionEnabled`, 네이티브에 저장됨) Meta SDK를 초기화한다(자동 이벤트·광고 ID 켬). 네이티브
기본값은 모두 꺼짐(`firebase.json`, `app.config.ts`의 `react-native-fbsdk-next` plugin). 전환은 `trackConversion()`:

- 가입: `signup-flow.ts` `complete()` 맨 앞 → Firebase `sign_up`(`method: 'sns'`), Meta `fb_mobile_complete_registration`.
- 모의고사 완료: `exam-session-store.ts` `advanceAfterRegistration`이 `submission-barrier`로 넘어갈 때 →
  Firebase·Meta 모두 `mock_exam_completed`(Meta 맞춤 이벤트).

건드린 파일: `src/lib/ad-conversion.ts`(신규), `firebase.json`(신규), `app.config.ts`, `index.ts`, `signup-flow.ts`,
`exam-session-store.ts`, `amplitude.ts`(주석), `.env.local.example`, `docs/eas-build-handoff.md`.

ATT 권한 요청, Google의 SKAdNetwork ID, Google Ads 콘솔 연결은 이 변경에 없다. Meta plugin이 Meta의 SKAdNetwork ID
2개를 자동으로 넣는다.

## 기준 충돌

- 보내는 곳: 응집도(분석 호출 한 곳)와 예측 가능성(광고로 나가는 줄이 보임)이 충돌 → 예측 가능성. 같은 지점의
  `trackEvent`와 전환 호출 중복은 둔다.
