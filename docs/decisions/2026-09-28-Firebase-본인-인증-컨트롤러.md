# Firebase 본인 인증 컨트롤러

## 문제

Firebase SNS 인증 성공과 Identity 서비스 로그인 성공을 구분해야 한다.
앱에서 취소해도 네이티브 인증 작업이 남을 수 있고, 새 인증과 겹치면 Firebase 현재 사용자와 반환 증명이 어긋날 수 있다.

## 선택지

| 선택지 | 이점 | 부담 |
| --- | --- | --- |
| 인증 완료까지 앱 화면 취소 금지 | 실행 관리가 단순함 | 이용자가 오래 걸리는 인증에서 빠져나오기 어려움 |
| 취소 즉시 새 인증 허용 | 바로 다른 수단 선택 가능 | 이전 네이티브 작업이 새 사용자를 덮을 수 있음 |
| 화면 취소 허용 + 실제 작업 종료까지 새 인증 차단 | 화면 복귀와 실행 겹침 방지를 함께 보장 | 화면 상태와 실제 작업 수명을 분리해야 함 |

## 결정

사용자가 작성한 스켈레톤 및 후속 대화의 결정이다.

- 인증 중 추가 요청은 무시한다. 서로 다른 Provider도 동시에 실행하지 않는다.
- SNS 인증창 취소 및 앱 로딩 화면 취소를 허용한다. 취소 결과는 `cancelled`, progress는 `idle`이다.
- 앱 취소는 현재 시도를 무효화한다. 기존 작업 종료까지 pending을 유지하고 새 인증·재시도를 차단한다.
- 늦게 도착한 성공·실패로 후속 Token 요청·서버 교환·화면 전환을 하지 않는다.
- 재시도 가능한 실패는 진행 단계와 Firebase User를 메모리에 보존한다. Provider 실패는 인증부터, Token 실패는 Token 획득부터 재개한다.
- 실패 원인(reason)과 다음 행동(nextAction)을 구분한다. 연결·일시 장애는 retry, 재인증 필요는 sign-in-again, 설정·미분류 오류는 get-help다.
- 같은 Firebase 사용자와 유효한 시도인지 확인한 뒤 Token을 반환한다. `proof-ready`는 서비스 로그인 완료가 아니다.
- Google·Apple·Kakao를 지원하며 Apple은 양 플랫폼을 지원한다. 사용자 확인상 Kakao는 OIDC, Google·Phone Provider는 활성화돼 있다. 실제 프로젝트 설정값은 아직 연결하지 않았다.
- 전화번호는 같은 Firebase 사용자에 연결하는 후속 범위다. Identity 세션·가입·Guest 병합은 이 컨트롤러에서 처리하지 않는다.

## 코드 흐름 변화

- `firebase-auth-controller.skeleton.ts`를 정식 `firebase-auth-controller.ts`로 대체했다.
- `createFirebaseAuthController(sdk)`가 `signIn`, `retry`, `cancel` 및 작업 상태 구독을 제공한다.
- 비공개 progress에 Firebase User를 보관한다. 공개 Zustand 상태에는 단계·Provider·실패 값만 있으며 토큰과 User는 없다.
- 실행 취소는 호출자에게 즉시 반환한다. 실제 SDK Promise가 끝나기 전까지 공개 상태는 `cancelling`이다.
- `firebase-auth-sdk.ts`: Google SDK → Firebase credential 로그인, iOS Apple nonce 인증 → Firebase 로그인, Android Apple 및 Kakao OIDC → Firebase Provider 인증.
- `firebase-auth-errors.ts`: 명시적인 SDK 코드만 해석한다. 계정 충돌·정지·미분류 오류를 재시도나 자동 계정 연결로 추정하지 않는다.
- App·기존 인증 runtime은 전환하지 않았다. SDK 생성 시 네트워크·Firebase 초기화를 실행하지 않는다.

## 뼈대 → 구현에서 달라진 것

- 사용자 재시도 뼈대의 `provider-sign-in → 다시 사인 인`, `get-id-token → 아이디 토큰부터`를 실제 호출로 옮겼다. 미완성 `return` 문법과 도달 불가능한 throw를 정리했다.
- 독립 함수 대신 factory 내부에서 progress·pending을 공유한다. 외부에서 임의의 user를 넣어 재시도할 수 없게 했다.
- `ignored` 결과를 추가했다. 중복 요청(`busy`)과 재시도할 작업 없음(`no-retry`)은 사용자 취소·인증 실패와 다르다.
- `cancelling`은 UI에 노출할 작업 상태다. 취소로 초기화한 progress와 별개로 실제 실행을 추적한다.
- 각 실행의 AbortSignal로 오래된 결과를 무효화한다. SDK 네이티브 호출을 강제로 중단한다고 가정하지 않는다.
- UID를 Token 획득 전후 모두 확인한다. 성공·취소·재개 불가능한 실패는 private progress를 초기화하고, 일시 실패만 보존한다.
- reason/nextAction을 결합한 유니온으로 잘못된 조합을 방지했다. 구체 SDK 오류 매핑·Provider별 취소 정규화는 AI 구현이다.
- Google Sign-In 16.1.5(Expo peer >=52.0.40), Expo Apple Authentication 57.0.1(설치된 Expo 57 호환 목록)을 추가했다.
- RNFirebase 26.4.0은 OAuthProvider의 providerId를 private으로 선언했지만 modular API는 public 필드를 요구한다. 어댑터에서 공개 PROVIDER_ID와 toObject를 전달해 native 호출 계약을 유지한다. SDK 내부 구현 변경 시 재검증한다.

## 기준 충돌

공통 인증 흐름과 Provider별 SDK 호출을 분리하는 합의한 책임 경계를 유지했다.
화면 상태는 코디네이터의 책임이며, 이 컨트롤러의 구독 상태는 실제 인증 작업의 실행·종료 대기만 표현한다.
성공한 Firebase 로그인 자체가 취소로 롤백된다고 가정하지 않으며, 임의 signOut으로 다른 작업의 사용자를 지우지 않는다.

## 검증과 후속 작업

- `node scripts/check-firebase-auth.mjs`: 실제 controller·adapter를 실행하고 native SDK만 대체해 17개 검사 통과.
- 기존 세션 복원 회귀 검사 20개 및 lint·TypeScript·architecture·naming·diff 검사 통과. architecture 경고는 기존과 같은 24건이다.
- 설치 후 peer 검사에서 새 인증 SDK 충돌은 없고 기존 navigation peer 불일치만 확인했다.
- Firebase 설정 파일·Google OAuth Client ID·정확한 Kakao OIDC ID·Apple 설정, config plugin 및 개발 빌드 연결이 필요하다.
- 실제 iOS/Android 인증·복귀·취소 종단 검증은 아직 수행하지 않았다.
- 설정 후 앱 단위 controller를 한 번 생성하고 코디네이터에 연결한다. `proof-ready` 후 Identity exchange/prepare와 세션 저장은 별도 구현이다.
- 사용자의 최종 흐름 설명·확인은 아직 진행하지 않았다.
